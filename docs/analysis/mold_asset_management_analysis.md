# 模具资产管理系统：风险、漏洞及优化方案分析报告

## 1. 概述
本报告针对 XDFC 系统中模具资产管理模块（含模具档案、技术图纸、外借流转、遥测更新）进行深度审计。分析基于当前 TypeScript 服务层的实现逻辑，旨在识别潜在的系统性风险、逻辑漏洞，并提供可落地的优化路径。

---

## 2. 核心风险与漏洞分析

### 2.1 数据一致性风险 (Data Consistency)
- **风险描述**：系统目前高度依赖 IndexedDB (通过 `StorageService`)。虽然比 localStorage 更可靠，但由于 `saveMolds` 等方法采用的是“先读取全量、内存修改、再全量覆盖回写”的模式，在并发环境下仍极易发生数据覆盖（Race Condition）。
- **逻辑漏洞**：虽然 `updateTelemetry` 实现了重试机制，但在 `createLoan`、`returnMold` 等涉及跨服务（Mold + Loan）级联更新的操作中，没有数据库级别的原子事务保护。如果模具状态更新成功但借用记录保存失败，系统将进入非法中间态。

### 2.2 状态机逻辑缺陷 (State Machine Vulnerabilities)
- **归还逻辑闭环缺失**：在 `returnMold` 操作中，模具归还后直接切换为 `IDLE` 状态。
    - **漏洞**：系统未校验模具在借出期间是否已由合作方代为保养或是否已达到维保阈值。一个处于“需维保”边缘的模具被归还后，可能被绕过检查直接投入生产。
- **状态非法跃迁**：状态变更缺乏当前状态的合法性检查。例如，处于 `RETIRED`（报废）状态的模具目前在逻辑上仍可能被发起借用请求。

### 2.3 审计与追溯性盲区 (Audit Gaps)
- **核心档案缺乏操作日志**：图纸模块（DrawingService）具备日志系统，但模具核心档案（模具增删改、维保重置、状态变更）虽然通过 `StorageService` 触发了 `AuditService`，但缺乏业务层面的上下文（如：为何修改、关联的工单号等）。
- **虚假删除 (Soft Delete) 实现不彻底**：`deleteMold` 仅从列表中移除了记录。若关联的外借记录仍指向已删除的 `moldId`，会导致 UI 逻辑出现“孤儿数据”，且无法满足“技术遗产保留”的初衷。

### 2.4 遥测与物理同步风险 (Telemetry Sync)
- **单向信任隐患**：`updateTelemetry` 仅接收来自外部的 `cycles` 计数，缺乏对物理设备异常（如计数器回滚、传感器离线）的基准校验逻辑。
- **缺乏版本控制**：图纸管理虽有版本字段，但不支持版本历史的回溯查看，无法支持生产中“按特定版本图纸加工”的严格要求。

---

## 3. 优化方案建议

### 3.1 技术层优化 (Technical Hardening) - **高优先级**
1. **引入状态保护锁 (Status Guard)**：
   - 为 `MoldService` 增加强制执行状态转换合法性检查的机制。
   - 增加版本号校验（Optimistic Locking），在 `saveMolds` 时校验 `_gv`（全局版本号），防止并发覆盖。
2. **深度集成审计引擎 (Deep Audit Integration)**：
   - 增强业务日志，在记录变更时加入 `operator` 和 `reason`。
   - 确保所有敏感操作（如手动调整模具寿命）必须输入变更原因。
3. **实现分层存档策略 (Archiving Layer)**：
   - 将“删除”改为状态标记，或将物理档案移至独立的 `ArchivedMolds` 存储中，确保流转和审计链路的历史引用完整。

### 3.2 业务层优化 (Business Intelligence)
1. **维保流程标准化**：
   - 增加 `MaintenanceService`，记录每一次维保的详情（更换零件、精度校准结果）。
   - 模具归还后应强制进入 `OFFLINE_CHECK` 状态，经专家确认后再转为 `IDLE`。
2. **图纸与实物硬关联**：
   - 实现“生产必备条件检查”：若某型号模具无有效图纸，自动禁止启动相关模具的流转。
3. **智能化预警 (Smart Alerts)**：
   - 结合“久置未用周期”和“历史修模频率”计算模具画像。
   - 当模具健康值低于阈值时，系统自动锁定领用功能。

---

## 4. 结论
当前模具资产管理系统具备基础框架，但在**并发安全性**、**状态流转严密性**以及**业务追溯性**方面存在可被优化的空间。建议通过实施“状态机加固”和“业务层审计注入”，将系统从简单的“记录工具”提升为可靠的“资产监控系统”。
