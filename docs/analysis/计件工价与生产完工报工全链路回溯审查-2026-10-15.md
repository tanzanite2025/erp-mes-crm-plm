# 独立工资计算边界纠正与生产历史问题回溯

更新日期：2026-10-15。用户最新明确：财务自行录入已有人员、部门及独立环节对应数量，只计算工资。此前将任务扩为工资报工、结算审核、收付登记和金额调整，是错误扩大范围，相关模型、服务、接口及页面已撤除，不再作为长期目标。

当前工资契约见 [`独立计件工资模块契约与实现边界.md`](../architecture/独立计件工资模块契约与实现边界.md)。

## 1. 当前工资业务

人员、部门复用已有人事数据，人员默认部门取主要任职。财务在计算表中选择人员、已有部门、独立工资环节及数量，按工价日期匹配单价，计算明细与人员/部门汇总。不同币种分别汇总。

输入有误直接修改重算，不建立报工来源、提交账号快照、请求回执、待计价队列、结算批次、审核、收付、作废或调整。没有班组金额分配要求，也不新建工资人员或部门。

工资与生产完全独立；生产完工、扫码、返工不调用工资，工资计算不查询产品、条码、批次、工段、作业、路线、BOM 或用料分配。

## 2. 保留的工价保护

- 环节 ID 是工资自己的 `payItemId`，不接受产品、生产作业或路线身份。
- 工价区间为 `[effectiveFrom, effectiveTo)`，同环节、同单位不允许重叠。
- 工价更新和删除检查行版本，PATCH 只投影可写字段并保留差分与审计。
- 旧字段、`piecePrice/effectiveAt` 别名和兼容读取已删除。
- 数量及单价最多四位小数，金额用精确十进制乘法后一次 half-up 舍入到分。
- 无工价直接提示修正后重算，不保存“待计价工资”。

工资迁移只处理环节及工价，不再迁移工资报工或结算记录；业务库尚未执行本轮迁移。

## 3. 历史生产问题

初始审查曾发现生产请求重试重复完工、隐式路线重放变化、启动时破坏性拓扑迁移、批次条码错配、草稿步骤引用保护、旧生产身份工价 PATCH 和旧迁移错误。其中文字和行号仅代表当时实现，不能作为当前工资设计。

生产请求幂等回执、轮次唯一性、扫码副作用重放、常规启动停止破坏性拓扑准备、路线基础生命周期已由生产域自身保护。工资自动联动已解除，不得恢复。

生产域仍需独立处理：

1. 执行批次与条码不一致时拒绝，避免错用产品或数量。
2. 被执行事实引用的草稿步骤修改/移除保护及执行使用发布路线的约束。
3. 共享标准作业、工段、产线的完整停用与引用删除保护。
4. 路线家族、业务修订号和复制修订流程。

这些生产事项不影响财务按独立环节工价计算工资，也不属于本轮工资修复。

## 4. 验证说明

旧报工、补价、结算和收付测试与截图属于已撤回实现，之前的“闭环完成”结论不适用于当前需求。本轮围绕财务录入重新验证计算精度、既有人员和部门选项、无业务写入、改数量后重算、缺价与错误提示、人员和部门分币种汇总。

生产隔离回归仍检查生产无需工资表或员工绑定、不会创建或改变历史工资数据。历史数据保护测试可以使用仅供测试的旧表，应用运行模型与工资计算不会使用它。
