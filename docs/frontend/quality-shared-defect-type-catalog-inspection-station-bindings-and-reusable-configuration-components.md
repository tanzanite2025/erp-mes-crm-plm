# 统一异常点目录、检验站绑定与可复用配置组件

更新日期：2026-11-10。实施范围为统一异常点目录、品质检验站与异常点的多对多绑定，以及页面和快捷弹窗复用的配置组件。

## 业务边界

成型、机加、精细、涂装四个检验站属于品检，也是转往下一环节时的实际扫码地点，继续使用现有 `QualityInspectionStage` 目录及其 ID。新增检验站同样可以配置适用异常点。

针孔、裂纹、划伤等问题在品质内统一维护，不在每站复制一份。检验站绑定表示本站可以检查和登记哪些问题，不代表产品已经出现问题，也不证明完成检验。目录初始为空，具体问题及各站适用范围由业务人员维护，不根据示例自动写入。

重量仍沿用“检验站 → 重量项目 → 等级规则”。异常点目录不保存中心值、单位或重量等级，不修改现有实测必检校验。重量是检测项目，超重、欠重可以是检测发现的问题；后续执行接入时需要保留原实测与判定依据，不能用人工问题勾选覆盖服务端重量结论。

## 当前配置数据

- `QualityDefectType`：稳定 ID、系统生成且不可变的编码、名称、规范化唯一名称、说明、顺序、启用状态及版本。
- `QualityInspectionStageDefectTypeBinding`：检验站 ID 与异常点 ID 的唯一组合，引用两个现有实体，不持有生产工序或返修目标。
- 异常点可以被多个检验站绑定；一个检验站可以绑定多个异常点。取消绑定只删除关联，不删除统一目录项。
- 停用异常点保留已有绑定并明确标识；不能新增绑定到停用项，可从原绑定中移除。停用检验站只读其绑定。
- 目录改名保留 ID。未来的检验问题事实应保存当次名称及依据快照，不能通过目录改名改写检验事实；本次不新增执行明细或历史兼容。

绑定集合读取和替换沿用检验站的现有 `version`，保存时锁定检验站并比较版本。绑定变化与版本递增、审计在同一事务内提交；目录编辑与绑定编辑之间的过期提交同样拒绝。保存失败保留页面输入，需重新加载后再编辑。读取绑定集合时保持版本与集合一致。相同版本下提交相同集合不增加版本或重复审计。

## 页面与组件

品质基准增加“异常点配置”TAB，与“品质标准”并列。同一页面提供统一目录维护及按检验站绑定两个区域，不增加独立业务模块。

目录管理组件、检验站绑定组件不依赖路由或固定弹窗。配置组合组件在页面直接渲染，快捷配置弹窗只负责容器和关闭控制；两处共用查询、保存、权限及校验。品质标准列表提供快捷配置入口，页面与弹窗不会产生两套配置。

读取沿用 `menu_quality`，维护沿用 `perm_manage`。新增 API 仅承接目录查询/保存和绑定集合查询/替换，不新增权限种类。查询键包含账号身份；加载失败显示重试，不将失败当空目录。未保存内容在切换编辑对象、检验站或关闭弹窗时提示，保存过程中防止重复操作。按钮和表单沿用系统字号及胶囊按钮。

## 后续返修接入约束

实际检验问题明细应关联产品或条码、检验任务、发现检验站和异常点。发现站不等于问题产生工序。同一产品一次可能发现多个问题，后续需要分别追踪处理情况，不能因处理其中一个问题就认为全部完成。

返修去向应结合“发现检验站 + 异常点 + 产品实际生产路线”确定，不在全局异常点上写死唯一返修工序。生产侧现有 `REWORK` 及目标路线步骤能力可作为后续接入候选，品质目录不拥有生产路线和条码执行状态。

现有异常处置记录 `REWORK` 并关闭，表示已确认处置决定，不能作为实际返修完成或复检通过的证明。本次不修改这条链路，也不增加返修单、派工、自动跳站、放行或复检状态。后续按独立范围对齐逐问题事实、处置、生产执行及复检。

## 验收

1. 同一异常点可以绑定多个检验站，取消一站绑定不影响其他站。
2. 目录支持新增、改名、说明、排序和启停；重复名称、未知关联和过期版本由服务端拒绝。
3. 绑定批量保存为原子操作，空集合需显式提交；缺失字段不视为清空。审计失败完整回滚。
4. 页面与快捷弹窗复用组件，查询失败可重试，保存失败和并发冲突保留输入，普通查看账号无维护操作。
5. 原重量规则、实测提交、异常处置及四站身份保持各自原有职责；本次配置完成不代表扫码、返修已经接通。
