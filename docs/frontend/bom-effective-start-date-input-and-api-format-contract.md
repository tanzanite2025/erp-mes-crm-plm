# BOM 生效开始：直接输入、日历与日期传输契约

## 输入与业务含义

生效开始是 BOM 的计划适用日期，与发布状态分别管理。它是一个日历日期，不表示用户所在时区的某个瞬间，也不触发自动发布。

编辑器支持直接输入、粘贴以及日历选择。手输接受年在前的 `YYYY-MM-DD`、`YYYY/MM/DD`、`YYYYMMDD`；分隔格式的月、日可以省略前导零。输入过程中保留原文，离开输入框后才统一为 `YYYY-MM-DD`，避免逐字输入时被改写。日历提供年份与月份下拉，可直接定位历史日期。

空日期仍为可选。无效日期、不完整日期、月日在前的歧义格式以及多余尾部字符会保留输入并提示错误，不能保存；不存在的日期不会自动进位为下个月。普通保存与保存并发布均使用表单校验，服务边界另行校验，防止绕过界面。锁定记录禁用输入与日历。

年月下拉使用日历原有的原生选择控件。系统 `Calendar` 的根组件定义已移到渲染函数外，保持组件身份稳定，避免父级刷新时重建下拉元素、打断正在选择的年月；不通过延迟关闭规避问题。回归测试验证重渲染后同一 DOM 和焦点保留，浏览器实测点击展开并停留 1.5 秒后仍能正常选择。

## 格式与保存边界

| 环节 | 值与规则 |
| --- | --- |
| 正在编辑 | 保留输入原文，例如 `1998/1/15` |
| 失焦或有效表单提交 | `1998-01-15`，严格校验真实年月日，支持闰年 |
| HTTP 请求 | `masterDataControl.effectiveFrom: "1998-01-15T00:00:00Z"`，符合 Go `time.Time` 的 RFC3339 要求 |
| 清空日期 | 嵌套字段显式发送 `null`；不发送空字符串 |
| 省略日期字段 | 保留已有日期，兼容未编辑日期的调用方 |
| HTTP 响应与回显 | 从嵌套日期中保留声明的年月日，映射为表单、列表和预览使用的 `YYYY-MM-DD` |

日期传输由已经校验的日期字符串直接拼接 UTC 零点，不先创建本地午夜再调用 `toISOString()`，因此不会因正负时区换日。响应中的 RFC3339 时间戳只在读取边界转换，不允许把用户输入的任意尾部字符截断为有效日期。生效结束沿用同一传输契约。

本次同时修正原顶层表单日期与后端 `masterDataControl` 日期未映射的问题。后端继续只输出嵌套命名空间；前端投影用于兼容既有表单与展示消费者。修改后的顶层表单日期优先于详情里旧的嵌套日期，其余嵌套控制元数据保留。前端不向后端再发送一套重复的顶层日期。

后端请求类型记录日期字段是否出现。更新事务对显式 `null` 清空数据库列，避免共享元数据合并和 GORM 零值省略恢复旧日期；省略字段保持原兼容行为。日期清空在快照、审计和返回详情之前完成，仍受原锁定与乐观锁检查保护。

## 验证

自动测试覆盖历史日期、闰年、真实日历合法性、原文不截断、直接提交未失焦输入、保存及直接发布前校验、锁定只读、实际 HTTP 请求的嵌套 RFC3339 格式、日期回显、旧嵌套值不能覆盖编辑结果，以及省略与清空的区别。

后端使用隔离 PostgreSQL schema 验证新建、修改、清空、数据库与快照一致、未提交日期保留、版本冲突和锁定拒绝，不写入真实业务记录。浏览器通过隔离 API 检查桌面与手机输入、日历年月选择、弹层边界、Escape、无效输入阻断及 Enter 提交。
