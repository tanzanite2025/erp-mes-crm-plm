# BOM 三态生命周期、直接发布与保存发布事务

2026-10-24：当前业务使用“草稿 → 已发布 → 已作废”。研发 EBOM 和生产 MBOM 使用同一流程，不再进入评审或批准状态。

## 操作与历史兼容

- 新建弹窗同时提供“存草稿”和“保存并发布”。产品向导与两份指南复用同一编辑器和保存协议。
- 已有草稿提供“直接发布”，提交当前核对后的字段和配方；不需要先批准或关闭重开。
- 已发布记录内容锁定，可通过“作废 BOM”退出使用，确认后保留历史。已作废不能恢复为草稿。
- 历史 `REVIEWING`、`APPROVED` 继续读取和显示原状态，不批量迁移或自动发布；两者均可直接发布，历史批准内容继续只读，发布时不重新保存表单。
- 已发布且锁定的 EBOM 才能派生 MBOM；派生结果仍是独立生产草稿。发布生产草稿同样一步完成。已发布 MBOM 的既有修订行为继续生成已发布新版本并作废旧版。

## 权限与发布校验

沿用 `action_engineering_bom_manage`（编辑保存）和 `action_engineering_bom_promote`（状态操作）。保存并发布同时需要这两项；只有编辑权限仍可保存草稿，界面不显示发布按钮。生产 BOM 修订会直接发布替代版本，因此修订路由、服务和列表按钮也使用已有状态操作权限；没有发布权限时不能通过修订绕过发布限制。服务端状态权限矩阵识别现有的状态操作权限，兼容旧的 `bom:release`、`bom:obsolete`、`bom:manage` 与 `manage` 权限。

发布统一检查至少一条物料、正向用量、物料有效、正向成品重量和重量单位，并保留归属、引用、版本冲突及已发布 BOM 的范围唯一约束。重量和单位清空不能因结构体更新跳过零值而恢复旧值；新建发布也不会因数据库默认 `g` 而跳过未填单位的校验。独立状态入口先将大小写和首尾空格规范化，再执行权限与发布校验，不能以 `" released "` 绕过检查；数据库只写入规范状态。

## 单次保存发布协议

`POST /engineering/bom` 的 `publishOnSave?: boolean` 是命令参数，不存入 BOM 模型。省略或 false 保持普通草稿保存行为。true 在同一事务中保存内容，再调用共用状态转换函数发布；任一校验、权限、快照或通知写入失败会回滚整笔请求，不留下额外草稿或部分编辑。

既有 `/bom/:id/promote` 继续用于只读历史批准记录发布、独立状态转换及作废。业务状态的转换规则为 `DRAFT → RELEASED`、`RELEASED → OBSOLETE`；历史兼容允许 `REVIEWING → DRAFT/RELEASED`、`APPROVED → RELEASED`，不再允许进入旧中间态。

保存与发布分别记录快照，编辑已有草稿的一次保存发布使持久版本递增两次；新建普通草稿返回版本 1，新建保存并发布返回版本 2。前端乐观锁按操作核对推进量，普通新建不能误报“预期版本 2”。服务端保存、状态转换和生产修订先锁定同一 BOM 行，再核对版本，阻止并发重复发布或修订。派生对源 BOM 加共享锁，确保读取状态期间不能被并发作废。日期继续使用 `masterDataControl` 内的 UTC 零点 RFC3339，重量、物料和关系协议继续沿用原字段。

## 配方关联与修订一致性

新建和导入明细在进入关系构造器前获得稳定 UUID，保存时物料行 ID 与关系叶节点 `itemId` 指向同一行。再次打开编辑器时继续使用该身份，避免分组和嵌套关系依赖临时表单 ID。

派生与生产修订会生成新的物料行 ID，同时重映射关系叶节点 `itemId`；关系节点自己的 ID、父子结构和分组顺序保留。显式引用不存在源行的关系不能继续克隆。历史只有临时 `field:` 节点、没有物料行引用的记录沿用原兼容行为，本次不猜测关联或迁移历史数据。

生产修订在一个事务内重新检查发布权限、有效物料、用量和成品重量，旧版作废并将持久版本递增一次，新版直接发布并锁定。校验失败不改变旧版，也不留下替代版本或额外快照。
