# 产品模板独立属性配置与组件复用

产品模板直接拥有自己的属性定义和可选内容。打开车圈模板即可维护工艺系列、轮圈类型、制动类型等字段；其他模板分别维护自己的字段。不同模板可以有同名属性、同名选项，但各自保存，增删修改互不影响。

界面入口统一称为“物理规格模板”。编辑弹窗使用具体名称，例如“编辑 · 车圈物理规格模板”，表示维护产品建档时使用的规格字段和选项。具体产品在建档时分别填写并保存自己的规格值。

## 业务关系

- 模板定义字段名称、选项、排序、启用状态、是否必填。
- 具体产品使用所属基础型号关联的模板，并单独保存自己的属性选择值。同一模板建立的多个产品可以填写不同选项。
- 产品分类树独立维护一级分类、二级分类和第三级基础型号。例如“碳纤维车圈 → 山地车车圈 → R50”；R50 是自行命名的基础型号，在“产品管理 → 编辑分类 → 新增分类”中选择二级父分类，填写分类名称、编码并关联模板。
- 分类弹层维护分类和基础型号；产品管理的每张卡片对应一条具体产品记录。同属 R50 的多个产品可分别填写碟刹、V 刹等规格，并在 BOM 中管理各自需求。
- 卡片标题继续使用产品编辑底部“最终型号显示预览”的聚合规则。基础型号、产品规格和 BOM 资料分别读取自己的来源；属性选项名称必须按产品实际使用的模板解析，不能按同名字段从其他模板取值。

BOM 是产品生命周期管理的必备资料，承载物料组成、版本和升级记录。产品建立、BOM 准备与验证、确认后的关联可以分开操作：产品可先保存，BOM 经验证确认可用后再在“BOM 配方”中关联具体产品。产品保存不以先绑定 BOM 为前提。

性能版本 versionLevel 继续由 BOM 保存，其可选内容使用独立性能版本目录。在 BOM 表单的性能版本字段旁维护选项；它不参与产品模板的动态属性配置。

性能版本用于区分同一产品的标准版、轻量版、超轻版、加强版等配方与性能配置，与 BOM 的迭代版本号分别维护。界面统一使用“性能版本”（Performance Version），内部字段 versionLevel 和已有选项值继续保留。

性能版本目录只提供各具体产品共用的可选名称，不要求每个产品建立全部性能版本，也不额外维护产品与性能版本的配置关系。每份 BOM 按需选择一个性能版本，同时保存该具体产品在当前 BOM 配方下的重量与单位。这里按具体产品 `productId` 区分，同属一个基础型号 `typeId` 的多条产品记录不共用重量。性能版本、BOM 迭代版本号（如 V1.0）和 BOM 生命周期（草稿、审核、发布、作废）分别表达配置差异、迭代和状态。

BOM 表单使用一个“性能版本＋重量”组合选择组件，外部只保留性能版本下拉，选项和选中值一起显示版本名称、重量及单位，例如“超轻版 · 420 g”；不再单独展示成品重量与重量单位输入。重量和单位统一在版本选项弹窗右侧编辑，不要求先给 BOM 选择版本才能填写。版本管理弹窗将“本型号已有版本”与“其他可选版本”分开展示；界面中的“本型号”实际指当前选中的具体产品及其 BOM 类型、归属范围。已有版本旁直接列出重量；未采用的共用选项不显示成 0g。点击版本或填写它的重量，即选用于当前 BOM 草稿，无需额外点击选用按钮；未采用的版本从空重量开始，不沿用上一个版本的数值。版本之间切换保留当前会话的各自重量草稿，列表与下拉标注“本次暂存”；仅当前选中版本随 BOM 保存，不会批量保存其他版本。切换具体产品或归属时清空旧版本与重量。

未选择产品时，性能版本下拉和选项管理按钮禁用，界面直接提示“请先选择产品”；选择产品后即可使用。管理按钮使用蓝色底色与图标，便于识别可点击入口。BOM 编辑弹窗在桌面采用左侧产品与 BOM 信息、右侧配方明细布局；移动端通过“基本信息”和“配方明细”两个步骤切换，保留填写草稿。组件职责和后续扩展约定见 [BOM 编辑弹窗职责边界](bom-editor-dialog-product-information-recipe-layout-and-responsibility-boundaries.md)。

重量对比只读取同一具体产品、BOM 类型和归属（内部或同一客户）的完整 BOM 元数据，不受默认分页限制，不混用其他产品、客户或生产/研发 BOM 的重量。每个性能版本优先显示最新已发布记录，没有已发布记录时显示最新未作废记录；当前打开的 BOM 使用当前草稿值，并标明来源和发布状态。作废记录仍在原有生命周期与历史功能中保留。共用选项单独保存，重量随当前 BOM 保存，弹窗不会创建或修改其他版本的 BOM。

BOM 性能版本使用产品结构模块自己的单个管理弹窗：左侧列出现有版本，底部提供添加按钮，右侧直接新增或编辑性能版本名称、英文名、说明和启用状态，不再嵌套新增或编辑弹窗。弹窗适当加宽加高，名称与英文名并排，收紧标题、重量卡片、说明及各分组的留白，使常用桌面尺寸下的表单完整显示。保存并刷新下拉选项后，提示“性能版本已保存，可在下拉菜单中选择。”，约 0.5 秒后自动关闭，返回 BOM 下拉选择；短暂停留期间阻止编辑和重复提交。保存失败保留输入，不自动关闭；保存期间阻止切换、关闭和重复提交。不打开产品一级或二级属性分类编辑器，也不要求先创建产品属性分类。列表和 BOM 下拉只查询独立性能版本目录，保存后同步刷新可选项与产品展示。兼容存储所需的内部固定目录由服务端在写入时确保存在，不向用户提供分类选择。

“如何建立 BOM”作为独立说明页解释上述业务含义，与“如何建立产品”同级；五个章节 Tabs 只切换阅读内容，不接业务弹窗。导航、文件分工及说明范围见 [BOM 说明指南](bom-creation-operation-guide-content-navigation-and-responsibility-boundaries.md)。共用物料分组的维护与配方内编辑由 [BOM 编辑弹窗](bom-editor-dialog-product-information-recipe-layout-and-responsibility-boundaries.md#已实施的配方单视图与共用分组管理) 承接，独立于产品模板属性与性能版本名称目录。

## 编辑与保存

统一入口为 /engineering/templates。模板编辑直接展开当前模板的属性及其选项，支持新增、修改、移除、排序、必填和启用设置，无需进入公共属性库或先创建公共分类。

所有属性编辑保留在当前模板草稿内，通过“保存模板”一次提交。取消不写入属性或选项，保存失败保留草稿，保存期间阻止重复提交和关闭。模板保存成功后刷新模板及属性展示缓存。

删除模板、规格属性或下级选项时，统一使用系统确认弹窗，必须输入大写 `DELETE` 才能确认。删除属性会同时移除其全部下级选项。属性和选项确认后只从当前编辑草稿移除，保存模板后才生效，取消编辑可撤销；模板本身确认后直接请求删除。关闭确认弹窗再打开时，确认词清空。

已有产品引用的属性或选项不能直接删除；可停用以限制后续新选择，既有产品仍保留并显示原值。未被使用的属性和选项可以删除。后端按基础型号的分类继承链定位模板，并验证产品提交的属性和选项属于该模板。

分类或基础型号仍关联模板时禁止删除该模板，并提示先调整分类的模板关联。未使用的模板删除时，其独立属性定义一并移除。

不提供独立属性分类 TAB、独立分类路由、公共分类库入口或旧地址兼容跳转。HOME 和操作手册统一进入产品模板页。

## 变更记录

模板页面提供全部物理规格模板的“变更记录”，每张模板卡片也提供该模板的记录入口，复用系统全局审计时间线。记录覆盖模板创建、保存、字段修改和删除，包含操作人、时间、历史模板名称及修改前后内容；属性和选项的名称、说明、排序、必填和启用状态一并保存。操作人从服务端认证上下文取得。

历史展示读取保存当时的快照，不依赖当前模板或选项仍然存在。删除选项、修改模板名称或删除模板后，仍可在页面全局记录中查看当时的内容。模板每次保存重建属性记录的内部 ID 不作为业务变更展示。

业务写入与审计写入使用同一数据库事务。验证失败、版本冲突、批量保存失败或审计写入失败时整笔回滚，不留下对应的成功记录。属性和选项仅修改草稿、确认移除后又取消编辑时，不产生业务变更记录。保存和删除成功后同步刷新全局与单模板的记录缓存。

审计接入前未记录的历史操作无法补出真实操作人；变更记录从本次接入后产生。

规格模板编辑、删除确认和记录面板沿用系统颜色及胶囊按钮。Chrome 109 在这些浮层打开时使用局部视口兼容样式，避免根节点双侧滚动条预留空间使弹窗及关闭按钮偏移；现代浏览器保留原有布局。记录头部的操作人、对象与时间使用随主题变化的前景色。

## 数据与迁移

ProductTemplateAttributeBinding 记录模板自身的字段名称及 options 选项数组，不再只记录公共分类引用。categoryKey 和 optionValue 继续作为当前模板范围内的字段和值标识，具体产品的已有选择无需改写。

启动迁移按已有模板引用复制名称、说明和全部选项，每个模板获得独立数据。迁移包含事务与一次性标记；重复启动不会覆盖已经独立编辑的模板，遇到缺失定义整批回滚并报告问题。

属性展示查询返回带 templateId 的模板属性投影，独立目录只返回 BOM 性能版本。产品卡片、产品填写和建档步骤优先直接读取模板自己的定义；聚合名称按模板范围匹配选项。

模板读取由查询层管理缓存，服务层仅合并同时进行的请求，重新查询会读取服务端数据。产品弹窗关闭时不发起模板请求，重新打开时更新定义；切换基础型号时重新解析对应模板，解析完成前暂停提交，旧请求不得覆盖当前选择。

模板 ID 和分类继承链中的模板关联优先于表单组件类型。明确关联的模板不存在时显示未解析状态，不借用其他模板；多个模板可以复用同一表单组件，组件类型本身不能用来区分模板的业务数据。

产品变更记录按变更前后各自的模板读取属性名称和选项名称。产品已删除时，优先使用记录中的模板或分类定位；无法定位时展示原始记录值，不从其他模板借用名称。停用属性不影响已有产品已填值的展示。

模板全量保存、字段补丁和产品属性写入锁定同一模板记录。并发修改时取得锁后重新核对版本和引用，失败整笔回滚，避免保存已被删除的选项或被旧版本覆盖。

## 验证

- PostgreSQL 隔离测试：迁移独立性、重复执行、失败回滚和产品原值保留。
- PostgreSQL 服务和 HTTP 测试：同名属性隔离、跨模板选项拒绝、版本冲突、已有引用保护及并发保存；审计操作人、删除后的历史快照、全局及单模板记录权限、审计失败与批量保存失败回滚。
- 前端测试：DELETE 确认词校验、取消后清空、确认删除后的草稿保存、历史记录入口及被删除选项的展示；草稿隔离、取消、失败重试、重复提交拦截、产品标签按模板解析，以及远端刷新、弹窗重开和型号切换时的请求隔离。
- 类型、格式、国际化和生产构建检查；浏览器布局与 Chrome 109 兼容检查另行记录实测结果。
