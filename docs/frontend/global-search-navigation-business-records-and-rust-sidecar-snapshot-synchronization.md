# 全局搜索：导航、业务记录与 Rust 侧车索引同步

系统整体的 TS、Go、Rust HTTP/CLI/WASM 与原生 SDK 分工见[跨语言职责和集成契约](../architecture/typescript-go-rust-and-native-sdk-runtime-responsibilities-and-integration-contract.md)。本文说明当前搜索实现。

底部菜单栏和 Ctrl+K 共用一个搜索弹窗。搜索分为页面入口、业务记录、快捷操作和知识库。

## 页面入口

`global-search-navigation-catalog.ts` 从侧边栏、模块页签和带规范名称的已认证路由生成页面索引，包含物料分类页。搜索目录与导航配置同步，不再依赖手工维护的业务链接白名单。参数化详情地址不会生成空链接。

`search-data.ts` 中原有的模块配置仅补充历史别名和拼音，不增加独立于导航的页面。页面名称及所属分组同时支持中英文关键词，空白分隔的多个关键词按 AND 匹配，支持全角字符归一化。展示前按当前用户的路由权限过滤。知识库关联页面和命令目标选择器共用完整的页面选项。

## 业务记录

`GET /api/v1/search/global?q=...&limit=30&offset=0` 由 Go 接收请求、校验权限，调用 Rust/Tantivy 侧车检索，再从业务数据库读取当前记录并生成跳转地址。TS/React 负责导航入口匹配、弹窗交互和结果跳转，不承担业务后端查询。

所有来源集中定义在 `server/services/global_business_search_source_catalog.go`，每个来源同时定义表、搜索字段、关联字段、读取权限、页面与详情参数。

订单和审批状态、供应商主营产品等原有索引字段也纳入统一目录。UUID 和 JSON 字段统一转换为可搜索文本。

销售、报价、退货和换货共用产品行身份字段定义，销售与报价额外包含客户料号、工程规格名称、型号快照和工单号。新增字段或关联只登记在来源目录；索引投影、当前数据复核和变更依赖共用这些定义。退货/换货关联的是各自保存的历史明细，不用后来修改的产品档案覆盖单据身份。

Go 把可访问类别和当前用户范围传给 Rust，在索引检索和分页前过滤。审批归属由目录中的用户字段声明，权限管理员可查询全部。返回前 Go 重新检查当前记录、软删除、类别划分、关键词和审批归属，防止旧索引泄露已删除或改派记录；被过滤的命中会继续补页。nextOffset 表示已消费的 Rust 命中位置，可能大于可见结果数。订单关联明细与伙伴资料统一投影成一份文档，不重复返回主单。

来源的读取权限以实际列表接口为准。审批列表读取要求 `menu_approval`，单独拥有 `action_approval_review` 不授予列表读取权。审批目的页验证并读取 `requestId`，从当前可访问列表显示所选记录，包括本人曾处理、已不在待办区的历史申请；不存在或失去访问权时明确提示，读取故障另行报错。

支持中文和编码的部分匹配、单字查询、不区分大小写、全角输入归一化，以及跨主单和明细的多关键词 AND 匹配。Rust 用 1～3 字符 n-gram 倒排索引筛选候选，再验证完整片段；不使用 QueryParser 解释用户输入。`%`、`_`、`!`、`&`、`/` 等均按字面字符匹配；RPC 使用 JSON，跳转参数使用 URL 编码，数据库读取使用参数绑定。精确编码优先，其次为精确名称和前缀匹配，最后为部分匹配。

每页默认 30 条，上限 100 条；响应返回 `data`、`hasMore`、`nextOffset`、`generation` 和 `candidateLimitReached`，弹窗提供“加载更多业务结果”。后续页必须携带当前 generation；Go 补页也固定同一标识。如果内容变化则返回 `409 / GLOBAL_SEARCH_SNAPSHOT_CHANGED`，前端清除旧分页并重新加载第一页，避免混合不同排序快照导致漏项或重复。自动重启后若第一页仍发生冲突，则显示失败并提供手动重试，避免持续重启请求。generation 来自稳定投影的内容指纹，数据相同的周期重建不打断分页。

单次关键词查询可分页检查前 100000 个经过 Rust 类别/用户范围过滤的候选，起始 offset 为 0～99999。Go 在临近边界时缩小补页批次；Rust 同时拒绝越界批次。若窗口外仍有命中，最后一页返回 `candidateLimitReached: true`、`hasMore: false`，保留已找到的记录并提示补充订单号、料号或客户名。即使窗口内命中全部因过期而被排除，也显示缩小范围提示，避免误报无结果或侧车故障。只有 `hasMore: true` 时才能使用 nextOffset 请求后续页。

输入上限为 200 字符、8 个关键词，offset 上限 100000；单次查询超时为 5 秒。前端按关键词、用户和权限隔离查询缓存。换关键词、卸载或关闭弹窗会取消在途请求，取消信号经共享 apiFetch 传递到 Go 及其 Rust HTTP 调用；主动取消保留原始原因，不计为超时或服务故障，Go 不再为已取消查询记录侧车故障。网络超时覆盖完整响应体读取。

前端 API/DTO 边界集中在 `src/features/global-search/services/global-business-record-search-api.ts`。Zod 校验结果字段、内部目的页和分页契约；缺字段、旧协议或不前进的分页明确报错，避免默认空数组掩盖问题。搜索采用独立的熔断状态，搜索失败和恢复不改变其他业务 API 的故障计数；认证检查继续走共享机制。

查询失败时提供“重新搜索”，统一清除当前分页并从第一页重试。菜单按稳定结果 ID 管理键盘选择，同名同编码记录仍可分别选中。

这 11 类是当前记录搜索的覆盖范围。其他模块可搜索其页面入口；新增记录类型需在统一目录中注册字段、关联、权限和目的页，并补充记录回归用例。通用投影、索引重建、变更依赖与详情读取自动使用该目录，无需再添加独立同步分支。

## 索引生命周期与一致性

Go 的 global_business_search_snapshot_coordinator.go 统一管理同步，替代原来分散在业务服务中的五类异步逐条推送。

- 启动立即构建，失败每 3 秒重试，不再只重试 5 次后永久放弃。
- 从目录自动收集主表与关联表，Gorm 创建、更新、删除统一触发刷新，750ms 合并连续写入，单个进程串行构建。
- 每 30 秒再次校准，修复侧车单独重启、原始 SQL、外层长事务或其他 Go 实例写入后的索引遗漏。该机制为最终一致：Gorm 正常写入通常在合并等待加构建耗时后可搜索，兜底写入在下一次周期加构建耗时后可搜索；并非事务提交即刻可见。
- PostgreSQL 使用只读 REPEATABLE READ 快照，以主键游标每批 250 条读取。关联字段按批量查询合并，Go 不一次加载整张业务表。
- 关联键类型由目录声明。UUID 引用统一归一化，非法历史字符串不传给 PostgreSQL UUID 列；缺失关联时保留主单和历史名称，避免一条异常引用阻断整个目录。
- Rust 提供 start / batch / publish / abort 协议。新索引写入独立 staging 索引，全部成功后原子替换；任何步骤失败均放弃新索引，旧索引继续可查询。完整替换也清除已删除记录和旧类别。
- Rust 统一限制只允许一个索引构建，避免多个 Go 实例交错推送；失联构建 120 秒无新批次后可被替换。完整构建超时为 2 分钟，失败记录日志并重试。
- 索引 RPC 使用构建预算，查询 RPC 使用 5 秒预算，避免完整索引发布被查询级短超时提前截断；调用方的 context 截止时间始终生效。
- 首次完整索引尚未发布、侧车离线或协议不匹配时返回 503，弹窗显示搜索失败，不将故障显示为“没有结果”。图像处理接口保留。
- Rust 对候选逐条校验，并使用有界排名堆，每个分段只保留 offset + limit + 1 条，避免宽泛查询积累全部结果后排序。

当前采用内存索引，侧车重启后由 Go 自动恢复。每次校准扫描完整目录，重建成本随总记录数增长；规模扩大时应基于同一来源目录增加持久化索引和增量变更日志，而非恢复逐模块同步分支。

## 部署

本次同时修改 Go 与 Rust 的内部 RPC 协议，需要配套构建并发布两者（先停止旧 Go 写入，再替换 Rust 和 Go），随后等待完整快照发布日志。旧 Go 的逐条 /v1/index 推送和 GET /v1/search 协议已移除；不支持混用新旧实例。无需新增 PostgreSQL 文本索引或手工执行 pg_trgm 迁移。

开发可用 SEARCH_ENGINE_PORT 为测试 Rust 进程设置独立端口；Go 继续通过 SEARCH_ENGINE_URL 配置侧车。生产侧车端口仅应暴露给 Go 或受控本机网络。

## 验证

前端回归覆盖导航与页签完整性、中英文别名、多关键词、特殊字符、单字查询、关闭状态、请求乱序与取消、继续加载、快照变化后整体刷新、失败重试及列表的路由筛选更新。API 边界测试覆盖响应 Schema、分页进度与代际、搜索熔断隔离、认证保留、调用方取消及响应体超时；视图测试覆盖重试按钮和同名记录的方向键选择。

cargo test 覆盖中文与编码片段、字面标点、全角归一化、完整片段验证、精确编码排序、权限先于分页、原子发布、过期代际拒绝、冲突及中断保留旧索引，并保留图像处理回归。

Go 的 TestGlobalBusinessSearch\* 默认验证来源字段、主表/关联投影、统一变更失效、失败时中止快照、补页代际一致性、候选窗口边界及审批读取权限，以及 HTTP 参数校验、409/503 区分。设置 GLOBAL_SEARCH_TEST_RUST_URL 指向本次构建的独立 Rust 进程，可运行真实 Go → Rust → 数据库链路，覆盖 11 类记录、明细料号、退换货明细与标签、伙伴当前名称、权限、分页及旧索引再校验。设置 GLOBAL_SEARCH_TEST_POSTGRES_DSN 可使用 PostgreSQL，每个用例创建并清理独立 schema，验证 UUID/varchar 关联、异常历史引用、多批构建，以及相同内容重建后保留分页和内容变化后拒绝旧分页。前端额外验证审批目标参数、已挂载页面切换记录、目标不可见与读取故障，以及候选上限提示。集成测试不修改应用业务数据。
