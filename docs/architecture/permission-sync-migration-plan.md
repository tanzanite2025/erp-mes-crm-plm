# Permission Sync Migration Plan Closeout

> 状态：历史迁移计划已关闭。
> 更新时间：2026-07-26
> 当前权威文档：`docs/architecture/组织人员归属-账号权限边界与文件职责计划.md`

## 关闭原因

这份文档记录的是早期从历史 `users.role` 权限字段迁移到后端有效权限解析的阶段性方案。当前代码已经出现新的 `IdentityAccessService`、`/auth/snapshot` 接入和账号访问画像查询能力，原文里的阶段划分已经不是当前执行清单。

同时，原文中关于“职位字段映射权限”的候选方向不再作为当前权限架构原则。职位可以作为组织人事资料展示或任职属性，但当前不得作为生产扫码、工序执行、页面按钮或普通账号权限的默认推导来源。

## 当前保留原则

1. 后端是权限裁决唯一真相源。
2. 前端只消费 `/auth/snapshot`、登录返回和访问画像接口，不自行按部门、职位或文字名称推导权限。
3. 账号代表人员在系统中的执行身份，负责登录、状态、权限预设、显式权限和绑定人员档案。
4. 人员归属用于组织关系和业务上下文，不代表某个页面或动作权限。
5. 页面权限、命令权限、动作权限必须显式分配到账号或账号权限预设，不从生产工序、职位名称或产线节点反推。
6. 当前物理字段已迁移为 `users.permission_preset_id`，对应表为 `permission_presets`；历史 `users.role / roles.role_id` 只在启动迁移中作为旧 schema 来源识别，不再作为运行时字段或接口。

- `docs/architecture/组织人员归属-账号权限边界与文件职责计划.md`
