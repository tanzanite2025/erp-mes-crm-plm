## 当前实现与缺口

已有生产领料工作区 `/mrp/production-material-issuance`、独立指南 `/mrp/production-material-issuance-guide`、导航和页面权限。工作区按“物料汇总／订单行进度”展示后端完整范围统计，分别分页，单据与领退记录作为追溯区域。指南解释已接入的进度、领退规则及仍未接入的打印／消息边界，不提供虚构数量、发送、保存或发料确认。前端维护说明见[工作区与指南文档](../frontend/production-material-issuance-workspace-tab-and-warehouse-confirmed-movement-integration-boundaries.md)。

[MRP Go 服务](../../server/services/mrp_requirements.go) 已使用独立的逐订单行配方展开、生产物料仓库可用量及包装投影能力，返回订单 ID／行 ID／版本、BOM ID／版本／修订、性能版本、成品重量与逐来源物料贡献。多份适用配方需要明确选择，来源不完整时不生成汇总。重复配方贡献不再重复累计成品数量。具体字段与文件职责以[共用需求计算契约](production-material-requirement-shared-expansion-bom-selection-stock-allocation-and-packaging-calculation-contract.md)为准。MRP 查询和打印仍是分析参考，不自动创建正式单据。

[当前打印](../../src/features/mrp/components/requirements/requirement-drawer.tsx) 只是浏览器打印，Excel 导出只产生文件，仓库共享提示没有发送处理。裁纱下发建立生产计划和任务，不是物料级库存交接。[通用出库确认](../../server/services/inventory_command_service.go) 带销售发货数量与销售出库凭证逻辑，不能直接作为生产领料命令。

Go 领域层已提供来源核对、下发、撤回、冻结单据详情及分页查询；单据／来源／覆盖／回执四个模型和仓库交接／批次物料／订单行分配三个模型均已注册主迁移，但此次开发没有对业务数据库执行迁移。下发同事务保存冻结依据、有效覆盖、幂等回执与审计，撤回保留历史并释放覆盖。销售订单的保存、明细编辑、客户／分类／状态变更、取消、删除及批量同步已接入来源保护，冲突通过现有订单 HTTP 入口返回 409 和 `PRODUCTION_MATERIAL_SOURCE_PROTECTED`。

读取接口分别承接来源核对、单据分页、冻结详情及完整有效订单进度，另有独立下发／撤回命令。MRP 完整分析后先明确核对，再确认全部来源下发；生产领料页在原单详情内填写原因并撤回。读取不创建单据，下发／撤回也不创建收发事实或预占、扣减库存。独立仓库领域命令已承接实际发料／补料／退料、逐订单行发退分配和原子库存移交，仓库核对、建议及确认 HTTP 和独立动作权限现已注册，原单内办理界面已接入；正式打印、主动待办队列及消息仍未接入。HTTP 身份来自认证上下文，不接受客户端指定操作者。仓库实现及独立文件职责见[正式交接、订单行归属和库存保管契约](production-material-issuance-confirmed-warehouse-movements-order-line-allocation-and-custody-inventory-transfer-contract.md)。

## 已开放的 HTTP 与授权范围

下列路径均位于 `/api/v1`，要求已认证身份及独立动作权限 `action_production_material_issuance_view`（生产领料：查看依据与单据）。来源核对、下发与撤回另需 `menu_mrp`、`tab_mrp_requirements`、`tab_mrp_production_material_issuance` 中至少一项生产业务访问权限；已下发单据列表和详情也接受 `menu_warehouse` 作为业务访问。仅页面、仅指南、仅动作或仓库出库权限均不能读取；该动作不授予发送、撤回或仓库收发权限。

| 请求                                                            | 输入与响应                                                                                                                                                                                                                |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /mrp/production-material-issuance/source-review`          | 严格 JSON `{sources:[{salesOrderId,salesOrderLineId,bomId}]}`，明确选择 1–500 条整行来源；返回 `{sources,warehouseCategoryCode:"MATERIAL"}`，包含真实来源、订单／BOM 版本、成品重量与性能版本、逐配方行贡献及完整依据指纹 |
| `GET /mrp/production-material-issuance/active-order-progress`   | 生产访问＋查看动作；`materialsPage,ordersPage,pageSize` 默认 1／1／20，页大小上限 100；统一读取完整有效订单范围，先统计后分页，包含异常来源及完整性标识，见独立进度契约                                                   |
| `GET /mrp/production-material-issuance/documents`               | 仅接受 `status`（空、`DISPATCHED`、`WITHDRAWN`）、正整数 `page` 和 `pageSize`；默认 1／20，页大小最多 200，拒绝重复／未知参数及分页偏移溢出；返回 `items,total,page,pageSize`                                             |
| `GET /mrp/production-material-issuance/documents/:id`           | 按真实单据 UUID 返回 `{document,sources}`，只读冻结来源，不按当前订单行号或 BOM 重算历史                                                                                                                                  |
| `POST /mrp/production-material-issuance/dispatch`               | 严格 JSON `{commandId,sources:[{salesOrderId,salesOrderLineId,bomId,expectedOrderVersion,expectedBomVersion,basisFingerprint}]}`，只接收真实来源、预期版本和指纹，不接收客户端计算数量；返回 `{document,sources}`         |
| `POST /mrp/production-material-issuance/documents/:id/withdraw` | 严格 JSON `{commandId,expectedVersion,reason}`，单据身份只取路径；原因必填、去首尾空格后最多 2000 UTF-8 字节；返回保留冻结来源的 `{document,sources}`                                                                     |

HTTP UUID（包括命令 ID）要求完整规范小写格式；JSON 请求上限 256 KiB，拒绝未知字段、客户端操作者及尾随 JSON。成功响应使用 `Cache-Control: no-store`。错误显式返回：400／`PRODUCTION_MATERIAL_ISSUANCE_INVALID_REQUEST`，409／`PRODUCTION_MATERIAL_ISSUANCE_BASIS_CHANGED`、`PRODUCTION_MATERIAL_ISSUANCE_SOURCE_COVERED` 或 `PRODUCTION_MATERIAL_ISSUANCE_COMMAND_REUSED`，404／`PRODUCTION_MATERIAL_ISSUANCE_NOT_FOUND`，500／`PRODUCTION_MATERIAL_ISSUANCE_QUERY_FAILED` 或 `PRODUCTION_MATERIAL_ISSUANCE_COMMAND_FAILED`。内部错误记录在服务端，响应不泄露 SQL。

下发在业务访问及查看权限之上，另需 `action_production_material_issuance_dispatch`；撤回另需 `action_production_material_issuance_withdraw`。两个动作互不替代，也不授予仓库确认权限。沿用当前系统共享生产范围，撤回不按是否为原下发人猜权限；任何具有明确撤回权限的账号仍受原单版本、状态和仓库执行事实约束。

仓库新增 `GET /mrp/production-material-issuance/documents/:id/warehouse-review`、`POST /mrp/production-material-issuance/documents/:id/ordinary-allocation-suggestion`，以及末段分别为 `/issue`、`/supplement`、`/return` 的确认 POST。查询接受生产或仓库业务访问＋查看动作；确认只接受仓库访问＋查看＋各自独立领退动作。动作、原单和操作者均不能由 body 伪造。具体载荷、错误码、幂等及文件职责见[仓库 HTTP 契约](production-material-issuance-warehouse-http-review-allocation-suggestions-confirmation-permissions-and-error-contract.md)。

当前系统只有页面／动作权限，没有按客户、组织或个人划分订单的数据范围基础设施。因此该查看动作的授权范围为**当前系统共享生产数据**：可核对选定的有效来源，并查询所有正式领料单及其冻结来源，不按下发人过滤，也不表示已实现客户或组织隔离。未来引入细分范围时，须在来源读取及列表统计、分页之前统一约束，不能靠浏览器过滤或只限制详情。

前端 DTO 复用 MRP 的 BOM 候选与配方贡献 schema，额外校验来源／单据身份、单位、正重量、指纹及分页完整性；API service 无界面副作用，React Query 管理远端快照。没有查看动作权限时不挂载查询组件、不发请求。分析范围、BOM 选择、完整性或加载状态变化时卸载旧核对，旧异步响应不能显示在新范围。核对结果只表示读取成功，不能显示为已发送或已领料。

命令 DTO、service、Hook 与下发／撤回控件各自独立；正式结果必须验证来源集合、BOM、预期版本和指纹，撤回另校验返回单据、递增版本、状态及原因。下发旧请求若返回已经撤回的原单，界面明确显示原单已撤回，不冒充新下发。下发成功区订阅同一原单 Query，后续撤回同步更新展示；查询失败明确报错，不继续把旧回执当作当前状态。确认范围为分析的全部来源，不随表内搜索或缺料过滤缩小。

当前会话内以 React Query Mutation Cache 保存已准备的命令变量，按操作者、动作和依据范围隔离；双击受同步保护，明确点击重试沿用原命令 ID 和完整载荷。下发依据变化、单据版本变化或账号切换会重挂载对应命令控件，旧结果不显示到新范围。网络／超时／非法响应标为结果未确认，明确的 4xx 拒绝另行提示；均不自动换键或重试。`retry:false` 与 `networkMode:always` 防止离线挂起后自动重放，命令不进入浏览器离线队列。

会话内请求恢复不是持久化待办或跨刷新回执恢复。重载页面、重开应用或清空 QueryClient 后，应先查询正式历史并重新核对；后台有效覆盖仍防止同一订单行重复下发。当前未增加客户端正式领料账、第二套离线存储或自动提交任务。

## 系统生产物料仓库的固定身份

现有 `MATERIAL` 仓库已经是系统内置仓库，唯一规范名称为“生产物料仓库”。它存放生产所需物料，承接采购收料、物料入库及库存管理；名称不表示生产领料、订单行归属或库存过账对接已经实现。

初始化按固定编码 `MATERIAL` 查找并沿用原记录，缺失时才创建；该系统仓库名称与预置名称不一致时直接统一为“生产物料仓库”，不保留名称别名或按历史名称分支的兼容逻辑。其他编码的自建仓库名称不受此规则影响。此次调整不更换仓库 ID、编码、库存余额、批次、成本或历史关联。系统仓库继续禁止通过普通分类维护接口编辑、停用或删除。列表按数据动态渲染不影响系统身份，也不需要再创建一个生产专用物料仓。

首期生产领料接入时固定从 `MATERIAL` 读取适用批次和可领量，界面自动带入“生产物料仓库”，不增加每次选仓步骤。后端按编码定位并校验系统仓库及业务能力；不能按中文名称、列表顺序、跨环境固定 UUID 或任意默认入库仓推断来源。缺失或不可用时明确阻塞，不能退回其他仓库。MRP 分析现也固定读取 MATERIAL，并逐批次扣除有效 RESERVED 占用、跨分组分配同一份可用量。领料接入继续复用这套需求、库存缺口及包装能力，不重建计算或库存账。

## 两个页面共用需求依据

共用的最小需求粒度为“稳定订单行 × 物料 × 采用的 BOM 依据”，保留原配方行贡献；同一物料在该订单行中重复出现时先汇总标准用量，再计算该行待领。MRP 与生产领料调用同一份后端配方展开能力，不能各自维护一套正式需求算法。MRP 保留理论需求视角，生产领料在需求依据上关联正式领退事实。

生产领料的默认范围来自有权限的有效订单行，而非已有领料单集合；支持与 MRP 显式选择一致的订单范围，并明确显示状态、仓库等筛选条件。未下发来源也必须进入需求范围并显示“未下发”，不能因为没有单据就从总体待领中消失。取消、关闭等来源退出范围须有后端明确规则，历史单据和收发事实仍可追溯。

| 来源状态                | 生产领料采用的依据                                                                                     |
| ----------------------- | ------------------------------------------------------------------------------------------------------ |
| 尚未下发                | 当前可用配方形成的待核对需求，标明未下发；缺少配方、版本或单位时显示具体阻塞，不能当作需求为零或已齐套 |
| 已有效下发              | 原单冻结的来源数量、BOM／修订及标准需求；同一来源只计一次，不能再叠加一份当前预览需求                  |
| 下发后订单或 BOM 有变化 | 保持历史基准并指出变化，经过明确变更处理后采用新的有效依据，不能查询时静默重算旧单                     |

重复分析、重打、分次领料、追加补料均不增加标准需求。订单编辑及配方变化处理应保留有效依据关联，防止一条订单行被不同单据重复统计。

## 总体物料与订单行进度

工作区默认按物料汇总，可展开来源订单及订单行；“按订单查看”以订单 → 订单行 → 物料展示同一组事实。两种视角共用查询范围与数量口径。单据查询、打印和收发历史为办理及追溯入口，不作为需求范围的唯一来源。

每条订单行、同物料、兼容主单位内计算：

```text
标准应领 = 覆盖成品数量 × 已核对配方的物料标准用量合计
净领料 = 累计已领（包含补料）− 累计退料
尚待领料 = max(标准应领 − 净领料, 0)
超标准领料 = max(净领料 − 标准应领, 0)
同物料总体待领 = sum(各订单行尚待领料)
同物料总体超标准 = sum(各订单行超标准领料)
```

同一订单行的多条配方贡献先汇总，跨订单行的待领和超标准分别汇总。例：A 行标准 200、净领 220；B 行标准 200、净领 160，则总体待领 40、超标准 20，不能用 `max(400 − 380, 0) = 20` 掩盖 B 行欠领。将 A 行材料转给 B 行需要明确的归属调整依据，不能由查询自动抵消。

标准、已领、已退、净领可按同物料主单位加总。生产领料只计算领退进度；需求、库存缺口与包装换算统一引用共用需求能力，不增加基于待领数量的第二套缺口算法。理论需求与尚待领料语义不同，不能互相替换；实际确认仍须在事务内重新校验库存。

不同料号、不同且未经验证可换算的单位不能合成一个“总缺料数量”。顶部可显示待领料号种类、未领齐订单行数、未下发订单行数及依据异常数；缺失依据单独展示，不能标记已领齐。后端对完整查询范围聚合后再分页，前端不能以当前页行数或数量代替总体结果。

## 合并发料的订单行归属

1. 下发时保留每条订单行的标准需求、覆盖关系和确定的分配顺序。仓库按物料汇总拣料，核对本次实际发出数量及批次，无需逐订单重新建单。
2. 服务端按已保存的来源顺序及各行待领量生成分配建议，普通发料最多分至该行剩余标准量；确认前可展开查看并明确调整。超标准部分通过有原因、明确归属的补料处理。
3. 确认请求必须绑定本次查看的单据／依据版本。服务端重新检查需求、待领及库存；并发或依据变化时返回冲突，不能在确认时静默换一套分配。
4. 每笔实际发料的订单行分配合计必须等于该笔发料量，物料、单位和批次关联可追溯。归属、库存过账、幂等回执与审计同事务保存；已领统计只读正式确认的分配事实。
5. 补料保留来源订单行和原因；退料关联原发料及其订单行分配，分别校验可退量。首次接入不将无归属的共享池领料计入某订单行的已领，不事后按理论比例猜测实际归属。

这些分配记录承接领料归属，不维护第二套库存余额，也不生成生产实际消耗。默认建议减少日常录入，保留确认前核对与差异调整能力。

## 最小办理闭环

1. 发起人集中核对订单明细、覆盖数量、BOM／修订、物料和目标仓库，选择“发送至仓库”或“发送并打印”。搜索、折叠和仅看缺料不隐式改变正式发送范围。
2. Go 在事务内检查来源、依据变化、有效覆盖和重复请求，生成正式单号，保存冻结基准、下发人、时间和目标仓库。返回正式结果后前端才显示发送成功。
3. 仓库直接查询待发料单；纸张单号或拟支持的二维码用于定位同一张原单。二维码不携带授权凭据，不绕过登录和数据权限。
4. 仓库勾选本次实际发出的物料，核对数量、批次及订单行分配建议，一次确认。同事务保存实际收发、逐订单行归属、库存过账及必要审计，失败整体回滚，不再手工建一张相同的销售出库单。
5. 补料、退料沿原单留痕，保留原因。部分领、领齐、超标准等进度由正式数量推导，无需人员手工改进度标签。

| 用户看到的事实 | 判定依据                                     |
| -------------- | -------------------------------------------- |
| 已下发         | 正式单号、下发人和时间已提交，目标仓库能查询 |
| 已提醒／已读   | 消息中心的实际收件和账号阅读状态             |
| 已领料         | 仓库对实际交接的正式发料确认                 |

打印、打开单据、排产、完工和消息已读都不推导已领。发送并打印先提交后打印；浏览器不能可靠证明出纸，取消打印不自动撤回已下发单。重打读原单，不增加应领或新单。参考分析输出与正式单据须有明显标识；打印正式单据读取冻结的后端依据，并提示核对当前状态，撤回后的旧纸不能充当有效发料授权。

## 来源身份与配方基准

正式单据至少保存：订单 ID、稳定明细身份、业务行号快照、来源版本／用量相关指纹、产品和客户归属、覆盖成品数量、BOM ID／修订／性能版本、配方行身份、标准用量、主单位和计算结果。显示名称快照用于历史解释，不代替实体身份。

2026-10-27 已修正销售保存的明细身份：存量行按真实 ID 保留，行号只作显示和排序；新增行生成新 ID，重复、跨订单及已移除 ID 均拒绝。普通保存、SDRTS、行变更及批量同步共用校验，并明确持久化明细内容；批量同步也校验并递增版本。有效覆盖保护已同步接入订单写入口，以冻结来源核对数量、产品、单位与客户，拒绝移除、取消、删除、转报价或变为不允许的状态；允许重排行号、修改备注／价格及新增未覆盖行。已有覆盖在订单完成后仍保留。具体职责及测试见[订单行身份与来源关联契约](sales-order-line-stable-identity-edit-reorder-version-and-production-material-source-reference-contract.md)。

MRP 与领料共用独立的 Go 配方展开能力。前端提交来源、用户明确的配方选择和预期依据标识，Go 校验并生成正式数量，不接收客户端汇总数直接过账。发送前用量相关依据变化须明确冲突并重新核对，不能静默换配方、跳过缺失来源。

当前 MRP 按发布状态、生效日期、产品和客户归属筛选候选，多份候选由用户逐订单行明确选择，返回版本和配方行贡献。正式下发领域事务已重新读取真实来源、共用同一配方展开能力，核对订单版本、BOM 版本及完整依据 SHA-256 指纹，并冻结选中 BOM、成品重量与单位、配方贡献和物料显示快照；未采用候选不写入历史。即使旧写入口漏递增版本，数量、重量或配方变化也不能沿用旧核对结果。

下发仅允许未删除、非报价且处于 `Pending`／`Scheduling`／`InProgress` 的订单，要求来源单位、正版本及正成品重量完整；仓库必须为启用且允许出库的系统 `MATERIAL`。核对与下发不读取、预占或扣减库存，包装和库存快照也不成为冻结需求事实。历史查询只读取冻结单据和来源，并校验快照指纹及扁平身份，当前产品、物料或 BOM 改名／修改不会改写原依据；快照损坏明确报错。单位变更、停用等影响后续实际发料的变化，仍须由仓库确认命令再次校验。

## 幂等、覆盖与并发

| 情况                 | 后端必须保证                                                                                               |
| -------------------- | ---------------------------------------------------------------------------------------------------------- |
| 双击、网络超时后重试 | 按操作者＋命令键唯一，同事务保存请求指纹及回执；同键同请求返回原单及其当前状态，同键不同载荷或不同动作拒绝 |
| 再分析、再打印       | 不自动生成新单；重打无业务写入                                                                             |
| 来源集合部分重叠     | 按来源覆盖核对并显示原单，不能仅比较整张单的来源集合指纹                                                   |
| 已领齐               | 仍保持已下发关联，不释放为未下发；补料沿原单                                                               |
| 两人同时确认         | 按固定顺序锁定单据与库存，检查版本和剩余数量，数据库约束防重复事实                                         |
| 撤回                 | 首期仅允许无执行事实的单据整体撤回并释放覆盖，已发料不得简单撤回或删账                                     |
| 超标准或超退         | 普通领料和补料分别校验，补料有原因和差异；退料不超过可核对的可退量                                         |

订单版本变更不能绕过已有覆盖。超时表示结果未知时，按原幂等键查询／重试取回结果，不换键重新提交。库存命令不通过浏览器离线队列盲目重放。已确认错误通过明确冲正或退料同时处理库存，原记录不可直接覆盖或删除。

已实现的下发来源先按订单 ID、真实明细 ID 排序，界面换序不改变幂等载荷；同一操作者的下发与撤回共用命令键空间。有效覆盖以真实明细 ID 为数据库主键，即使不同命令的来源集合部分重叠也不能重复覆盖；原单号为 `PMI-` 加 UUID 派生值，不依赖另一套编号配置。

撤回要求明确单据版本与原因，仅允许 `DISPATCHED` 且无仓库执行标记、无正式交接事实的单据，成功后版本递增并改为 `WITHDRAWN`，完整保留来源快照。释放覆盖后可改订单并重新核对下发；重试原下发命令只返回已经撤回的原单，不会自动建立新单。`warehouseExecutionAt` 由仓库确认领域事务同事务首次写入；标记丢失也不能绕过对实际交接事实的检查。进度由真实分配数量推导，不能以该时间字段冒充已领数量。

PostgreSQL 下发／撤回采用 Serializable 事务；下发按固定顺序锁来源订单并共享锁定配方、物料、产品和仓库，撤回锁定原单据。来源核对与历史查询采用只读一致快照。序列化冲突及死锁返回可识别冲突，调用方应使用原命令键重试，不在领域层盲目重放。失败的业务校验、覆盖冲突或审计写入均整体回滚，不遗留半单和回执。

## 库存、权限与通知

数量以本文“总体物料与订单行进度”为统一契约，[工作区与可复用帮助](../frontend/production-material-issuance-workspace-tab-and-warehouse-confirmed-movement-integration-boundaries.md) 解释同一口径。补料包含于已领；待领与超标准逐订单行计算后分别汇总；库存缺口与包装计算继续复用共用需求服务。待领不等于采购缺口或现场余料；已领不等于消耗。

生产领料已在领域层明确为 `MATERIAL` 移交系统固定 `PRODUCTION_MATERIAL_PENDING_CONSUMPTION`（生产待耗用物料），复用既有 `Inventory` 和 `InventoryLedgerEntry`，不建第二套库存余额。实际交接保留批次、原分配和成本，退料按原发料成本反向移交；不会联动销售已发货数量或销售成本。固定去向、数量容差、旁路保护和后续生产耗用边界见[库存保管移交契约](production-material-issuance-confirmed-warehouse-movements-order-line-allocation-and-custody-inventory-transfer-contract.md)。本轮未执行真实迁移。

库存适配器接受调用者传入的 `tx`，不能自行另开事务；前端不分别调用“扣库存”和“增加已领”两个 API。收发事实关联库存事实身份，查询汇总和缓存不是可独立编辑的另一份正式账。

复用现有账号和角色，读取、下发和撤回采用上文明确的权限与系统共享范围。实际发料、补料和退料确认已由后端校验各自动作及仓库访问，动作互不替代；未来细分数据范围须统一落实到查询和命令。不能按用户名或前端按钮可见性授权。指南阅读权限不授予工作区、订单、库存或确认权限。

通知遵守[消息中心长期契约](workflow/system-notification-inbox-cross-device-synchronization-and-delivery-contract.md)：业务事实、必要收件、投递队列和执行证据同事务写入；提交后推送。实时通道故障不撤销已提交事实，仓库列表仍可查询。复用公共收件和投递机制，补明确来源、可见权限和业务完成后的解除规则，不建第二套通知重试服务。消息不是待发料的唯一数据来源。

## 实施顺序与验收

已接入共用需求、稳定来源、下发／撤回、原单查询及仓库发料／补料／退料界面，沿原单显示分配进度、批次可领量和交接历史。全订单进度已独立接入，后续为正式打印、主动待办及消息；指南明确区分本单领退与总体进度。代码实现和隔离验证不表示真实业务服务已部署或库存验收完成。

2026-10-27 隔离 SQLite 回归覆盖只读核对、下发冻结、来源排序后的幂等、同键异载荷、部分重叠、依据变化、数据库唯一约束、审计失败整体回滚、撤回释放覆盖与保留历史、撤回后改量及旧依据拒绝、跨订单写入口保护和快照损坏报错。原有来源身份及共用需求回归一并验证。测试库无库存表，能够验证下发没有偷偷扣库存；不能据此认定仓库确认已完成。

[读取 HTTP 及授权回归](../../server/routes/production_material_issuance_readonly_source_review_document_queries_and_http_authorization_test.go) 覆盖认证、权限组合、真实来源、严格请求、冻结历史、404／409／损坏快照 500、读取不写业务记录及只读路由组不注册命令。[命令 HTTP 回归](../../server/routes/production_material_issuance_dispatch_withdrawal_http_permissions_identity_idempotency_and_atomic_coverage_test.go) 覆盖独立动作、认证操作者、同键重放、异载荷／覆盖冲突、依据变化无半单、严格请求、撤回版本／原因／执行阻塞、释放覆盖及保留历史。前端新增命令回归覆盖显式核对和范围确认、双击、超时与重挂载沿用原请求、无离线自动重放、跨范围／账号隔离、已撤回原单不冒充新下发及撤回原因与版本。
