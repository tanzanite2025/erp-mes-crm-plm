# 当前审批申请与消息提醒边界

更新日期：2026-11-24。

本文说明审批申请、业务事务与消息提醒之间的当前职责。跨设备收件箱、投递、恢复和保留规则以[消息中心长期契约](system-notification-inbox-cross-device-synchronization-and-delivery-contract.md)为准。

## 审批申请

审批申请是业务审批状态的权威记录。模型位于 `server/models/approval.go`，服务入口位于 `server/services/approval_service.go`，HTTP 路由和处理器分别位于 `server/routes/routes_approval.go` 与 `server/handlers/approval.go`。

业务域在自己的事务中创建申请、关联业务记录并处理审批结果。当前公共审批支持一级和二级审批；条件审批、并行会签及其他复杂规则须先定义明确的业务状态、授权与回写契约，再单独扩展。

## 业务配置与事务

独立审批策略配置由 `business_approval_policy_configuration_service.go` 维护，目前用于品质标准审批。品质标准提审和审批结果回写通过业务事务契约与标准生命周期保持一致。

审批策略只决定审批人和审批步骤。业务状态仍由所属业务域事务维护，策略变更只影响新建申请，不改写已经创建的申请及其办理人快照。

## 消息提醒

消息中心只保存实际收件、展示快照、业务引用和解除条件，并指向真实审批申请或业务事实。阅读、归档和投递恢复不推进业务状态，不创建审批申请。

业务事件在所属事务中生成或解除收件；提交后由共用投递队列刷新客户端。浏览器读取服务端收件和审批状态，不承担业务事件扫描或审批状态写入。
