# 销售订单明细：稳定身份、编辑版本与生产领料来源关联

建立及复核日期：2026-10-27。本文说明已实现的稳定明细身份、保存约束和正式领料有效覆盖保护；核对、冻结历史、下发／撤回 HTTP 与前端已接入，仓库确认已接入 Go 领域事务、HTTP 及独立权限，仓库原单办理界面及独立仓库入口已接入，总体订单进度仍待接入。

## 身份与版本

| 字段                        | 职责                                                   |
| --------------------------- | ------------------------------------------------------ |
| `sales_orders.id`           | 订单实体身份                                           |
| `sales_order_lines.id`      | 已保存明细的真实身份；跨编辑、删其他行及重排保持不变   |
| `sales_order_lines.line_no` | 当前业务行号，只作显示及排序；删行后可重新编号         |
| `sales_orders.version`      | 订单快照并发版本；修改按预期版本校验，成功后由后端递增 |

不增加第二套明细 UUID 或行版本。正式领料来源使用“订单 ID＋明细 ID”，同时保存来源订单版本及业务行号快照。不能把订单号拼行号、数组下标或产品 ID 当作长期来源身份；同一产品可以出现多条不同订单行。

普通保存、SDRTS PATCH、增行、删行、多行变更和现有批量同步共用身份校验。已有明细必须提交其真实 ID；未保存行省略 ID（Go 中为零），由数据库生成新 ID。保留的行不能被后端按新行号重新赋予旧行 ID。请求中的行号必须为互不重复的正整数，同一个已保存 ID 不能出现两次。

例：原第 1 行 ID=101、第 2 行 ID=102。删除第 1 行后，原第 2 行变为行号 1，ID 仍是 102；随后新增的行号 2 获得新的 ID，不能占用 101 或 102。复制成新行时须移除保存身份，不能沿用原 ID。

跨订单 ID、不存在的 ID、已从订单移除的 ID 一律拒绝，禁止偷偷改为新建或按行号匹配。新建订单不能携带任何已保存明细 ID。前端 API DTO 校验正整数身份和行号；前端增删及预览重排保留存量 ID，差量金额基线也按 ID 匹配。

## 保存与执行事实

独立实现文件为 `server/services/sales_order_line_stable_identity_validation_and_persistence.go`，负责身份及归属校验、请求映射和明细持久化。事务入口继续负责订单行锁、预期版本、权威汇总、状态推导和审计，不在帮助组件或前端建立正式身份账。

订单主单更新显式排除 `Lines`，避免 GORM 在主单更新阶段自动写入关联。明细随后按已校验的 ID 更新，新增行单独创建；数量、价格、空备注及零值均明确写入，不依赖默认关联 upsert。单据和明细处于同一事务，后续失败整体回滚。

普通编辑不写回已发货数量、认领人与时间、执行状态，既不能接收客户端伪造值，也不能用旧表单覆盖保存期间更新的执行事实。认领命令只写认领字段，发货和状态推导继续由原领域命令负责。它们不代表生产物料领料事实。

没有有效覆盖的移除行沿用此前关联替换的保留方式：保留原数据库记录，解除当前订单关联；禁止再通过普通保存把该 ID 挂回当前订单或其他订单。已有有效生产领料覆盖的行不能移除，见下节。

已有批量 `/sales-orders/sync` 入口也校验同一身份及预期版本，现有订单版本不匹配时返回 409；不再接受客户端版本直接覆盖或缺版本时自动使用当前版本。每次成功同步由后端递增版本，数量金额重新计算。批量失败整体回滚。此处未增加离线重放、幂等回执或新的同步协议；普通编辑继续使用 SDRTS，正式领料不能借该入口写入。

## 与 MRP、正式领料的边界

MRP 返回真实订单／明细 ID、订单版本以及 BOM／配方贡献，仍是多次读取的分析参考。现有分析范围的订单号与行号选择键只用于当次查询；正式下发必须提交并重核分析结果里的真实来源身份及预期依据，不能重新使用显示行号寻找“看起来相同”的行。

正式下发领域层、来源覆盖表、冻结配方及订单写入口保护已建立。只读 HTTP 核对真实订单／行／BOM，历史详情只读冻结身份，不按当前行号重找来源；该读取不建立覆盖或修改订单。专用下发／撤回 HTTP 复用领域事务，分别检查业务访问、查看及对应命令动作权限，身份来自认证上下文；仓库确认由[独立 HTTP 与领退动作权限](production-material-issuance-warehouse-http-review-allocation-suggestions-confirmation-permissions-and-error-contract.md)承接，原单办理界面及独立仓库入口已接入，总体订单进度仍待接入。当前领域约束为：

1. 发送事务重新锁定并读取真实订单及明细，校验版本、产品、客户归属、数量、明确 BOM 选择及配方依据。
2. 冻结来源身份、数量、当时行号、订单版本和配方版本，建立有效覆盖约束，不以查询时的当前配方覆盖历史。
3. 已有效覆盖的来源不得被普通订单编辑、删行、换产品、批量同步或订单删除悄悄替换；需保持原覆盖，或走明确的变更／撤回流程。保护要同时接入所有写入口，不能只隐藏前端按钮。
4. 来源删除、订单取消和 BOM 变化后，历史下发及领退仍可按冻结身份追溯。退料不能按当前行号回冲另一条行。

独立 [有效覆盖保护服务](../../server/services/production_material_issuance_active_coverage_order_mutation_guard.go) 在调用方持有订单锁的事务内读取真实覆盖及冻结来源；覆盖断裂明确报错。保护已接入普通保存、SDRTS、明细增删改、客户／分类／状态变更、取消、删除及批量同步；既不只隐藏按钮，也不只比较可能已经错误变化的当前旧值。现有订单 HTTP 入口以 409 和 `PRODUCTION_MATERIAL_SOURCE_PROTECTED` 返回该冲突。

已覆盖行禁止改数量、产品、成品单位、客户归属及移除；订单不得取消、删除、转为报价或变为不允许的状态。允许重排行号、修改备注／价格、新增未覆盖行和正常完成，单据仍按真实 ID 关联原覆盖。订单完成、消息已读或打印不释放覆盖。尚无仓库执行的整单可通过带原因及版本的撤回释放覆盖，之后修改订单需要重新核对；原快照始终保留。

下发事务复用共用配方展开，重核来源版本、BOM 版本及完整依据指纹，同事务保存单据、冻结来源、有效覆盖、幂等回执和审计。数据库以真实明细 ID 为有效覆盖主键，避免部分重叠时重复下发。下发和撤回已接入界面，但不表示领料进度或库存过账已启用。全部模型已注册迁移，本阶段未对业务库执行迁移。总体流程及职责见[生产领料契约](production-material-issuance-dispatch-warehouse-confirmation-and-inventory-posting-contract.md)。

## 验证范围

独立 Go 回归使用内存 SQLite，覆盖编辑、删除后补行、重排、零值更新、身份与行号重复、跨订单／已移除 ID、新建订单冒用 ID、版本冲突、审计失败回滚、批量同步、包装随身份保留，以及普通编辑不覆盖执行事实。前端测试覆盖真实增删 Hook、预览重排、API 适配和提交差量的 ID 传递。

新增领料隔离回归覆盖各订单写入口的来源保护、数据库防重复、撤回后允许改量且不改历史，以及备注／重排／未覆盖新增仍可保存。PostgreSQL 并发测试已提供专用测试 DSN 入口，当前环境未配置而明确跳过。这些验证不涉及真实业务数据，也不代替 PostgreSQL 下的实际锁、迁移和仓库库存过账验收。
