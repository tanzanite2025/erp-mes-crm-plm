# 模具分组主档、稳定引用与历史组名迁移

更新：2026-10-29。本文描述本次实现的分组主数据契约。

## 归属与数据关系

分组由设备工装模块统一维护，独立存储在 `mold_groups`，不再通过模具名称字段汇总生成。空分组可以独立建立和选用。模具通过 `molds.group_id`、产品通过 `products.mold_group_id` 引用分组 ID；一副模具属于至多一个分组，一个产品关联至多一个分组。未分组资产、未绑定产品的引用为空。

分组拥有名称、说明、启用状态、并发版本和审计信息。名称去除两端空白，不能为空，最多 100 个字符；名称精确唯一，说明最多 2000 个字符。删除采用软删除，已删除名称保留，防止历史名称被重新用于其他身份。

`groupName` 和产品 `moldGroup` 保留为显示及旧客户端兼容字段，不作为新界面的关联键。分组改名在同一事务内同步这两列，关联 ID 不变。模具调整所属分组只影响该副模具，不会替产品调整分组。

## 管理和选用

- 模具管理提供“分组管理”，可独立新增、编辑、停用、启用及删除分组，并展示现存模具、产品引用数量。
- 模具资产中的所属分组使用统一目录选择器，支持就地新建分组、打开管理界面和读取失败重试。
- 产品字段使用相同目录，以 ID 选用、查看组内模具、清除关联；空组明确显示暂无模具，停用组保留显示并禁止新选用。
- 新建分组立即入主档，取消模具或产品草稿不会删除该分组。确认分组只改变产品草稿，保存产品才持久化关联。
- 新建模具、分组改名或启停后，统一刷新分组目录、模具目录和产品查询，避免旧名称留在其他入口。

## 后端约束

`GET /mold-groups` 返回完整目录及引用计数；`POST /mold-groups` 新建；`PUT /mold-groups/:id` 携带版本更新；`DELETE /mold-groups/:id?version=…` 携带版本删除。读写权限沿用设备工装读取权限和 `action_equipment_mold_manage`，分组写入以 `mold-group` 实体记录审计。

分组更新、删除与模具／产品关联写入共享事务锁，防止检查后并发新增引用。重复名称、过期版本、无效或不存在的分组均拒绝写入。停用后允许既有记录保持原关联并修改其他字段，禁止新记录或其他记录新增关联。删除检查包含软删除的模具和产品；存在任何引用时只能停用，不能删除。

模具全量保存、PATCH、批量恢复和产品创建、全量更新、PATCH 均经过同一引用解析。旧客户端若只传组名，只能解析已有分组，不能借保存模具或产品隐式创建分组；新客户端写 ID，服务端采用主档当前名称。清空 ID 同时清空显示字段。数据库外键以 `RESTRICT` 防止物理删除破坏引用。审计失败时，分组变更和显示字段同步一起回滚。

## 历史数据迁移

服务端完成表结构迁移后，在单一事务内执行 `BackfillMoldGroupMasterIdentities`：

1. 从模具与产品中读取尚无分组 ID 的非空历史组名，包含软删除记录。
2. 去除组名两端空白，按精确名称建立或复用主档，并回填 ID 及规范名称。
3. 仅出现在产品中的历史组名也保留为空分组，不丢弃原绑定。
4. 添加模具及产品到分组主档的数据库外键。

迁移可重复执行；已经回填的记录不会重建分组。空白组名保持未分组；相似但不同的名称不会自动猜测合并。迁移失败终止服务启动，事务整体回滚。上线需先更新并启动后端，再更新前端；迁移新增表和 ID 列，原名称列保留。
