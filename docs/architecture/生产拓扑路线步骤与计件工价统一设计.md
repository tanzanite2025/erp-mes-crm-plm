# 生产拓扑、路线步骤与计件工价统一设计

> 文档状态：架构基准与实现对齐说明  
> 确认日期：2026-08-13  
> 适用范围：生产架构、生产路线、作业项目、工序执行、计件工价、报工结算  
> 关联代码：`server/models/production_process.go`、`server/models/production_topology.go`、`server/models/production_route.go`、`server/models/piecework_rate.go`、`server/models/piecework_record.go`

## 1. 结论先行

生产拓扑、产品工艺路线和计件工价必须分别按稳定身份建模。最终采用以下关系：

```text
生产架构
└─ ProductionLine 产线
   └─ LineSegment 工段
      └─ ProcessStep 作业项目 / 标准工序（计件叶子）

产品路线
└─ ProductionRoute 工艺路线
   └─ ProductionRouteStep 产品在某一工段执行某一作业项目的路线步骤

计件管理
   └─ PieceworkRate 产品在某一作业项目上的计件工价
```

核心规则：工段管生产归属，作业项目管具体工作，工艺路线管产品如何经过这些作业，计件工价管作业如何计薪。

计件粒度的硬规则：

> `LineSegment` 工段从来不是计件对象。计件必须落在工段下被路线选中的 `ProcessStep` / `ProductionRouteStep` 叶子作业上。

工段在业务界面上可以表现为两种形态，但底层合同保持一致：

| 工段形态 | 业务示例 | 底层表达 | 计件对象 |
|---|---|---|---|
| 单作业工段 | 成型下面不再细分 | 工段映射一个同名或等价的 `ProcessStep`，界面可扁平显示为“成型” | 该唯一作业项目/路线步骤 |
| 多作业工段 | 卷料下面有外圈、内圈 | 工段映射多个 `ProcessStep`，界面展示下级作业 | 外圈、内圈等具体作业项目/路线步骤 |

因此，“成型没有下级”只是一种界面和业务表达，不代表数据库可以直接拿 `segmentId` 计价。底层仍需要一个可引用、可报工、可冻结历史的叶子作业身份。

## 2. G24 业务示例

以产品 G24 为例，推荐配置如下：

```text
产品：G24

工艺路线：G24-ROUTE-V1
├─ 01 备料
│  └─ 唯一作业项目：备料（界面可扁平显示）
├─ 02 卷料
│  ├─ 作业项目：G24 外圈
│  └─ 作业项目：G24 内圈
├─ 03 成型
│  └─ 唯一作业项目：成型（界面可扁平显示）
├─ 04 机加
│  └─ 唯一作业项目或实际细分作业
├─ 05 精细
│  └─ 唯一作业项目或实际细分作业
├─ 06 涂装
│  └─ 唯一作业项目或实际细分作业
└─ 07 包装
   └─ 唯一作业项目：包装（界面可扁平显示）

计件工价
├─ G24 + G24 外圈 + PCS = 计件单价
├─ G24 + G24 内圈 + PCS = 计件单价
└─ G24 + 成型作业 + PCS = 计件单价（如果成型采用计件）
```

同样，“卷料”只是工段，不允许配置一个覆盖外圈、内圈的混合工价。外圈和内圈必须分别计价。成型如果没有业务细分，则通过唯一的“成型”作业项目计价；这不等于按成型工段计价。

## 3. 当前仓库的真实模型

### 3.1 生产工段与作业项目

当前生产模型的准确关系是：

```text
ProductionLine
└─ LineSegment
   └─ line_segment_process_mappings
      └─ ProcessStep
```

对应代码：

| 对象 | 文件 | 当前含义 |
|---|---|---|
| `ProductionLine` | `server/models/production_topology.go` | 产线或生产结构的 L1 |
| `LineSegment` | `server/models/production_topology.go` | 产线下的工段，L2 |
| `ProcessStep` | `server/models/production_process.go` | 全局可复用的作业项目或标准工序，通过映射成为某工段可执行的 L3 |
| `ProductionRoute` | `server/models/production_route.go` | 产品或产品模板适用的工艺路线 |
| `ProductionRouteStep` | `server/models/production_route.go` | 路线中的一个产品工艺步骤，引用 `segmentId + processStepId` |

`ProcessStep` 当前不是被某个 `LineSegment` 单独拥有的子表，而是全局标准作业库。`LineSegment.Processes` 通过 `line_segment_process_mappings` 建立可执行范围，一个作业项目可以被多个工段复用。前端脑图可以把映射结果投影为“工段下级”，但删除、改名和引用保护必须按共享主数据处理。

生产路线引用生产拓扑中的工段和作业项目，只保存产品实际需要执行的顺序、执行方式、质检关卡、耗时和转移要求。发布路线的每个步骤都必须选中一个 `processStepId`；不能只选工段。

### 3.2 计件工价与计件记录

当前后端模型是：

| 对象 | 文件 | 当前含义 |
|---|---|---|
| `PieceworkRate` | `server/models/piecework_rate.go` | 产品 + 工序编码维度的计件工价 |
| `PieceworkRecord` | `server/models/piecework_record.go` | 报工后的计件记录，保存当日工价快照和金额 |
| `Team` | `server/models/team.go` | 生产班组或计件核算组织 |

当前 `PieceworkRate` 的后端字段为 `productId`、`processCode`、`processName`、`unitPrice`、`effectiveAt`、`status`。`PieceworkRecord` 当前记录员工、班组、产品、`processCode`、数量、工价快照和金额。

## 4. 术语统一

| 业务术语 | 推荐代码语义 | 说明 |
|---|---|---|
| 工段 | `LineSegment` | 生产结构中的归属层级 |
| 作业项目 | `ProcessStep` 或产品路线中的 `ProductionRouteStep` | 具体执行内容，可作为报工和计件对象 |
| 单作业工段 | 一个 `LineSegment` 只映射一个有效 `ProcessStep` | 界面可不重复展开同名下级，但保存和计件仍引用该作业 ID |
| 多作业工段 | 一个 `LineSegment` 映射多个有效 `ProcessStep` | 必须选择具体下级作业，不能直接选择工段计件 |
| 标准工序 | `ProcessStep` | 可在多个产品路线中复用的作业定义 |
| 产品工艺步骤 | `ProductionRouteStep` | 某产品路线中对标准工序的一次具体应用 |
| 工艺路线 | `ProductionRoute` | 产品执行顺序和过程约束 |
| 计件工价 | `PieceworkRate` | 作业项目的计件价格规则 |
| 计件报工 | `PieceworkRecord` | 实际数量、操作人、工价快照和结算金额 |

兼容策略：

1. 生产架构页面中的 `LineSegment` 才使用“工段”。
2. 计件页面不应继续把自由文本“末级层级名称”当作唯一业务身份，应逐步改为选择作业项目 ID。
3. 工段名称可用于筛选和展示，但 `segmentId` 不得成为工价规则的匹配键。

## 5. 推荐的领域关系

### 5.1 当前可落地关系

```text
Product
└─ ProductionRoute
   └─ ProductionRouteStep
      ├─ LineSegment
      └─ ProcessStep

PieceworkRate
├─ Product
└─ ProcessStep（当前通过 processCode / processName 间接关联，不允许关联 LineSegment 计价）

PieceworkRecord
├─ Employee
├─ Team
├─ Product
└─ ProcessStep（当前通过 processCode 记录）
```

### 5.2 目标关系

产品、工艺和计件应按 ID 关联，名称只用于展示：

```text
Product
├─ ProductionRouteVersion
│  └─ ProductionRouteStep
│     ├─ segmentId
│     └─ processStepId
└─ PieceworkRate
   ├─ productId
   ├─ routeStepId（优先，产品路线精确定位）
   ├─ processStepId（通用作业项目）
   ├─ effectiveFrom / effectiveTo
   └─ unitPrice
```

`routeStepId` 和 `processStepId` 的使用建议：

- `PieceworkRate` 必须至少定位到一个叶子作业，不允许只保存 `segmentId`；
- 如果同一个作业项目在同一产品路线中只出现一次，`processStepId` 可以作为通用匹配键；
- 如果同一个作业项目在一条路线中重复出现，或不同路线对同一个作业项目有不同工价，必须使用 `routeStepId`；
- 工价计算时优先按 `routeStepId` 匹配，再按 `productId + processStepId`，最后才允许使用受控的默认工价；
- 工价匹配不得回退到 `productId + segmentId` 或工段名称；
- 不允许以 `processName` 或 `segmentName` 作为数据库连接键。

## 6. 产品路线和计件配置

### 6.1 推荐配置流程

```text
1. 生产维护产线拓扑
   ├─ 维护产线和工段
   ├─ 维护标准作业项目库
   └─ 将作业项目动态绑定到可执行的工段

2. 为产品配置工艺路线
   └─ 选择工段
   └─ 从该工段已绑定的作业项目中选择具体叶子作业
   └─ 设置顺序、执行方式、质检和耗时

3. 配置产品作业项目的计件工价
   └─ 产品 + 路线步骤/作业项目 + 单位 + 生效时间 + 单价

4. 现场报工
   └─ 扫码或执行记录
   └─ 报工必须定位到路线步骤/作业项目，不能只定位到工段
   └─ 生成 PieceworkRecord
   └─ 固化工价快照
```

工段和作业项目采用动态绑定，不在 `ProcessStep` 上保存唯一 `segmentId`：

```text
LineSegment（工段）
    ↕ line_segment_process_mappings
ProcessStep（标准作业项目）
```

这样配置有三个好处：

1. 成型工段当前可以只绑定一个“成型作业”，后续需要细分时再动态增加“预成型”“终成型”等作业；
2. 卷料工段可以同时绑定“外圈卷制”“内圈卷制”等多个作业，并分别计件；
3. 同一个标准作业确实可跨工段复用时，不需要复制主数据；产品差异仍由 `ProductionRouteStep` 表达。

页面交互规则：

- 工段只有一个有效作业时，可以默认选中或扁平展示，但提交值仍是 `processStepId`；
- 工段有多个有效作业时，必须让用户明确选择一个具体作业；
- 工段没有有效作业时，不允许发布包含该工段的产品路线；
- 工价配置页面只提供作业项目/路线步骤选择器，不提供“按工段计价”入口。

### 6.2 G24 外圈的推荐身份

当前系统可以先使用：

```text
ProcessStep.code = G24-OUTER-RING
ProcessStep.name = G24 外圈
PieceworkRate.productId = G24
PieceworkRate.processCode = G24-OUTER-RING
```

但长期更推荐：

```text
ProcessStep.code = ROLL-OUTER-RING
ProcessStep.name = 外圈卷制
ProductionRouteStep.routeId = G24-ROUTE-V1
ProductionRouteStep.processStepId = ROLL-OUTER-RING
ProductionRouteStep.displayName = G24 外圈
PieceworkRate.routeStepId = G24-ROUTE-V1 / 对应步骤
```

原因是“外圈卷制”可能被多个产品复用，而“G24 外圈”是产品路线中的具体展示名称。标准工序应尽量保持可复用，产品差异应放在路线步骤或作业参数中。

如果当前阶段不增加 `ProductionRouteStep.displayName`，可以暂时保留产品名编码的 `ProcessStep`，但必须在文档和代码中明确这是过渡方案，不应继续扩散。

## 7. 版本、生效和历史冻结

两类版本必须独立：

| 领域 | 当前版本机制 | 业务规则 |
|---|---|---|
| 工艺路线 | 当前 `ProductionRoute.version` 是同一记录的乐观锁版本；`status` 有 `DRAFT/PUBLISHED/ARCHIVED` | 基础生命周期已保护发布路线不可原地修改和删除；路线家族、业务修订号和复制修订流程仍待实现 |
| 工价 | 已有 `processStepId`、可选 `routeStepId`、`effectiveFrom/effectiveTo`、`version` 和区间重叠校验 | `effectiveAt`、`piecePrice` 仅作兼容读取投影；真实 PostgreSQL 迁移验收和历史问题清理仍待完成，报工快照服务已建立 |

推荐的生产单据冻结策略：

```text
生产计划/工单下达
├─ 冻结已发布工艺路线
└─ 记录当时有效的计件工价版本或规则 ID
```

历史计件记录至少应保存：

```text
productId
routeId
routeStepId
processStepId
quantity
unit
unitPriceSnapshot
totalAmount
workDate
employeeId / teamId
sourceExecutionId
```

工价调整只影响新报工，不追溯修改已经生成或已经结算的 `PieceworkRecord`。

## 8. 当前实现分歧与文档纠正

当前代码需要后续对齐的地方：

| 分歧 | 当前代码 | 影响 |
|---|---|---|
| 启动迁移破坏路线步骤 | 已由 PR0 修复：`InitDB()` 常规启动路径不再调用破坏性拓扑清理，且有 `server/db/production_topology_migration_guard_test.go` 守卫 | 仍需在真实数据库中核对历史孤儿 `routeStepId`，但不能再描述为“每次启动都会删除路线步骤表” |
| 发布路线原地变更 | 已由 PR2 基础生命周期保护修复：`DRAFT` 可编辑，`PUBLISHED` 只能原样归档，`ARCHIVED` 只读；路线删除会检查状态和下游事实 | “复制为新路线修订”、路线家族 ID 和独立业务修订号仍未实现，当前 `version` 仍是行版本用途 |
| 生产主数据删除缺少业务保护 | `DeleteProcessStep`、`DeleteProductionLine` 当前仍主要进入仓储删除，尚未覆盖完整的发布路线和执行事实检查 | 共享作业、工段或产线的停用/删除保护仍需独立 PR；不能把 PR2 的路线删除保护扩大解释为全域主数据保护 |
| 计件前端字段 | 页面仍可读取 `processName`、`piecePrice`、`effectiveAt` | 通过 API adapter 转成 canonical `processStepId`、`unitPrice`、`effectiveFrom`；写入不再发送旧展示字段 |
| 计件身份 | 后端核心保存和 resolver 使用稳定 ID | 旧 `processCode` 只在兼容边界解析或作为展示快照，不能作为核心匹配键 |
| 计件写入接口 | 已对齐 GET、POST、PATCH、DELETE | PATCH 使用 SDRTS `o/n` 和版本元数据，删除要求版本号 |
| 工价规则数据库约束 | 服务层已做生效区间重叠校验，迁移已准备 PostgreSQL 排他约束 | 历史数据未清理前不启用最终非空和排他约束，需完成真实数据库验收 |
| 计件记录来源 | `PieceworkRecordService` 已按路线步骤/作业解析工价并冻结快照，生产/扫码完工入口已接入 | 后续新增报工或结算入口必须复用该服务；缺工价只形成计件配置缺口，不阻断生产完工事实 |
| 产品路线步骤名称 | `ProductionRouteStep` 当前主要展示关联 `ProcessStep.name` | 产品专属作业名称需要后续增加路线步骤展示名或作业参数 |

以上表格区分了已修复问题和仍待实现的缺口。

本文件只维护稳定的业务模型和领域规则。实施进度、文件路径和迁移步骤不得反向改变以下核心原则：

- 工段与标准作业采用动态绑定；
- 工段不是计件对象；
- 路线步骤选择具体作业；
- 计件按 `processStepId` 或 `routeStepId` 匹配；

## 10. 验收原则

1. 工段可以动态绑定一个或多个作业项目。
2. 成型工段只绑定一个“成型作业”时，页面可扁平显示，但报工和计件仍保存该作业 ID。
3. 卷料工段绑定外圈、内圈等多个作业时，必须按具体下级作业分别配置工价。
4. 系统不存在只按 `segmentId` 或工段名称匹配的计件规则。
5. 同一作业项目可以被多个工段映射和多个产品路线复用。
6. 同一作业项目在不同产品或路线中可以使用不同计件工价。
7. 工价改价不会修改历史计件记录。
8. 路线步骤重复使用同一 `ProcessStep` 时，工价仍能通过 `routeStepId` 精确匹配。
9. 产品 G24 的“G24 外圈”可以被报工和计件，并且使用稳定的作业/路线步骤身份。
10. 连续重启服务不会删除或重建已有路线步骤 ID。
11. 发布路线修订后，历史报工和委外记录仍能解析原路线步骤。
12. 所有跨域关联使用稳定 ID，展示名称只用于显示和搜索。
