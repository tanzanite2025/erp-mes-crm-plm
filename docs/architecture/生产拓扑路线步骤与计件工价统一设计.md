# 生产拓扑、路线步骤与独立工资计算边界

更新日期：2026-10-15。原文将生产作业、路线、报工及工资结算串联为一条链路，该设计错误，已撤销。财务只使用已有人员、部门和独立环节工价录入数量、计算工资，不需要生产报工、审核或收付流程。

工资唯一实施契约见 [`独立计件工资模块契约与实现边界.md`](独立计件工资模块契约与实现边界.md)。本文只保留生产模型说明及双方边界，不保留已撤销的产品路线工价配置建议。

## 1. 生产模型

```text
ProductionLine 产线
  -> LineSegment 工段
    -> line_segment_process_mappings
      -> ProcessStep 标准作业

Product 产品
  -> ProductionRoute 路线
    -> ProductionRouteStep 路线步骤
      -> segmentId + processStepId
```

`ProcessStep` 是全局标准作业，通过映射绑定到工段，并非由某个工段唯一拥有。同一标准作业可以被多个工段复用。产品路线保存顺序、执行方式、质检和交接要求，每个发布步骤引用具体作业 ID。

单作业工段可以在界面扁平展示，多作业工段需要选择具体下级作业；这些只是生产配置，与工资工价无关。

| 对象 | 文件 | 含义 |
|---|---|---|
| 产线与工段 | `server/models/production_topology.go` | 生产结构 |
| 标准作业 | `server/models/production_process.go` | 可复用生产作业 |
| 路线与步骤 | `server/models/production_route.go` | 产品执行顺序及约束 |
| 生产执行 | `server/models/production_execution.go` | 生产动作、请求回执及轮次 |

## 2. 工资模型

```text
既有人员和部门 + 独立工资环节与工价 + 财务输入数量
  -> 工资计算明细
  -> 人员、部门汇总（分币种）
```

`PieceworkPayItem` 表示独立工资环节，`PieceworkRate` 表示该环节按单位和生效日期维护的工价。计算直接读取既有人事主数据，不能引用 `ProcessStep`、`ProductionRouteStep`、产品、条码、批次、BOM 或用料分配。

不再使用 `PieceworkRecord` 模型，没有报工提交、待计价补录、结算审核、收付登记或金额调整。录错后修改输入、重新计算；无生效工价时直接报错。计算不会写入业务事实。

工价只使用 `payItemId`、`unitPrice`、`currency`、`effectiveFrom/effectiveTo`、状态和行版本，旧字段与别名不兼容。工价区间与版本属于工资维护，生产路线版本属于生产，两者不关联。

## 3. 已有生产保护与后续生产事项

常规启动不再调用破坏性拓扑清理。路线已有 `DRAFT/PUBLISHED/ARCHIVED` 生命周期保护，发布路线不能原地修改或删除，归档保留步骤身份。路线家族、独立业务修订号与复制修订尚未实现。

生产 HTTP 执行和扫码要求自己的 `idempotencyKey`，回执与生产副作用同事务提交。同条码操作串行化，完工按条码、路线步骤、作业与轮次唯一；返工开启下一生产轮次。生产轮次不生成工资，生产请求不携带工资归属字段。

生产仍需独立处理批次与条码错配、被执行引用的草稿步骤修改保护、共享作业/工段/产线完整停用与删除保护。这些不是工资计算的前置条件。

## 4. 迁移与验证边界

生产回执和轮次迁移只处理生产表。工资迁移只维护独立环节和工价，不创建、迁移或推导工资报工及收付记录。业务库尚未执行本轮应用迁移。

工资应能在没有生产表时完成财务录入与计算；生产应能在没有工资表和员工工资绑定时完成执行及扫码。这两项边界分别由测试验证，不能再恢复生产自动计件 hook。
