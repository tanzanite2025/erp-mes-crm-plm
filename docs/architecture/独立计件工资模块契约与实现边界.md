# 独立计件工资模块契约与实现边界

确认日期：2026-10-15。以用户最新明确的范围为准：财务使用已有人员、部门和独立环节工价，录入数量，计算工资。此前增加的工资报工、待计价、结算审核、收付登记、金额调整及班组分配均不属于本需求，相关实现已撤除。

## 1. 唯一业务链路

```text
财务选择已有人员、部门、工资环节，填写数量
                 + 独立环节工价
                 = 工资明细及人员、部门汇总
```

人员与部门来自既有组织人员主数据，复用 `employees`、`employee_assignments`、`org_units`。人员默认部门沿用既有主要任职，财务可以从已有部门中选择本次计算部门。工资模块不再建立一套人员、部门或班组归属模型。

工资环节与工价由工资模块独立维护，使用 `PieceworkPayItem` 与 `PieceworkRate`。环节不引用生产作业、工段或路线步骤，也不需要产品、条码、生产批次、生产执行、BOM 或用料分配。

计算不创建报工、待办、工资单据、结算批次、付款记录或调整记录，不要求审核、请求幂等键、作废或冲正。输入有误直接修改后重新计算。

## 2. 输入与输出

`POST /piecework/calculate` 只接收：

```json
{
  "calculationDate": "2026-10-15",
  "rows": [
    {"employeeId": "人员 UUID", "departmentId": "部门 UUID", "payItemId": "环节 UUID", "quantity": 3}
  ]
}
```

计算日期只用于选择生效工价，不是生产日期或报工日期。每次计算 1 至 500 行，人员、部门和环节必须存在；人员或部门不自动新建。HTTP 拒绝未知字段，旧字段不兼容。

每行返回人员、部门、环节、数量、单位、单价、币种及整数分金额。数量范围 `0..99999999.9999`，数量和单价最多四位小数；金额使用十进制精确乘法，最后一次 half-up 舍入到分。单行金额上限 `9999999999.99`，超限报错。

前端显示逐行结果，支持按人员或部门汇总；不同币种分别汇总，整数分累加。修改人员、部门、环节、数量、日期或行数后立即清除旧结果，重新点击计算即可，不需要新增业务凭证。

无生效工价时明确报错，修正环节工价或计算日期后重算，不生成待计价队列。任一行失败则整次计算不返回部分结果。

## 3. 工价维护

工价使用 `payItemId`、单位、单价、币种、`effectiveFrom/effectiveTo`、状态与版本。区间为 `[effectiveFrom, effectiveTo)`；同环节、同单位的有效工价不允许重叠。更新和删除检查行版本，工价维护保留事务审计。

工资环节的新建和编辑只要求业务名称、单位、启用状态及可选备注，前端不提交环节编码。新建时由后端生成唯一内部编码，编辑时自动保留已有编码；已有环节、工价关联不需要迁移。环节和工价列表不展示内部编码或并发版本，环节选择使用名称和单位，版本继续由系统随更新请求携带。

工价弹窗通过既有 `GET /finance/currencies` 只读获取系统币种选项，只使用代码、名称和启用状态。新建工价选择系统启用币种，不手工输入或写死默认币种；编辑时保留系统中已有的当前币种显示。工价仍只保存币种代码，不建立币种外键，不使用汇率、基准币种或金额精度，也不调用币种维护、同步、结算或收付接口。工资计算与不同币种分别汇总的契约不变。

不保留 `piecePrice/effectiveAt`、生产身份或读取别名。存量旧工价必须显式转换为独立环节事实后才能执行工价迁移；不按生产数据猜测映射。

迁移只维护环节、工价两张表和工价约束，不创建或迁移工资报工、结算、收付、调整、命令回执。历史业务表不由本次代码自动删除，业务库尚未执行应用迁移。

## 4. 接口与页面

- `GET /piecework/calculation-options`：读取已有人员、部门的最小选项，不返回身份证、银行卡等人员敏感字段。
- `POST /piecework/calculate`：只读计算，不写业务记录或审计事实。
- `GET/POST /piecework/pay-items`：维护独立工资环节。
- `/piecework/rates` 的 GET/POST/PATCH/DELETE：维护环节工价。

工资计算需要 `menu_piecework`，不要求财务拥有人员主数据维护权限。环节、工价维护沿用 `perm_manage`。工资页主入口 `/piecework/query`，提供录入、计算及人员/部门汇总；保留既有表格模板入口。班组管理不参与工资计算，工资导航不再暴露班组入口。

## 5. 验证边界

计算测试覆盖既有人事主要任职的部门选项、数量修改后直接重算、四位小数乘法和分舍入、零数量、缺价、无效人员/部门、超范围及整次失败不返回部分金额；通过数据库写入回调确认计算不创建、修改或删除业务事实。生产隔离回归保留，但生产问题不再作为工资前置任务。

此前结算与收付的测试、截图及完成声明属于已撤回实现，不能用于证明当前计算契约。当前代码的验收应围绕财务录入和计算重新执行。

当前 `go test ./services ./handlers ./routes ./db`、前端六文件 28 个测试、TypeScript、受影响文件 ESLint 和中英文结构校验均通过。临时 PostgreSQL 的只读事务已验证既有人员部门和独立工价可以直接计算，未建立生产或报工表。
