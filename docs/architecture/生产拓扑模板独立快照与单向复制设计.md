# 生产拓扑模板独立快照与单向复制设计

## 1. 目标与边界

生产拓扑模板用于复用已经建立好的脑图分支组合。L1 仍读取产品侧 `ProductTemplate`，L2 仍关联有效生产 MBOM 分支，L3 仍归属于稳定 MBOM 分支。生产拓扑模板是独立对象，不替代这三层的业务身份。

本次实现两次单向复制：实际 L1 → 新拓扑模板；拓扑模板 → 新实际 L1。模板编辑、删除以及来源 L1 的后续编辑、删除，都不会传播到对方。已有实际 L1 不提供模板覆盖、订阅或自动同步入口。重复应用模板创建不同的 L1 和 L2 ID。

## 2. 独立快照

模板存放在服务端独立的 `production_topology_templates` 表，具有独立 UUID、版本、名称、说明、时间戳和 JSON 内容快照。模板不保存实际 L1/L2/L3 的 ID，不建立指向来源 L1 或被创建 L1 的外键和 ORM 关联。来源 L1 编码仅作为快照说明。

快照内容包括产品侧模板 ID/名称、L1 说明、各 L2 的稳定 MBOM 分支身份、型号/名称参考、说明、属性和顺序，以及 L3 名称、说明、启用状态和顺序的参考快照。产品模板 ID 和 MBOM 稳定身份用于应用时重新校验主数据；快照显示字段不会冒充当前主数据。

L3 参考快照只用于查看与比对。当前一个分支的 L3 被该分支的所有脑图关联共享，因此应用模板不得用参考快照创建、覆盖、停用或删除真实分支工序。新 L1 的 L3 从所选分支当前维护的工序读取。模板也不生成、修改或发布生产路线、计划及执行事实。

模板保存接口同样执行只读约束：按稳定 MBOM 分支身份匹配已有分支，型号、名称与 L3 参考快照沿用模板原值，不能由客户端改写，也不随实际工序后续修改而刷新。新增分支必须由服务端重新校验为当前有效 MBOM 分支，并读取当时的型号、名称与 L3 作为初始参考快照；客户端提供的参考内容不生效。分支说明、属性及顺序仍可编辑。已有失效分支允许继续查看、编辑说明或移除；不能借新增分支绕过有效性校验。

原浏览器本地模板结构不满足现有 MBOM 分支契约，本次不提供兼容读取或自动导入。模板清单以服务端为准，读取失败显示错误，不能伪装为空清单。

## 3. 操作与事务

| 操作 | 行为与校验 |
| --- | --- |
| 从实际 L1 生成模板 | 选择来源 L1，提交看到的 L1 版本；事务内锁定来源 L1、检查版本、读取当前分支工序并序列化为独立快照，只新增模板与审计。 |
| 查看/编辑模板 | 编辑名称、说明、L2 分支组合、顺序及分支说明；L3 参考快照只读。编辑草稿深拷贝，取消或保存失败保留原模板和实际结构。 |
| 保存模板 | 锁定模板并检查版本，拒绝重复/非法分支身份；保留已有分支只读参考值，新增分支重新校验并读取真实快照，递增模板版本并写审计；不写生产实际表。 |
| 应用模板 | 明确输入新 L1 编码并提交模板版本；锁定模板并检查版本，重新校验产品模板启用状态与每个有效 MBOM 分支，生成全新 L1/L2 ID，型号及名称读取当前主数据。 |
| 删除模板 | 锁定模板并检查版本，仅软删除模板并写审计；来源及所有已创建实际结构保持有效。 |

新增 L1/L2、模板应用审计和 L1 创建审计必须同事务提交。任何分支失效、编码冲突、版本冲突或审计失败都整体回滚，不允许创建一半结构。模板失效分支可继续查看、移除并保存，应用前必须全部有效；服务端始终重新校验。

模板应用的新 L1 编码沿用现有产线页面规则：去除空白并转为大写，前端提交与服务端落库使用相同规则。长度、非空及重复编码检查以规范化后的值为准，避免模板创建的编码在脑图读取时变成另一个显示值。

读取入口沿用生产架构访问权限，生成、编辑、删除和应用模板沿用 `perm_manage`。缺失/已删除对象返回 `404`，版本冲突返回 `409`，参数或主数据失效返回 `400`，新 L1 编码冲突返回 `409`。界面显示具体错误、保留草稿并阻止重复提交。

## 4. 验收与状态

当前状态：2026-11-17 实现及本地相关验收完成，实际目标部署迁移与部署后验收尚未执行。

验收必须覆盖双向隔离：模板编辑/删除不改变来源或已应用结构；来源及已应用结构编辑/删除不改变模板；重复应用生成独立 L1/L2 ID；实际 L3 更新后模板快照保持原值，应用读取当前 L3 且不改动任何已有工序、路线或执行事实。补充过期版本、失效 MBOM、停用产品模板、重复编码、审计失败回滚、权限、失败草稿保留及防重复提交验证。

本地验收证据：

- 隔离 PostgreSQL 15 测试确认双向隔离、来源删除后仍可应用、重复应用生成新身份，及产品模板名称/型号更新后应用读取当前主数据。模板表没有指向实际生产结构的外键；快照不保存实际 L1/L2/L3 ID。
- 模板编辑、删除与应用的四种提交顺序都发生真实行锁等待。变更先提交时，过期/已删除模板拒绝应用；应用先提交时，后续模板变更不回写新 L1。
- 生成、编辑、应用、删除模板时注入模板审计失败，整个操作回滚；应用已经写入的 L1/L2 及 L1 审计也一并撤销。失效 MBOM、停用产品模板、重复编码和重复分支均不留下半成品结构。
- 真实 HTTP 覆盖生成、编辑、应用、清单和删除，验证过期版本/编码冲突返回 `409`、已删除模板返回 `404`。路由测试验证只读生产架构访问不能执行四种写操作，维护权限才能进入参数校验。
- 保存边界补充验收：既有分支型号、名称及 L3 参考不能被客户端伪造，实际工序变更后模板参考仍保留原值；新增有效分支读取服务端当前真实快照。新增不存在、过期、未发布或产品停用的分支均被拒绝，不改变模板版本与审计；既有过期分支仍可维护说明或移除，但应用必须拒绝。HTTP 另行验证只读参考保留、无效新增返回 `400`，以及编码去空白/转大写后落库和重复编码返回 `409`。
- 前端 6 项测试覆盖独立编辑草稿、失败重试、取消分支移除、仅创建新 L1、防重复提交、明确来源版本、只读权限和读取失败恢复；与既有 L3 编辑测试合计 8 项通过。
- 真实 Chromium 页面使用隔离模拟 API 完成生成、查看 L3 参考、应用、编码冲突保留草稿并重试、编辑和删除流程；请求记录确认所有生产写请求仅访问模板接口。编辑/删除后来源及已创建 L1 的说明、版本和 L2 ID 保持原值，删除后新建 L1 仍可在脑图选择并查看；脑图“保存为拓扑模板”正确锁定当前 L1。390 × 844 窄屏下页面及编辑弹窗没有横向溢出，长内容可滚动并保存。本项验证页面行为，实际数据库事务与隔离由前述 PostgreSQL/HTTP 测试验证，不视为真实后端全栈或部署后验收。
- 设置 `PRODUCTION_MBOM_BRANCH_TEST_POSTGRES_DSN` 指向独立容器后，`go test ./db ./services ./handlers ./routes -count=1 -timeout=180s` 通过；`pnpm exec tsc -b`、修改前端文件的 ESLint/Prettier 及 diff 空白检查通过。测试没有运行在既有业务库。

实际入口：脑图“当前 L1 操作 → 保存为拓扑模板”；拓扑模板 TAB 支持从已建立 L1 生成模板、查看参考快照、编辑分支组合及顺序、删除模板和从模板新建 L1。编辑不自动保存，每次显式保存使用模板版本控制。
