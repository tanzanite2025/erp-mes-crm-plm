# 一维码生命周期契约

## 适用范围

本契约覆盖四个业务入口：

- 基础设置的一维码协议 TAB
- 编码中心的一维码打印 TAB
- 编码中心的一维码状态 TAB
- 裁剪作业的产品绑定 TAB

它是跨 TAB 生命周期的唯一权威说明。各 feature 的 README 只描述本地职责，不复制本文件的状态机。前端状态页不得维护完整状态数组；页面必须读取后端只读契约 `GET /code-center/linear-barcode/status-contract`。

## 所有权

| 入口 | 负责 | 不负责 |
| --- | --- | --- |
| 一维码协议 TAB | 维护 15 位字段协议和服务端发号规则键 | 发号、创建打印批次、修改库存状态 |
| 一维码打印 TAB | 请求服务端批量签发、生成打印预览、展示逐码库存 | 在前端生成真实流水号、绑定原材料 |
| 一维码状态 TAB | 读取后端状态契约，展示库存状态、生产执行状态和 L3 二级定位边界 | 手工编辑状态含义、直接改某个条码当前状态 |
| 产品绑定 TAB | 扫描预浸料二维码和产品一维码，提交唯一绑定事务 | 创建产品码、绕过库存状态直接绑定 |
| 后端库存服务 | 唯一发号、逐码落库、库存状态转换、批次计数一致性 | 定时轮询整张库存表 |
| 后端一维码状态契约服务 | 汇总库存状态、生产执行状态、生产位置二级锚点和写入边界 | 替代扫码、工序执行或委外转移动作写业务事实 |

## 15 位协议

固定结构：

```text
年2 + 月1 + 日2 + 型号2 + 外观1 + 孔型1 + 孔数2 + 流水4
```

真实流水号只能由后端从持久化协议配置读取发号规则后生成。客户端不能提交发号规则键，也不能自行保留或递增流水号。

## 库存状态机

```text
打印签发
  -> AVAILABLE
       -> BOUND      产品绑定事务成功
       -> EXPIRED    该产品码被扫描绑定时发现 expiresAt 已到期
       -> SCRAPPED   所属打印批次被报废
```

约束：

- `BOUND`、`EXPIRED`、`SCRAPPED` 都是终态，不能恢复为 `AVAILABLE`。
- 产品绑定只接受已逐码落库且状态为 `AVAILABLE` 的产品码。
- `BOUND` 更新、绑定记录、绑定事件和打印批次激活计数必须处于同一事务。
- 报废批次只把仍为 `AVAILABLE` 的码转为 `SCRAPPED`，不能覆盖已绑定或已过期记录。

## 生产执行状态机

生产执行状态不是打印库存状态的扩展，也不是裁纱/卷材追溯的硬前置。它描述“产品一维码在生产链路中的执行状态”：

```text
NOT_STARTED
  -> IN_PROGRESS
       -> COMPLETED
       -> HOLD
       -> REWORK
```

约束：

- 生产执行状态的一维码事实源是 `product_barcode_states` 和 `product_barcode_state_events`。
- `status` 是一级状态，当前环节必须通过二级定位表达：`routeStepId` 表示路线中的具体 L3 节点，`currentProcessStepId` 表示该节点对应的 L3 工序定义。
- 界面可以展示为“选择 L3”，但写入时必须保存 `routeStepId`；只保存裸 `processStepId` 会在同一 L3 被多条路线复用或同一路线重复出现时定位不准。
- 状态变化应通过扫码、工序执行、转移或带审计的纠错命令写入；一维码状态 TAB 只读展示契约，不直接改某个条码状态。

## 过期判定边界

系统不得创建一维码库存定时扫描任务，也不得在打印新批次或查询库存列表时顺便扫描整张库存表。

过期采用业务事件驱动：

1. 操作员扫描预浸料二维码和产品一维码并提交绑定。
2. 后端只针对当前扫描的产品码检查 `status` 和 `expiresAt`。
3. 若当前码仍为 `AVAILABLE` 且已到期，只把这一枚码更新为 `EXPIRED`，随后拒绝绑定。
4. 未被扫描的其它库存码不发生状态写入或额外计算。

这样允许一次预打几百张并按生产节奏慢慢使用，同时避免无业务事件时反复更新库存。

## 事务与幂等

- 批量签发必须在一个事务内完成连续发号、打印批次创建和逐码库存创建。
- 产品绑定必须锁定当前产品码库存行，防止同一码并发绑定到不同预浸料卷。
- 相同产品码和相同预浸料卷的重复提交返回原绑定记录，不能重复增加批次激活计数。
- 未签发码返回未找到；过期码拒绝绑定；已绑定或已报废码返回冲突。

## 修改检查清单

修改下列任一内容时，必须同时核对本契约和回归测试：

- 15 位字段结构或解析器
- 发号规则、批量上限或库存 TTL
- `AVAILABLE / BOUND / EXPIRED / SCRAPPED` 转换
- 产品绑定事务或打印批次激活计数
- Vitest 与 Playwright 的测试收集边界

验证基线：

```text
go test ./...
pnpm test
pnpm test:contracts
pnpm exec playwright test --list
pnpm build
```
