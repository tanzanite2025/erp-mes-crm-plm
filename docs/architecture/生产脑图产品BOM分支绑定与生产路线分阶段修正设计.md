# 生产脑图产品模板、MBOM 分支与工序路线分阶段修正设计

更新日期：2026-11-24。

本文定义产线脑图、产品模板、生产 MBOM 分支、分支工序和生产路线 TAB 的关系，并记录分阶段实施顺序及验收状态。

## 1. 术语与当前现状

产品侧 `ProductTemplate` 是脑图 L1 的数据来源。`ProductionTopologyTemplate` 按阶段 E 实施独立快照与单向复制；不改变 L1 读取产品模板、L2 直接选择有效生产 MBOM 分支的规则，模板修改不会同步到实际结构。

当前脑图和路线配置均使用产品 MBOM 分支及其独立工序身份；扫码、条码状态和委外事实已按 B5 切换到同一分支工序身份：

```text
ProductionLine 产线（L1，关联 ProductTemplate）
  -> LineSegment（L2，关联有效 MBOM 分支）
    -> ProductionBOMBranchOperation（当前脑图 L3）

ProductionRoute 产品路线
  -> ProductionRouteStep 有序路线步骤（branchOperationId）
    -> ProductBarcodeState.routeStepId 定位当前路线位置
      -> 路线步骤带出 branchOperationId
```

`LineSegment.id` 是 L2 的数据库行 ID，不能当作稳定 MBOM 分支身份；`ProductionBOMBranchOperation.id` 是脑图 L3 ID。路线步骤只保存分支工序 ID；路线步骤 ID 表示该工序在某条路线中的位置。条码状态通过 `routeStepId` 定位路线位置，再由步骤读取 `branchOperationId`。系统未正式投产，B5 在数据库启动迁移前清理不可映射的开发执行事实、重置委外汇总、删除不符合新身份的路线，并移除旧身份列和映射表；不保留旧字段兼容读取。

产品与模板的现有关系是：`Product.typeId` 指向 `ProductType`；产品分类自身或其父级分类通过 `templateId` 关联产品侧 `ProductTemplate`。MBOM 则绑定一个具体 `Product`，并有内部/客户归属、性能版本及修订生命周期。产品模板只用于 L1 读取/关联，不代表具体产品，也不用于推导或筛选 L2 的 MBOM 分支。

`ProductionTopologyTemplate` 原来保存在前端本地存储。阶段 E 将其改为服务端独立快照，支持实际 L1 生成模板、模板创建全新 L1；不提供覆盖或自动同步既有实际结构的能力。

生产路线 TAB 的业务定位是维护选定 L2 分支下 L3 工序的有序路线。路线弹窗选择真实 MBOM 分支，不自由输入产品型号；服务端会重新校验分支并以产品和 BOM 主数据填充展示字段。草稿路线发布时再次验证当前有效 MBOM 分支及其启用 L3；已发布路线供扫码执行读取，并锁定编辑和删除。系统尚未正式投产，未绑定分支的开发数据不提供名称猜测或兼容读取；迁移会清理不能满足当前身份契约的数据，再按现行分支关系重建。

### 1.1 脑图与生产路线的职责核对

截至 2026-11-24，工序配置和实际执行分成三层：工序库定义可复用的工序；路线 TAB 按 MBOM 分支直接选择工序库条目，由服务端建立或复用该分支独立的 `branchOperationId`；路线再定义工序子集、顺序及路线级执行要求。L2 脑图选配仍是独立管理配置，不是路线保存或排产的前置条件。发布后路线修订冻结工序快照，计划按 MBOM 分支及路线适用范围绑定当时已发布修订，条码执行沿用计划绑定的修订。

执行链不读取 L1、`LineSegment` 或拓扑模板来决定路线。L1 的产品模板关联、L2 的脑图关联不代表实际作业地点；扫码地点使用独立的 `ProductionWorkLocation`。因此，产线脑图不是 MES 路线执行的必要依赖。

当前实现中的 `ProductionRouteFamily` 绑定稳定 MBOM 分支及适用范围：分支默认或销售订单明细。`ProductionPlan` 有 `SalesOrderLineID` 时使用该明细路线；没有时使用分支默认路线。同一分支的不同销售订单明细可以配置不同工序集合和顺序。

脑图目前仍承载几项独立管理用途：维护 L1 与产品侧模板的关联、维护 L2 与有效 MBOM 分支的关联、配置分支工序，以及生成/应用独立的拓扑模板。路线配置直接选择 MBOM 分支、适用订单明细和工序库条目，不要求先在 L2 为该分支预选工序；工序通过该分支独立 `branchOperationId` 保持执行身份。L1/L2 树形结构不参与执行。脑图与拓扑模板的管理用途仍需结合 APS 资源规划单独评估，不随阶段 G 自动删除。

2026-11-24 已确认：同一 MBOM 分支允许按销售订单明细配置不同工序集合和顺序。路线适用身份因此需要从“仅 MBOM 分支”扩展为“MBOM 分支 + 适用范围”；适用范围为该分支默认路线或某个销售订单明细。订单明细范围使用稳定 `SalesOrderLineID`，同一明细可拆成多个生产计划，这些计划在各自排产时绑定当时匹配到的路线修订。

阶段 G 已完成服务端/数据模型、迁移、路线 TAB 和排产绑定。计划有 `SalesOrderLineID` 时精确命中“明细 + MBOM 分支”的路线，缺少明细路线时拒绝排产，不回退默认路线；计划没有 `SalesOrderLineID` 时使用该 MBOM 分支默认路线。同一销售明细拆分的多个计划各自在排产时绑定当时的当前修订；发布新修订后，之后排产的计划可以使用新修订，既有计划及条码继续使用已绑定修订。路线配置直接从工序库选择工序并排序，由服务端为该 MBOM 分支建立或复用稳定分支工序身份。脑图 L1/L2 与拓扑模板是否保留，仍按独立管理用途及 APS 资源规划单独评估；阶段 G 不修改或自动同步拓扑模板，也不删除脑图、拓扑模板或已有分支工序数据。

## 2. 目标关系

2026-11-19 新增需求：工序库先独立维护，L2 再从库中选配；工序库提供独立 TAB 与可嵌入配置弹窗。分阶段设计见 [`生产工序库独立配置与L2分支选配设计.md`](生产工序库独立配置与L2分支选配设计.md)。F2/F3 已建立独立选配关系、路线候选过滤和工序库引用保护；2026-11-20 补齐本地隔离 PostgreSQL 的迁移、并发替换和工序停用竞争验收。拓扑模板仍与产品模板、MBOM 分支和实际产线结构分离。

```text
ProductTemplate 产品侧模板
  -> 产线脑图 L1（读取并关联模板身份）
    -> ProductBOMBranch 具体产品的有效生产 MBOM 分支（L2）
      -> BranchOperation 该分支可独立维护的工序（L3）

ProductBOMBranch（L2）
  -> 生产路线 TAB（分支默认范围或指定销售订单明细）
    -> 从工序库选择工序并按该分支建立/复用 BranchOperation 身份
      -> 有序路线步骤（维护执行/质检/交接配置）
```

L1 读取并关联产品侧 `ProductTemplate` 的身份和显示名称。L2 直接从现有有效生产 MBOM 分支中选择具体分支，并保存该分支关联；L1 的产品模板不参与 L2 分支候选的推导或筛选。不得按模板名称、产品名称或性能版本目录推测并生成分支。

一个产品可以有不同性能版本或不同归属的 MBOM 分支。L2 绑定的是用户从有效生产 MBOM 分支中直接选择的一个实际分支，不是 L1 模板本身。候选 MBOM 必须属于具体产品、类型为 MBOM、状态为 `RELEASED` 且在当前有效期内；产品必须有效，客户归属数据也必须有效。

稳定分支身份为：

```text
productId + bomType(MBOM) + ownerType + ownerCustomerId + versionLevel
```

`bomId`、BOM 修订号和生命周期版本属于该分支的配方版本，不是分支身份。`siteCode` 不在当前 BOM 分支唯一键中，不作为分支维度。`ownerCustomerId` 表示 BOM 归属，不等同于销售订单客户。

L3 工序归属于 MBOM 分支稳定身份 `productId + ownerType + ownerCustomerId + versionLevel`，不归属于某个 L1 下 `LineSegment` 行，也不绑定某个 BOM 修订。每个分支工序有独立身份，并支持查看、编辑名称/说明、启停。编辑某一分支的工序不能改写其他分支或全局标准 `ProcessStep`。全局标准作业可复制为分支工序的初始内容；复制完成后不共享可变实体。

B3 将分支工序作为脑图 L3 的读写来源；B4 将路线配置切换到分支工序身份；B5 已将扫码/执行和委外事实迁移到分支工序身份并移除旧映射路径。全局 `ProcessStep` 继续作为可复制的内容来源，不承担路线或执行身份。

生产路线 TAB 从有效 MBOM 分支候选中选择具体分支；候选同时携带该分支的 L3 工序。路线维护工序顺序以及每步的执行方式、质检关卡和交接要求。由 L2 打开路线时可继承分支上下文；从生产路线 TAB 新建时必须选择真实 MBOM 分支。弹窗不再要求手工输入产品型号，产品身份由所选分支带出。

## 3. 分阶段实施

以下保留各阶段实施时的切换边界；当前完成状态及验收以第 4 节为准。B4 当时限制发布与扫码的措施已在 B5 完成后解除。

### 阶段 A：完成路线对实际 MBOM 分支的绑定

路线弹窗使用实际有效 MBOM 分支选择器；新建路线保存稳定分支身份。服务端重新查询并校验所选分支，不信任客户端传入的产品名称、归属或 BOM 状态。未绑定分支的开发路线不按旧型号自动补绑，也不进入当前路线可用数据；应删除后按有效分支重建，不提供兼容读取路径。

完成标准：同一具体产品的不同性能版本和归属可选择为不同分支；不存在、未发布、未生效的 MBOM 不能保存；无分支身份的路线不能保存或参与执行，开发数据清理后只保留按新契约创建的路线。

### 阶段 B1：让 L1 读取产品侧模板（已完成）

脑图 L1 读取并稳定关联产品侧 `ProductTemplate` 的 ID 和名称。此步骤不应用或同步 `ProductionTopologyTemplate`，不修改其本地模板数据。

### 阶段 B2：让 L2 直接选择有效生产 MBOM 分支（已完成）

新建 L2 时，用户从当前有效生产 MBOM 分支中直接选择具体分支；同一 L1 可关联多个不同分支。L2 保存稳定身份 `productId + ownerType + ownerCustomerId + versionLevel`，不保存 BOM 修订 ID；L2 名称及产品展示信息由服务端根据分支主数据填充。分支候选和保存校验依据具体产品及 MBOM 主数据，不通过 L1 的 `ProductTemplate` 关联推导或筛选，也不按名称猜测。同一 L1 不可重复关联同一分支。

每个 L2 都必须绑定当前有效生产 MBOM 分支；创建和每次保存时服务端都重新校验分支。分支缺失或失效时必须改选当前有效分支或删除该 L2，不能依赖旧名称、未绑定记录或过期分支快照继续保存。

### 阶段 B3：建立可独立维护的 L3 分支工序

按稳定 MBOM 分支身份创建独立工序定义，并提供查看、编辑名称/说明、启停能力；脑图 L3 读取这些分支工序。可从全局 `ProcessStep` 复制初始名称和说明，但保存后使用独立工序 ID，后续编辑不写回全局标准作业。此阶段不改写 `line_segment_process_mappings`、`ProductionRouteStep.processStepId` 或扫码执行引用。

### 阶段 B4：让生产路线 TAB 维护所选分支的 L3 顺序

路线 TAB 先选择有效生产 MBOM 分支，再维护该分支启用 L3 工序的顺序和路线级执行配置。分支候选返回其 L3 工序；步骤只保存 `branchOperationId`，质检跳转只保存 `targetRouteStepId`，不再逐步选择 L2 或全局 `ProcessStep`。产品/型号字段从分支身份带出，不手输，也不关联产品侧模板。B4 只开放草稿维护；路线发布和扫码执行暂不开放，避免新路线步骤被仍依赖 `ProcessStep` 的执行链路误读。未绑定或旧字段路线不出现在路线配置列表，不能通过旧字段保存或归档；启用新路线模型前清理开发路线，不保留旧路线配置读取。

### 阶段 B5：迁移路线步骤与执行引用并清理旧路径（实现完成）

B5 在 B4 验证通过后实施，按下列边界逐项切换：

- `ProductionRouteStep` 只保存 `branchOperationId`；路线所属 MBOM 分支必须与每个启用工序所属分支一致。路线步骤 ID 继续表示路线中的一个有序位置，不能替代分支工序 ID。
- 条码状态使用 `currentBranchOperationId` 表示当前工序，状态事件和转移事件使用 `fromBranchOperationId` / `toBranchOperationId`；路线推进仍使用 `routeStepId`。
- 工序执行记录、委外发出/回收和检验等扫码执行事实保存 `branchOperationId`。`OutsourceOrderLine` 是计划行，只保存产品、数量和来源快照，不绑定 L3；实际工序在扫码时从条码当前 `routeStepId` 对应的路线步骤取得，不由委外任务手填，也不以 `ProcessStep` 推导。委外执行事实同时保存当时的 `routeStepId` 与 `branchOperationId`。
- 实际生产位置使用独立的 `ProductionWorkLocation` 身份，由执行命令单独选择并写入执行事实。它不使用 L2 `LineSegment.id`、分支工序 ID、委外持有方 ID 或品质域检验站 ID；持有方仍由转移事实记录。
- `qualityRouting` 只接受同一路线内的 `targetRouteStepId`。扫码执行和委外检验均通过路线步骤定位目标，不接受 `targetProcessStepId`。
- 移除路线步骤的 `segmentId` / `processStepId`、执行与条码事实上的旧 `ProcessStep` 引用、委外事实上的旧工序字段，以及 `line_segment_process_mappings` 执行路径。全局 `ProcessStep` 仍可作为创建分支工序时复制名称和说明的来源，不再参与路线或执行解析。
- 切换前清理不可映射的开发路线和执行数据；不将旧 ID 重新解释为分支、分支工序或生产位置，不提供旧字段兼容读取。新模型及位置选择通过验证后，才开放路线发布与扫码执行。

实现记录：数据库启动时会执行身份切换迁移；隔离 SQLite 测试覆盖旧执行数据清理、委外汇总重置、有效草稿路线保留、无效路线删除及旧列/映射表移除。路线发布是独立的显式动作，发布前重新校验有效 MBOM 分支和 L3，发布后路线进入扫码执行可读集合并锁定编辑/删除。B5 实施时后端相关测试、生产执行/PDA/委外执行流程共 40 项前端测试和 TypeScript 检查通过。2026-11-17 补充通过本地隔离 PostgreSQL 15 的真实 UUID/外键迁移、失败回滚、重复启动及 L2 必填产品列迁移测试；实际目标部署数据库的升级验收仍待执行。

B5 只完成执行身份切换；随后由阶段 C 实现按计划 MBOM 分支自动绑定已发布路线。阶段 G 将路线适用范围细化为销售订单明细或分支默认范围，并由排产时的 `SalesOrderLineID` 精确选择；扫码只读取计划已绑定的路线修订，不重新按分支查找唯一路线。生产位置目录只表达实际作业地点，不参与产品、MBOM 分支或路线步骤的筛选。

B1 至 B5 每一步都单独实现、验证并记录结果，完成后再进入下一步。系统尚未正式投产，不为开发数据建立旧路线、旧工序映射或旧 ID 的兼容读取。B4/B5 切换时清理旧路线/执行开发数据和旧引用结构，再按新契约建立正式数据；不能只改 UI 标签而保留含义冲突的旧 ID。

### 阶段 C：按实际产品 MBOM 分支解析执行路线

`ProductionPlan` 是本批生产实际采用 MBOM 分支、销售订单及销售订单明细来源的权威来源。当前实现创建或排产计划时保存 `productId + bomOwnerType + bomOwnerCustomerId + bomVersionLevel` 稳定身份，并按 MBOM 分支及销售订单明细适用范围绑定路线修订；没有 `SalesOrderLineID` 时使用分支默认范围。用户从当前有效生产 MBOM 分支中为该计划选择一个分支；产品必须与分支相同。计划更新时重新验证分支有效性；计划已有执行批次或已经开始/完成执行后禁止更换分支。所有创建计划的入口（包括由 APS/切割任务创建计划的入口）都必须显式选择分支。

执行批次必须关联 `ProductionPlan`，批次产品必须与计划产品一致，产品条码唯一对应一个活跃执行批次。生产扫码只提交产品条码、动作及作业地点等执行信息；客户端不提交执行批次 ID、路线 ID、路线步骤 ID 或分支工序 ID。条码状态初始化接口也不接受客户端提供路线/工序身份。当前服务端按计划绑定的路线修订执行；该修订在排产时按计划 MBOM 分支及销售订单明细范围解析，计划有 `SalesOrderLineID` 时必须匹配明细路线，没有时使用分支默认路线。路线修订 ID 保存在计划上，扫码只读计划绑定修订，不在执行时选路。返工目标仍通过路线步骤 ID 表达。

计划创建/更新、执行批次登记和生产扫码均由服务端校验 MBOM 分支身份及产品归属。计划缺少分支、执行批次缺少有效计划、批次产品与计划不一致、分支失效、匹配范围没有已发布路线、路线范围身份不匹配或路线步骤包含失效工序时，必须明确拒绝并指出需维护的对象。不得从产品模板、型号/产品名称、销售订单客户或 BOM 最新版本推测分支，也不退回手动挑路线。订单明细范围路线必须校验明细属于计划订单且明细产品与 MBOM 分支产品一致；计划没有 `SalesOrderLineID` 时一律只使用分支默认路线。独立的工序执行写接口不能绕过计划路线，生产执行统一通过扫码命令；路线查询仍可用于展示当前路线进度。

阶段 C 的 PostgreSQL 验收使用独立测试容器和随机隔离 schema，验证以下边界：

- 旧执行身份清理在真实 UUID 列及外键约束下成功，失败时事务整体回滚；重复启动不清理按新契约创建的数据。
- L2 旧结构先删除未绑定及已删除开发记录，再迁移为产品必填的结构；已有可空产品列必须收紧为 `NOT NULL`，重复启动保留已绑定记录。
- 执行批次登记与计划分支更新锁定同一计划行。批次先提交时，分支更新必须拒绝；分支先提交时，批次必须读取提交后的计划产品和分支，不能保存锁定前的产品快照。
- 计划从客户分支切换到内部或无性能版本分支时，必须实际清空旧客户及版本字段；已经初始化路线位置的条码不能因执行批次软删除而解除计划分支保护。
- 计划新建入口在不关联销售订单时按现有可选来源规则写入 `NULL`，不能向可选 UUID 列写入空字符串；MBOM 分支仍必须有效。
- 扫码仅按条码读取计划已绑定的路线修订；并发重放只写入一次执行和路线推进事实，计划修订与 MBOM 分支或销售订单明细范围不匹配时拒绝执行。

本地隔离数据库验收与实际部署迁移验收分别记录，不以本地测试代替目标部署数据库验收。

### 阶段 D1：分支工序停用的引用保护（实现及本地验收完成）

已发布路线或已有生产/委外执行事实引用的 L3 工序禁止停用，服务端返回明确的业务冲突并指出引用来源。保护范围包括当前条码工序、条码状态事件、路线/持有方转移事件、工序执行及委外收发和检验事实；历史引用不因事实软删除而解除保护。仅被草稿路线引用、尚无执行事实的工序可以停用，但该草稿随后必须更换或重新启用工序才能发布。名称、说明与显示顺序仍可独立维护；本阶段不建立历史内容快照或业务修订。

路线保存/发布与分支工序更新在同一数据库事务内锁定对应工序行。修改、发布或删除已有路线时先锁定路线行，再按工序 ID 固定顺序锁定工序行，避免路线写入之间发生锁顺序倒置；停用先提交则发布必须读取停用后的状态并拒绝，发布先提交则停用必须读取已发布引用并拒绝，不能产生含停用工序的已发布路线。业务冲突通过 HTTP `409` 返回，编辑页显示服务端的具体原因、保留失败草稿并允许重试，保存期间阻止重复提交。

L1 与 L2 是脑图关联，不是执行工序或生产地点。L1 停用/删除、L2 移除不应按相同产品或分支推测执行依赖，也不得级联停用/删除分支工序、路线或执行事实。本阶段通过边界测试确认这种独立性；L1/L2 子记录归属及删除一致性由 D2 完成。拓扑模板独立复制由 E 完成；路线业务修订和发布工序快照、委外固定路线修订联动、每码单件、多条码数量拆分、同码复检轮次和返工后重复委外收发周期均已完成，剩余目标数据库部署验收。

### 阶段 D2：L1/L2 归属与删除一致性（实现及本地验收完成）

L2 记录只属于创建它的一个 L1；同一 MBOM 分支仍可以分别关联到不同 L1，各自使用独立 L2 ID。保存时必须拒绝借用其他 L1 的 L2 ID、重复提交同一 L2 ID、复用已删除 L2 ID，以及请求中与当前 L1 不一致的 `lineId`。新 L2 可以使用客户端生成的 UUID，但必须按新增写入，不能通过 upsert 接管已有记录；临时 L1/L2 ID 由服务端转换为正式 UUID。

保存与删除已有 L1 必须在事务内锁定同一活跃 L1 行，保存取得锁后再核对版本。已删除或不存在的 L1 返回 HTTP `404`，过期版本返回 `409`，非法 L2 归属返回 `400`；更新不得回退到创建，也不得复活已软删除的 L1/L2。并发请求使用同一新 L2 ID 时，最多一个请求成功，失败请求整体回滚。

移除 L2、更新 L1、递增版本和写审计在同一事务中完成。删除 L1 时同事务软删除其全部活跃 L2 关联；审计写入失败必须回滚整个操作。上述操作仅维护脑图关联，不级联修改共享分支工序、路线、条码状态、执行或委外事实。

验收包括跨 L1 借用、重复 ID、已删除 ID 复用、临时 ID 转正式 UUID、审计失败回滚，以及隔离 PostgreSQL 中保存/删除的两种提交顺序和不同 L1 并发创建相同 L2 ID 的真实锁等待。

### 阶段 E：拓扑模板独立快照与单向复制（实现及本地验收完成）

按 [`生产拓扑模板独立快照与单向复制设计.md`](生产拓扑模板独立快照与单向复制设计.md) 实施。模板与实际结构互不回写，L3 仅保留参考快照，应用只创建新 L1/L2 关联并读取分支当前工序；不修改生产路线及执行事实。

### 阶段 F2/F3：工序库选配与路线引用保护（实现及本地隔离 PostgreSQL 验收完成）

L2 可通过 `ProductionBOMBranchOperationProcessLibrarySelection` 按稳定 MBOM 分支身份选配 `ProcessStep`，每条关联创建独立的 `ProductionBOMBranchOperation` 作为 L3 和路线执行身份。路线 TAB 也可直接选择工序库条目；保存时服务端为该分支建立或复用同一 L3 身份并持久化分支—工序库关联，因此脑图 L3 能查看和维护路线直选的工序。L2 选配与路线草稿互不共享，也不要求先完成 L2 选配才能配置路线。取消选配前检查路线、条码、执行及委外事实引用。路线发布校验 L3 和工序库记录仍有效且启用；已被分支工序身份引用的工序库工序不能停用或删除，服务端返回 `409`。工序库 ID 不是路线步骤 ID。

### 阶段 G：销售订单明细级路线适用范围（已实现，本地验收通过）

用户已确认同一稳定 MBOM 分支下，不同销售订单明细可以采用不同的工序集合及顺序。路线仍由 MBOM 分支限定产品/BOM 身份，但路线家族还需记录适用范围：分支默认路线，或一个明确的 `SalesOrderLineID`。同一销售明细可拆为多个 `ProductionPlan`，这些计划在各自排产时绑定当时匹配的路线修订。

适用范围解析规则：

- 路线范围身份由稳定 MBOM 分支加范围组成。范围为该分支默认路线，或明确的 `SalesOrderLineID`；同一分支的默认路线与多个明细路线可以并存。
- 生产计划有 `SalesOrderLineID` 时，只读取该销售订单明细 + 计划 MBOM 分支的路线。缺少该明细范围的已发布路线时拒绝排产并指出需维护的明细路线，不静默回退到分支默认路线。
- 生产计划没有 `SalesOrderLineID` 时，一律读取该 MBOM 分支的默认路线；是否存在 `OrderID` 不改变此规则。缺少分支默认已发布路线时拒绝排产。
- 新建计划首次保存为 `SCHEDULED`，或计划从未排产状态进入 `SCHEDULED`，就是排产确认。服务端在同一事务中绑定当时匹配范围的当前已发布修订，客户端不得提交或覆盖路线修订 ID。已绑定路线修订的计划后续编辑不得静默改绑。
- 同一销售订单明细若拆成多个计划，各计划分别在自己的排产确认时绑定当前修订。发布新修订后再排产的计划可以绑定新修订；已排产计划及其条码继续固定原修订。需要使用新修订时，另建计划并排产。
- 计划有 `SalesOrderLineID` 时，该明细必须属于计划的 `OrderID`，且明细产品必须与所选 MBOM 分支产品一致。被路线家族、生产计划或执行事实引用的销售订单明细不得级联删除；明细产品变更不得使已有计划、条码或已发布路线身份重新解释，存在引用时必须拒绝变更或删除。
- 发布新修订只影响之后排产并绑定新修订的计划；既有计划及条码继续使用原修订。委外执行仍只读取条码所属计划已固定的路线修订。

路线 TAB 提供 MBOM 分支、适用范围（分支默认或指定销售订单明细）和工序库候选。维护人员选择工序并定义顺序；保存时服务端为当前 MBOM 分支建立或复用独立 `branchOperationId`，再保存路线修订。该入口承接路线工序配置，不要求先在脑图 L2 勾选、再在路线 TAB 重复选择。L1 产品侧 `ProductTemplate` 关联、L2 MBOM 分支关联及独立拓扑模板都不参与路线范围身份；拓扑模板修改不得修改已存在的路线或生产计划。工序停用、删除继续受已发布路线和执行事实引用保护。

数据模型契约：路线家族增加明确的 `scopeType`（`BRANCH_DEFAULT` 或 `SALES_ORDER_LINE`）及可空 `SalesOrderLineID`。默认范围必须为 `BRANCH_DEFAULT` 且 `SalesOrderLineID` 为空；明细范围必须为 `SALES_ORDER_LINE` 且 `SalesOrderLineID` 有值。唯一身份为“稳定 MBOM 分支 + `scopeType` + 对应范围 ID”，禁止重复默认路线或重复的分支/明细路线。迁移将当前每个分支唯一的路线家族归入分支默认范围，不保留旧运行时读取路径。销售明细被路线或计划引用后不得级联删除；路线发布、计划排产和明细变更必须按稳定 ID 校验，并通过同一范围家族锁保证发布与排产串行化。

脑图去留与阶段 G 实施分开决策：路线配置已承接路线工序选择；L1 产线记录、产品侧模板关联、L2 分支分组展示及独立拓扑模板不参与路线身份。按 APS 是否需要真实产线资源绑定、拓扑模板是否仍有实际复用价值，决定这些管理入口的保留或重定位。不得把它们加入路线身份，也不得让模板修改生产执行结构。

### 核心路线修订的数据契约

- 一个 `ProductionRouteFamily` 只属于一个稳定 MBOM 分支及一个明确适用范围。分支唯一身份仍为 `productId + bomOwnerType + bomOwnerCustomerId + bomVersionLevel`；适用范围为分支默认或 `SalesOrderLineID`。L1、拓扑模板、产品模板都不参与路线家族身份。同一分支和同一适用范围只允许一个路线家族，不能让排产猜选。
- 每个 `ProductionRoute` 记录代表一份业务修订，使用独立 `revisionNo`；现有 `version` 继续只作草稿乐观锁。路线家族保存当前发布修订 ID。首次建路线产生第 1 修订；从已发布路线复制新修订时，家族不变、修订号递增、步骤 ID 全新生成，旧修订及其步骤不变。
- 发布事务重新校验有效 MBOM 分支、路线步骤对应的启用 L3 和工序库记录，并把 L3 名称/说明写入路线步骤的发布快照。顺序、路线步骤配置、路线头部和分支身份都属于该不可变修订的历史内容。发布后不能编辑或删除该修订；发布下一修订只切换家族当前修订指针，旧修订仍为已发布且可供已经绑定它的计划和条码执行。
- 路线写入统一按“路线家族行 → 路线修订行 → 路线步骤/分支工序行”加锁；草稿保存、发布、复制新修订和删除共用此顺序。排产绑定锁定匹配适用范围的路线家族，再读取当前发布修订，因此发布与排产按家族锁串行；需要锁定分支工序时必须在路线修订锁之后获取，避免相反次序形成死锁。
- 保存一个 `SCHEDULED` 生产计划就是排产确认。服务端在同一事务中按 `SalesOrderLineID` 选择精确明细范围；计划没有该 ID 时选择分支默认范围，再读取当前已发布修订并绑定。客户端不能提交或覆盖修订 ID。之后编辑计划不能静默切换已绑定修订。需要使用新路线修订时，新建计划并排产；旧计划及其条码继续固定原修订。所有创建计划的入口，包括切割/APS 入口，都执行同一绑定规则。
- 首次扫码只读取计划已绑定的修订，不再按当前发布指针动态选路；条码状态首次开工时保存该修订 ID 和首个路线步骤 ID。每次后续执行都校验计划、条码状态和执行记录使用同一修订。路线历史页面按发布快照展示工序，不能从当前 L3 名称重算历史。
- 核心路线阶段验收包括：同一分支和同一适用范围只能有一个路线家族；复制发布新修订不改写旧步骤；修订快照不随 L3 改名而变化；计划绑定其匹配范围的新修订，已排产计划仍绑定旧修订；路线修订切换与计划排产并发时结果串行且唯一；订单明细属于计划来源订单且产品与分支产品一致；明细路线缺失不得回退默认路线；没有 `SalesOrderLineID` 时一律只使用分支默认路线（包括仍有 `OrderID` 但没有明细 ID 的计划）；被计划或路线引用的订单明细不能级联删除或改成不匹配产品；开工条码在发布新修订后仍按原步骤继续；分支或 L3 无效时发布/排产拒绝且不产生部分写入。

生产拓扑模板只提供独立快照与单向复制，不提供覆盖或自动同步实际 L1 的能力。产品侧 `ProductTemplate` 仍供 L1 读取/关联；L2 的 MBOM 分支选择、L3 分支工序及生产路线 TAB 分别按 B2 至 B4 的业务身份维护。

## 5. 不变边界

- 产品 BOM 维护产品配方分支及其修订；生产路线维护工序顺序和路线级执行策略，两者通过稳定分支身份关联，不互相复制内容。
- 工序说明“做什么”，生产位置说明“在哪里做”，两者使用不同身份。
- BOM 发布和路线发布使用各自生命周期；修改 BOM 修订不隐式修改路线，修改路线也不修改 BOM。
- 生产拓扑模板与产品侧 `ProductTemplate` 是不同对象；L1 读取/关联产品侧 `ProductTemplate`，L2 直接选择有效生产 MBOM 分支。模板应用重新校验这些引用，只创建新的 L1/L2 关联；不覆盖共享 L3、路线或执行事实，也不回写既有实际结构。
- 工资模块不引用 BOM、产品分支、产线、标准作业或生产路线步骤。
