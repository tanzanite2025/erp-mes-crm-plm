# 快捷扫描侧边栏指令契约

## 当前接口

`GET /quick-actions/sidebar/me`

该接口只返回当前登录账号可见的快捷扫描入口配置。

响应字段：

```json
{
  "businessCommands": [
    {
      "commandId": "warehouse_inbound_scan",
      "title": "入库扫描",
      "description": "仓库入库扫码入口",
      "route": "/warehouse/inbound",
      "searchParams": { "mode": "scan" },
      "icon": "PackagePlus",
      "category": "warehouse",
      "assignable": true,
      "enabled": true,
      "status": "active",
      "sortOrder": 10
    }
  ],
  "privateCommandIds": [
    "personal_workbench_photo",
    "personal_workbench_video",
    "personal_workbench_buffer"
  ]
}
```

## 分配来源

管理员保存账号配置时，只提交：

```json
{
  "categoryIds": ["warehouse"],
  "commandIds": ["wheel_trace_scan"]
}
```

后端统一把 `categoryIds` 内的分类指令和 `commandIds` 内的单独指令合并、去重，再通过 `/quick-actions/sidebar/me` 返回完整的 `businessCommands`。

## 强制约定

1. 业务指令只能通过 `businessCommands` 返回完整指令定义。
2. 前端快捷扫描侧边栏只读取 `businessCommands`，不接受业务指令 ID 数组。
3. 不允许恢复 `businessCommandIds`、字符串 ID fallback、旧 registry fallback 等兼容逻辑。
4. `privateCommandIds` 只用于固定个人私有工具：个人拍照、个人录视频、个人缓冲区。
5. 个人私有工具不得进入指令库、分类库，也不得参与管理员分配。

## 设计原因

系统尚未上线，不需要兼容旧契约。业务指令定义由后端指令库统一维护；分配页只保存“分类 + 单独补充指令”，侧边栏必须读取后端返回的完整定义，避免新增指令后还要修改前端静态 registry。
