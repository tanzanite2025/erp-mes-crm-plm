# 销售订单确认、生产计划进度与发货状态归属

销售端负责确认草稿、认领责任和允许范围内的作废。页面移除“进入排产”“下达生产”“标记完成”；旧接口动作名保留兼容识别，但不能手工推进生产或履约状态。普通保存、混合编辑及批量同步也不能伪造进度。历史订单原有状态在读取时保持兼容。

| 事实 | 对订单的影响 |
| --- | --- |
| 草稿确认 | `Draft → Pending` |
| 明细认领、MRP 分析、一维码预打 | 不推进生产状态 |
| 创建有效生产计划，包括裁纱下发 | `Scheduling` |
| 计划开工、完工，或工单运行、暂停、完成、有实际数量或开始时间 | `InProgress` |
| 有明确执行批次与计划关联的工序报工 | 计划进入生产中，同步来源销售订单 |
| 部分发货 | `InProgress` |
| 全部明细发货完成 | `Done` |
| 撤销全部未开工计划，且无发货 | 回到 `Pending` |

MRP、裁纱与一维码预打共用 `Pending / Scheduling / InProgress` 资格，排除草稿、终态、软删除和报价。服务端再次校验，不能依赖页面筛选。认领只是责任分配，所有明细认领也不会自动进入排产。

新裁纱计划保存稳定的 `salesOrderLineId`，只更新对应明细。通用计划保存校验明细归属，不允许已保存计划更换来源订单或来源明细。历史无明细 ID 的计划只影响整单，不能按产品名猜测同产品多行。该可选字段随现有 `ProductionPlan` 自动迁移添加，无需改写历史数据。

进度同步和生产单据写入在同一事务中执行，锁定销售订单并仅在订单或明细状态变化时递增版本、派发订单状态事件。通知配置不决定是否同步进度。草稿、作废、已完成订单不会被生产事件复活；已发生的生产不能因撤销计划而被抹除。生产完成不等于销售交付完成。

销售订单关联未撤销计划时应先撤销未执行计划，再作废订单；已开工订单不能直接作废。原有生产领料保护继续有效。没有计划关联的独立条码生产继续独立办理，不根据产品名推测销售来源，也不强制绑定裁纱。
