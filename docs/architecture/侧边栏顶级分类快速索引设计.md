# 侧边栏顶级分类快速索引设计

## 背景

当前系统左侧侧边栏已经逐步扩展为多级业务导航。随着顶级业务大类继续增加，用户在左侧菜单中查找某个业务域的成本会越来越高。参考 21st.dev 的 Chapter Scrubber 交互，可以在侧边栏与内容区之间增加一列独立的竖向快速索引轨道。

这个索引不是替代侧边栏，也不是新的菜单配置源。它只负责帮助用户快速定位左侧顶级大类，并在悬停时预览该大类下的业务结构。

## 设计目标

- 一条短横线代表一个顶级大类。
- 横线数量等于当前用户实际可见的顶级大类数量。
- 鼠标悬停横线时展示该大类名称、L1 子组和可点击的业务域入口。
- 点击顶级横线只负责把左侧侧边栏滚动到对应大类居中位置。
- 点击悬停卡片内的业务域入口才执行路由跳转。
- 当前路由所属大类和当前侧边栏居中大类都要有清晰状态反馈。
- 侧边栏展开、折叠、隐藏时索引轨道都应在桌面端存在。
- 移动端不显示该索引轨道，保持移动端原有侧边栏交互。

## 明确边界

### 1. 顶级大类才是索引刻度

索引轨道只认侧边栏顶级 `NavGroup`。例如采销、生产、原材料中心、经营分析、工程、品质、仓储物流、资产与组织、财务、消息审批、系统管理等。

不能把 L1 子组、三级业务域、页面 TAB 都做成横条。否则侧边栏膨胀后索引本身也会膨胀，失去快速定位意义。

### 2. TAB 不属于侧边栏索引

项目已经约定：三级菜单代表业务域，业务域内部的 TAB 由对应 feature 模块维护。

因此索引轨道不能读取 TAB 配置，也不能把 TAB 名称展示为侧边栏层级。

正确关系是：

- 顶级大类：侧边栏索引的一条横线。
- L1 子组：悬停卡片内的结构标题。
- 三级业务域：悬停卡片内可点击的路由入口。
- 页面 TAB：进入业务域之后页面内部自己的导航，不参与索引。

### 3. 不允许新增第二套菜单映射

索引数据必须从现有侧边栏数据派生，不能复制一份新的大类、子组、路由映射。

原因：

- 权限过滤后，每个用户看到的大类可能不同。
- 多语言标题必须与侧边栏一致。
- 后续新增、删除、重命名菜单时不能维护两份配置。
- 复制配置会导致侧边栏和索引长期不一致。

### 4. 不能根据文字判断层级

索引必须读取稳定的 `id` 和 `NavGroup` 结构，不能通过中文标题、英文标题、关键字来判断大类归属。

标题可以随语言和业务命名变化，`id` 才是长期稳定的系统识别字段。

## 参考组件实现原理

Chapter Scrubber 的核心不是普通滚动条，而是一组带动画的章节刻度。其可借鉴的点包括：

- 每个章节对应一个短条。
- 鼠标悬停短条时，短条变长、变亮。
- 当前指示器使用 motion value 或 spring 动画平滑移动。
- 悬停时根据元素 `getBoundingClientRect()` 计算浮层位置。
- 浮层内可以展示章节信息并执行跳转。
- 视口尺寸变化后需要重新计算可用区域。

本项目需要改造成垂直方向的业务分类索引，而不是直接照搬横向章节 scrubber。

## 项目现有导航链路

当前侧边栏关键链路为：

```text
src/components/layout/data/sidebar-data.ts
  ↓ getSidebarData(t)
src/features/authz/guards/navigation-access.ts
  ↓ getAccessibleNavGroups(user, navGroups, { isIdentitySynced })
src/components/layout/app-sidebar.tsx
  ↓ useSidebarNavGroupsWithBadges(visibleNavGroups)
  ↓ renderedNavGroups
src/components/layout/nav-group.tsx
  ↓ NavGroup 渲染顶级大类
src/components/layout/sidebar-menu-branch.tsx
  ↓ 渲染子组与业务域入口
```

索引轨道应复用 `renderedNavGroups`，而不是重新调用原始 `navGroupConfigs`。

特别注意：当前 `AppSidebar` 会过滤掉 `resource-management`，因此索引也必须使用过滤后的同一份 `renderedNavGroups`，避免出现索引里有、侧边栏没有的大类。

## 推荐组件职责

### `sidebar-navigation-model.ts`

建议新增统一导航模型生成文件，负责把权限过滤、徽标注入、需要渲染的大类列表整理为稳定结构。

职责：

- 接收 `getSidebarData(t)` 的原始导航数据。
- 调用权限过滤。
- 注入动态徽标。
- 输出侧边栏和索引共用的 `renderedNavGroups`。
- 避免 `AppSidebar` 和索引组件各自计算一遍导航树。

### `sidebar-category-scrubber.tsx`

负责桌面端竖向索引轨道。

职责：

- 渲染每个顶级大类对应的横条。
- 处理 hover、focus、mouseleave。
- 显示当前路由大类和当前居中大类。
- 点击横条时调用侧边栏滚动居中逻辑。
- 展示悬停浮层。
- 使用 `framer-motion` 做指示器和浮层动画。
- 移动端直接不渲染。

### `sidebar-category-scrubber-utils.ts`

负责纯函数逻辑。

职责：

- 从 `NavGroup[]` 提取浮层展示结构。
- 找到某个大类下所有可点击业务域入口。
- 计算浮层 top 坐标并限制在视口内。
- 计算当前居中的顶级大类。
- 提供测试友好的数据转换函数。

### `use-sidebar-active-center.ts`

现有文件已经负责把当前 active path 居中。后续可以扩展一个明确方法：

- 根据当前路由自动居中 active 业务域。
- 根据指定 groupId 把顶级大类滚动到侧边栏中间。

不建议在索引组件内重复写一套滚动算法。

### `nav-group.tsx`

需要继续保持稳定 DOM 锚点：

```text
data-sidebar-nav-group="<groupId>"
data-sidebar-nav-group-anchor="<groupId>"
```

其中：

- `data-sidebar-nav-group` 挂在顶级大类容器上，表示大类结构边界。
- `data-sidebar-nav-group-anchor` 挂在顶级大类标题按钮上，表示用户点击索引后真正要居中的视觉锚点。

这样索引点击某个大类时，可以准确找到该大类标题并滚动到侧边栏可视区域中间。不能直接居中整个大类容器，因为展开的大类会包含大量下级菜单，容器中心会被下级内容高度拉偏。

### `app-sidebar.tsx`、`authenticated-layout.tsx` 与 `sidebar.tsx`

索引轨道应作为 `<Sidebar>` 的同级元素挂载，而不是挂在 `SidebarContent` 内。

原因：

- 放在 `SidebarContent` 内会被侧边栏滚动和 overflow 裁切。
- 侧边栏隐藏时索引会跟着消失，不符合桌面端折叠后仍可用的要求。
- 作为 `<Sidebar>` 同级元素可以在桌面端形成独立布局列，避免索引与内容区互相覆盖。

当前实际接入点放在 `AppSidebar` 返回的 Fragment 中：

- `authenticated-layout.tsx` 继续只负责挂载 `AppSidebar`，并设置桌面端索引列宽变量 `--sidebar-gutter-width`。
- `sidebar.tsx` 负责让固定 Header、模块 TAB 的左偏移同时包含侧边栏宽度和索引列宽。
- `AppSidebar` 内部持有 `navViewportRef`，因此索引组件可以直接复用同一个侧边栏滚动容器。
- `SidebarCategoryScrubber` 与 `<Sidebar>` 同级，不进入 `SidebarContent`，不会被侧边栏滚动区域裁切。
- `SidebarCategoryScrubber` 自己渲染桌面端 `aside` 列；移动端不渲染。

## 折叠状态边界

### 侧边栏展开

索引轨道占据侧边栏右侧、内容区左侧的一列。用户可以通过索引快速滚动侧边栏。

### 侧边栏折叠或 offcanvas 隐藏

索引轨道仍然存在，占据内容区左侧的一列。

点击顶级横条时建议行为：

- 如果侧边栏当前隐藏，则先打开侧边栏。
- 再把对应顶级大类滚动到左侧侧边栏中间。
- 不自动进入默认页面。

### 移动端

移动端不显示索引轨道。

原因：

- 手机端空间不足。
- hover 交互不可用。
- 当前移动端已经有 Sheet 形式侧边栏，额外索引会增加误触。

## 状态设计

索引轨道需要区分两个状态。

### 当前路由大类

根据当前 pathname 通过 `resolveActiveSidebarPath(renderedNavGroups, pathname)` 得到。

它表示用户当前页面属于哪个顶级大类。

### 当前侧边栏居中大类

根据侧边栏滚动容器中各个 `data-sidebar-nav-group` 的位置计算。最接近滚动容器中心线的大类就是当前居中大类。

它表示用户目前在左侧菜单中看到的位置。

### 为什么要分开

用户可能当前在生产页面，但滚动左侧侧边栏去查看系统管理。此时：

- 当前路由大类仍是生产。
- 当前居中大类变成系统管理。

如果只用一个状态，会导致高亮错乱，让用户误以为页面路由已经变化。

## 交互规则

### 鼠标悬停横条

- 当前横条变长、变亮。
- 显示顶级大类名称。
- 展示该大类下的 L1 子组和业务域入口。
- 指示器用平滑动画移动到对应横条。

### 鼠标从横条移动到浮层

浮层应保持打开，不能立即消失。

建议设置一个小的关闭延迟，例如 100 到 160 毫秒，避免鼠标经过缝隙时闪烁。

### 鼠标在横条之间移动

外层轨道不能不断放大缩小。

只允许被 hover 的横条变化；容器本身保持稳定，避免出现类似底部 Dock 曾经的抖动问题。

横条之间不能存在鼠标探测断层。命中规则应按相邻横条中心线切分：每个横条负责自己的可见区域，并额外负责上下空白区域的一半。这样鼠标位于两个横条中间时，也会自然命中最近的大类，不会导致浮层突然关闭。

### 点击顶级横条

- 只定位侧边栏。
- 不跳转路由。
- 不展开页面 TAB。
- 不自动选择默认业务域。

### 点击浮层内业务域

- 直接跳转到该业务域路由。
- 路由变化后沿用现有 active path 机制展开对应侧边栏分支。
- 目标业务域自动在侧边栏中居中。

## 权限与可见性

索引轨道只能展示当前用户有权限看到的顶级大类和业务域入口。

不能展示无权限大类，也不能在浮层内展示无权限业务域。

这也是为什么索引必须使用权限过滤后的 `renderedNavGroups`。

## 动画原则

- 动画只服务定位和反馈。
- 不改变现有侧边栏字体、字号、图标大小。
- 不改变现有侧边栏宽度规则。
- 不影响内容区布局稳定性。
- 使用 `framer-motion` 即可，项目已有依赖，不需要引入新动画库。
- 支持 `prefers-reduced-motion`，减少动画用户应看到静态或弱动画反馈。

推荐动画：

- 横条长度和透明度过渡。
- 当前指示器弹簧移动。
- 浮层淡入、轻微位移。
- 当前路由大类可以有稳定主色标记。
- 当前居中大类可以有平滑移动的细线或光点。

## 视觉建议

轨道宽度应明确由布局变量控制，避免用 fixed left 贴边后和内容区重叠。

建议：

- 桌面端列宽由 `--sidebar-gutter-width` 控制，当前为 `3.75rem`。
- 横条默认短而低对比，但命中区要明显大于可见横条，避免鼠标经过缝隙时触发不到。
- 横条之间的空白区域由相邻横条各负责一半，确保轨道纵向命中连续。
- hover 后横条变长，颜色可使用主色或橙色强调。
- 浮层使用项目现有卡片、边框、阴影、字体层级。
- 不要新增一套独立字体风格。

## 实施顺序建议

1. 先抽出统一导航模型，保证侧边栏和索引共用同一份 `renderedNavGroups`。
2. 给 `NavGroup` 确认稳定顶级大类 DOM 锚点。
3. 扩展侧边栏滚动居中能力，支持按 groupId 居中。
4. 新增 `sidebar-category-scrubber-utils.ts`，先完成数据结构和测试。
5. 新增 `sidebar-category-scrubber.tsx`，只在桌面端渲染。
6. 在 `app-sidebar.tsx` 中作为 `<Sidebar>` 同级挂载。
7. 验证展开、隐藏、权限过滤、多语言、路由高亮、滚动居中。

## 不应做的事情

- 不要复制一份新的菜单配置。
- 不要从标题文字判断层级。
- 不要把 TAB 放进索引。
- 不要让点击顶级横条自动跳页面。
- 不要让索引随侧边栏隐藏而消失。
- 不要在移动端显示该轨道。
- 不要改变现有侧边栏字号、图标大小和菜单间距。
- 不要让浮层被侧边栏 overflow 裁切。
- 不要让 hover 在横条之间造成容器抖动。
