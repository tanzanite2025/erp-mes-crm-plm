# 车型模型模板注册表设计

## 1. 目标

车型规格库负责“种子车型”主数据，模型模板注册表负责“可被解析、可被预览、可被后续 3D 引擎复用”的模板资产。

这两个概念不能混在一起。

## 2. 职责分层

### 2.1 车型规格库

- 维护车型名称、类别、车厢尺寸；
- 维护可用装载空间；
- 维护安全余量和装载约束；
- 作为模型模板的种子主数据。

### 2.2 模型模板注册表

- 绑定一个种子车型；
- 只接收符合项目导出规范的 GLB（glTF 2.0 Binary）源文件；
- 保存源文件、格式、版本、解析状态；
- 输出归一后的预览摘要；
- 为后续 Rust / WASM / WebGL 引擎提供稳定入口。

## 3. 当前推荐的数据链路

```text
车型规格库
  -> 选择种子车型
  -> 上传 3D 源文件
  -> /assets/vehicle-model-templates/upload 保存受控 GLB 源文件
  -> 模型模板注册表持久化记录
  -> 写入不可变版本快照
  -> 显式触发 GLB 解析
  -> 解析结果写入新的模板版本快照
  -> 装箱预览读取模板摘要
  -> 后续 3D 几何引擎读取 vehicle-geometry.v1
```

## 4. 当前实现状态

已完成：

- 车型规格库页面新增模型模板入口；
- 模板记录必须绑定车型规格库中的一个种子车型；
- 车型模板长期只支持 GLB（glTF 2.0 Binary）；其它格式不再作为并列输入格式；
- 上传结果保存为后端托管的扁平 `/uploads/文件名` 服务器资产 URL；
- 车型模型模板使用独立上传入口，单文件上限为 8MB；通用资产入口的 50MB 上限不适用于车型模型模板；
- 车型模型模板上传文件统一使用 `vehicle-model-template-` 前缀；
- 模板注册服务端只接受后端上传返回的内部资产路径，不接受外链、查询参数、子目录、路径穿越或 Windows 分隔符；
- `logistics_vehicle_model_templates` 持久化模板注册记录；
- `logistics_vehicle_model_template_versions` 保存每次创建、更新、恢复后的不可变版本快照；
- 支持按种子车型查询、创建和更新模板；
- 支持读取单个模板的版本历史；
- 支持把历史版本显式恢复为新的当前版本；
- 支持管理员显式调用 `POST /logistics-config/vehicle-model-templates/:id/parse` 解析已上传 GLB；
- 解析入口通过 `VEHICLE_GEOMETRY_PARSER_BIN` 或本地默认构建路径调用 `xdfc-vehicle-geometry-parser`；
- 解析成功后，模板状态由 `uploaded` 推进到 `normalized`，并把 `vehicle-geometry.v1` 写入新版本快照的 `geometry` 字段；
- 解析过程不在普通保存流程中自动运行，也不创建未执行的后台任务表；
- 对模板名称、种子车型、内部源文件地址、格式、状态、归一尺寸做服务端校验；
- 模板实体已接入审计引擎注册表，创建、更新和恢复会写入 `vehicle-model-template` 审计事件；
- 前端使用现有 `perm_manage` 管理权限：无权限时上传和保存控件仍显示但置灰；
- 车型规格库页面可以查看当前种子车型的已保存模板，并回填到上传卡片继续更新；
- 车型规格库页面可以展开模板版本快照，并在有管理权限时恢复指定历史版本；
- 装箱预览会按推荐车型读取注册表中最新的模板摘要，选择逻辑集中在 `selectLatestVehicleModelTemplateForSeedVehicle`；
- 没有已注册模板时，装箱预览回退到车型规格库的种子定义；
- 模板注册表读取失败时，装箱页会明确提示，并临时回退到种子车型，不影响推荐计算；
- 预览当前仍只使用车型规格库尺寸完成 2D 示意，`geometry` 已落入版本快照但还未参与真实装箱计算。

未完成：

- 碰撞体 / 障碍区参与装箱计算；
- 3D 预览引擎接入。

已完成独立解析核心：

- `vehicle-loading-engine/core` 只接受 GLB；
- 解析节点语义、世界变换和顶点包围盒；
- 输出毫米制 `vehicle-geometry.v1`；
- native Rust 测试覆盖有效 GLB、缺少语义和非 GLB 输入。
- `vehicle-loading-engine/wasm` 已提供同一核心的 JSON 边界适配，但尚未接入前端实时预览。
- `vehicle-loading-engine/cli` 已作为 Go 显式解析入口的执行边界。

说明：

- 当前 `version` 字段表示该模板的当前生效版本号；
- 版本恢复不会覆盖历史快照，而是把选中的历史快照复制为新的当前版本；
- 普通保存形成的版本快照保存源文件、状态、归一尺寸和备注；
- 解析形成的版本快照在上述字段之外保存 `geometry`，这是后续 3D 预览和碰撞计算读取的唯一几何真相源；
- 当前 `status=normalized` 只能由显式 GLB 解析入口真实产出，上传和普通保存流程只能保存 `uploaded`；
- 当前注册表不会复制车型规格字段，车型规格库仍是种子车型主数据唯一来源；
- 上传源文件、注册模板和后续解析是三个阶段，不能把“文件已上传”误标为“几何已解析”。
- 上传资产目前采用“专用前缀 + 引用扫描”的生命周期：启动时和每日 03:30 清理超过 24 小时、且没有被当前模板或历史版本引用的模板源文件；
- 当前没有单独的上传资产登记表，清理任务只扫描 `vehicle-model-template-` 前缀文件，普通附件不会被纳入清理。

## 5. 边界说明

当前阶段，模板注册表只负责“源文件 + 种子车型 + 归一摘要”。

它不负责：

- 真实发货确认；
- 库存过账；
- 销售订单提交；
- 装车结果落库为正式出货。

装车页面仍然只是模拟与推荐，不进入真实出货链路。
