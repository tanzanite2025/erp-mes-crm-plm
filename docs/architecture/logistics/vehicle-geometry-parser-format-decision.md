# 车型几何解析格式决策

## 1. 决策结论

车型模型模板的上传、解析、归一化和浏览器预览，长期只支持一种源格式：

> `GLB（glTF 2.0 Binary）`

不再把 STEP、STP、OBJ、STL、FBX、GLTF 等格式作为车型模板的并列输入格式。

这不是因为其它格式不能解析，而是因为本系统需要一个稳定、可验证、可缓存、可在 Rust 与 WASM 之间复用的几何输入协议。多格式并行会让单位、坐标轴、节点语义、材质、外部资源和容差处理都出现多套规则，最终无法保证车型模板的唯一真相源。

## 2. 为什么选择 GLB

### 2.1 一份文件，减少链路和攻击面

GLB 将场景、网格和二进制缓冲合并为一个文件，不需要额外的 `.bin`、纹理目录或相对路径资源。

这适合当前受控上传入口：

- 上传接口只接收一个文件；
- 服务端可以对单文件做大小、魔数、结构和资源数量限制；
- 不需要递归解压或追踪外部资源；
- Redis、对象存储和临时目录不会因为资源链扩散而被拖垮。

### 2.2 解析器、预览器、WASM 使用同一条路径

GLB 既能作为 Rust 解析器的输入，也能直接作为浏览器 3D 预览的输入。解析后的标准几何还可以缓存为 `vehicle-geometry.v1`，后续装箱计算不需要每次重新读取源文件。

```text
GLB
  -> Rust 结构校验
  -> Rust 几何归一化
  -> vehicle-geometry.v1
  -> Rust 碰撞 / 装箱核心
  -> WASM / WebGL 预览
```

### 2.3 可以承载车型语义

车型装箱不只需要三角面，还需要知道哪些部分是：

- 可用装载空间；
- 轮包、凸起等障碍物；
- 门洞；
- 禁放区；
- 安全边界。

GLB 的节点层级、节点名称和 `extras` 可以承载这些受控语义。解析器不再“猜”某个任意网格是不是轮包，而是要求模型按本项目导出规范标记。

## 3. 为什么暂不选择其它格式

### 3.1 STEP / STP

STEP 更接近 CAD 的精确几何，适合保存 B-Rep、曲面和装配信息。但它不适合作为当前 Rust/WASM 的第一输入格式：

- 解析依赖 CAD 内核、曲面拓扑和装配语义；
- 纯 Rust、可在浏览器 WASM 内稳定运行的完整解析路径不成熟；
- 服务端解析和浏览器解析会变成两套实现；
- 文件通常更大，解析耗时和资源峰值更难控制；
- 最终预览和碰撞仍然需要先离散化为网格或碰撞体。

如果将来确实需要 CAD 级曲面精度，应另建服务端 CAD 转换边界，不把 STEP 直接塞进当前 WASM 装箱引擎。

### 3.2 OBJ

OBJ 容易解析，但缺少稳定的单位、场景元数据和受控节点语义，常常还需要配套 MTL/纹理文件。它不适合作为车型空间和障碍物的唯一来源。

### 3.3 STL

STL 只有三角面，缺少部件名称、装配层级和业务语义。它可以表达形状，但不能可靠表达“这是可用空间还是轮包”。

### 3.4 GLTF

GLTF 的 JSON 文件通常需要额外的二进制和资源路径。为了避免多文件上传、外部 URI 和路径安全问题，本项目只接受打包后的 GLB，不接受分离式 GLTF。

### 3.5 FBX

FBX 的解析、版本兼容和授权生态不适合作为本项目长期唯一输入。继续支持它只会增加格式适配和测试矩阵。

## 4. 本项目 GLB 导出规范

从 UG/NX 或其它建模软件导出 GLB 时，必须遵守以下规则：

### 4.1 文件级约束

- 只接受 GLB 2.0 Binary；
- 禁止外部 URI 和外部缓冲；
- 禁止动画、蒙皮、Morph Target、纹理和材质作为装箱计算输入；
- 文件大小保持在车型模板专用上限内，当前为 8MB；
- 节点、网格、顶点、索引数量必须有服务端上限；
- 所有数值必须是有限数，禁止 `NaN`、`Infinity` 和异常尺度。

### 4.2 节点语义约束

用于装箱计算的节点必须在 `extras.xdfc` 中声明：

```json
{
  "xdfc": {
    "kind": "usable-space",
    "collision": "aabb",
    "unit": "mm"
  }
}
```

`kind` 只允许来自解析协议定义的集合：

- `usable-space`
- `obstacle`
- `keep-out`
- `door`
- `reference`

解析器只读取受控语义，不根据颜色、材质或节点显示名称猜业务含义。

### 4.3 单位和坐标

- 输入统一按 GLB 场景的米制解释；
- 归一化输出统一使用毫米；
- 输出固定长度轴、宽度轴、高度轴；
- 原点、轴向和包围盒必须在解析阶段确定；
- 解析结果必须记录源文件摘要和归一化警告。

## 5. 解析阶段的边界

第一阶段只做：

1. GLB 文件结构校验；
2. 节点和网格读取；
3. 单位、坐标轴和原点归一化；
4. 语义节点校验；
5. AABB 包围盒生成；
6. 可用空间、障碍物和禁放区输出；
7. 生成 `vehicle-geometry.v1`。

第一阶段不做：

- 任意 CAD 曲面重建；
- 自动猜测轮包；
- 真实曲面级碰撞；
- 装箱搜索；
- 前端渲染；
- 发货或库存写入。

## 6. 版本和状态

```text
uploaded
  -> parsing
  -> normalized
  -> rejected
```

只有 Rust 解析器成功生成并通过校验的 `normalized` 模板，才允许进入真实碰撞或 3D 预览。

`uploaded` 只代表文件已保存，不能代表几何有效。

## 7. 后续实施顺序

```text
GLB 导出规范
  -> Rust GLB 解析器
  -> vehicle-geometry.v1
  -> 模板版本快照
  -> Rust AABB 碰撞核心
  -> WASM 适配层
  -> 3D 预览弹窗
```

当前不实现多格式适配器，不为 STEP、OBJ、STL、FBX 保留候选解析入口。
