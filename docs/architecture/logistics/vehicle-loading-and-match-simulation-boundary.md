# 车型匹配与装车模拟边界说明

## 1. 文档目标

本文档只说明一件事：`/logistics-config/vehicle-loading` 和 `/shipping-management/vehicle-match` 是“模拟与推荐”链路，不是最终发货链路。

它们的职责是把包装规则、车型规格、销售侧待发货数据和装车约束组合起来，给人看方案、看装车图、看推荐结果。

## 2. 核心结论

1. 装车计算是推荐，不是发货确认。
2. 车型匹配是辅助决策，不是仓库过账。
3. 如果后续需要保存结果，只能叫“方案草稿”或“模拟方案”，不能叫 shipment commit、出库确认、最终发货。
4. 最终是否发货，由销售侧决策；仓库只提供数据和模拟视图，不做闭环确认。

## 3. 当前数据链路

```text
销售订单行 / 待发货条码池
  -> 虚拟发货仓读取
    -> 车型匹配页 /vehicle-match
      -> 读取待匹配条目
      -> 打开车型库查看弹窗
      -> 调用推荐结果

包装管理中的包装规则
  -> /logistics-config/vehicle-loading
    -> 读取包装规则
    -> 读取车型规格库
    -> 返回装车推荐和示意图
```

## 3.1 推荐计算输入契约

推荐接口只接收以下业务标识和数量：

- `boxes`：本次模拟箱数；
- `packagingProfileId`：包装管理中的包装规则 ID；
- `vehicleSpecIds`：车型规格库中的车型 ID 列表。

后端根据这些 ID 重新读取包装规则和车型规格主数据，再执行计算。浏览器提交的尺寸、重量、载重和车型对象不作为计算真相源。

推荐结果中的朝向必须携带完整的长轴、宽轴、高轴映射以及旋转后的三维尺寸，不能只传一个“朝向轴”。

推荐计算只读取车型规格的几何与装载约束，不读取车型照片、页面展示图、说明卡片等展示数据。车型照片链路异常时，不能拖垮装车计算。

## 4. 页面职责

### 4.1 `/logistics-config/vehicle-loading`

- 只负责装载 / 配车计算；
- 车型主数据独立于“车型规格库”；
- 输入只认包装管理中的包装规则；
- 不使用手工箱型作为唯一来源；
- 不参与真实出库提交。

### 4.2 `/shipping-management/vehicle-match`

- 从虚拟发货仓读取待匹配条目；
- 打开车型规格库查看或对照；
- 展示车型推荐结果；
- 只承载模拟装车与预览；
- 不做仓库最终确认。

## 5. 明确禁止的语义

以下说法在当前阶段都不应该再出现在这条链路里：

- 仓库确认发货；
- 车型匹配提交出库；
- 装车推荐直接落真实出库；
- simulation 页面直接扣减库存；
- 把虚拟发货仓写成真正的库存出库仓。

## 6. 与库存域的边界

库存域的 `commitShipment`、`ShipmentRecord`、`VoidShipment` 仍然只属于库存内部真实出入库流程。

它们和本说明中的车型匹配 / 装车推荐链路是两条不同的线：

```text
库存真实出入库
  -> inventory

车型匹配 / 装车模拟
  -> logistics-config / shipping-management
```

两者可以共享部分包装规则或车型主数据，但不能共享“最终发货确认”语义。

## 7. 后续扩展建议

如果以后要保存模拟结果，建议新增独立对象：

- `LoadingSimulationDraft`
- `VehicleMatchPlan`
- `ShippingRecommendationSnapshot`

不要直接复用 `Shipment`、`ShipmentRecord`、`commitShipment` 这种容易把模拟和真实出库混在一起的名字。
