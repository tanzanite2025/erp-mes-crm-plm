## 1. 决策摘要

### 1.1 产线管理 TAB 的最终归属

`产线管理` 与 `产线脑图` 当前都围绕同一份 `/production/lines` 数据工作，并且都能修改产线层级。两者长期并存会造成：

- 用户不知道应该在哪个页面维护产线；
- 同一条产线出现两套编辑入口；
- 权限、搜索、最近访问和路由目录需要同时维护；
- 后续委外、工序转移、产能分析无法确定哪个页面是产线结构的权威来源。

最终决策：

```text
产线脑图 = 产线主数据 + L1 产品模板关联 + L2 有效生产 MBOM 分支 + L3 分支工序的唯一维护入口
```

独立的 `产线管理` TAB 应删除，而不是保留空壳、跳转页或兼容入口。

### 1.2 删除前的必要前置条件与当前状态

迁移前，脑图缺少以下产线基础操作；这些能力已在本次迁移中补齐：

- 新增产线；
- 编辑产线名称、编码、描述；
- 启用/停用产线；
- 删除产线；
- 产线级操作菜单；
- 生产拓扑模板维护入口，支持实际 L1 生成独立模板及模板创建新 L1；不自动同步实际结构。

这些前置条件已在 `产线脑图` 迁移中完成，旧 `line` 路由也已删除。实施顺序记录如下（均已完成）：

1. 先将产线基础操作迁入脑图工具栏或“当前产线操作”菜单；
2. 补齐脑图对应的权限状态、确认弹窗和空数据状态；
3. 验证脑图成为完整的产线管理入口；
4. 删除 `line` TAB、旧路由、搜索项、权限目录项和旧菜单引用；
5. 重新生成路由目录与权限索引；
6. 运行前端构建、后端测试和路由/权限一致性检查；
7. 最后再进入委外功能设计与实现。

当前进度：步骤 1 到 6 已完成并提交，生产路线、条码状态、工序执行基础骨架、委外单位档案、委外任务、收发检验、质量路由、委外消息中心事件源/通知编排、通知失败日志与人工重试恢复、跨域读写契约和移动端验收均已落地；PDA、Web、USB 生产入口均已复用统一扫码客户端，Web/USB 独立执行页为 `/production-execution`；委外专项设计已迁入 `docs/architecture/生产委外执行链路设计.md`。当前收发检验已复用统一扫码事务。委外不另建单位与工序的能力映射，产品当前工序只认一维码状态中的 `routeStepId`。

## 4. 重复职责与长期风险

### 4.1 重复职责

旧 `line-mgmt` 和 `line-mindmap` 都：

- 读取 `/production/lines`；
- 展示产线与层级；
- 修改产线拓扑；
- 触发版本更新；
- 受生产域权限保护。

差异仅在呈现方式和脑图的分支工序配置操作。继续保留两个页面会让同一份拓扑出现“双写入口”。

### 4.2 当前保存模型的风险

`SaveProductionLine` 会按整棵层级树保存，并删除不再提交的关联节点。该模式可以保证一棵树的整体一致性，但要求：

- 所有写入都携带最新 `version`；
- 任何页面都不能只提交局部旧快照；
- 脑图和未来委外页面不能直接修改产线拓扑；
- 发生 409 时必须让用户重新读取，而不是静默覆盖。

因此脑图成为唯一拓扑写入口后，版本冲突更容易定位，长期稳定性更高。

### 4.3 权限风险

旧独立产线入口涉及的配置位置已完成清理；当前维护以下文件，避免再次登记已删除的 `/production-architecture/line`：

- `src/features/authz/data/authenticated-route-catalog.ts`
- `src/features/authz/data/route-permission-labels.ts`
- `src/components/layout/data/search-data.ts`
- `src/features/production-architecture/tab-config.ts`

旧 `line.tsx` 路由已删除，当前页签仅保留 mindmap、topology、routes；路由、搜索和权限目录应与这些真实入口保持一致。

后端的权限边界仍应保留：

- 读取产线：生产配置菜单权限；
- 修改拓扑：`action_production_line_update`；
- 新增/删除产线：管理员权限；
- 拓扑敏感操作：`topology_auth_password` 二次授权。

## 5. 产线唯一入口的目标结构

```text
生产管理
└─ 生产协同
   └─ 生产架构
      ├─ 产线脑图（唯一产线管理入口）
      │  ├─ 产线选择与搜索
      │  ├─ 新增产线
      │  ├─ 编辑产线资料
      │  ├─ 启用 / 停用
      │  ├─ 删除产线
      │  ├─ 新增 / 编辑 L1、L2、L3 节点
      │  ├─ L2 有效 MBOM 分支关联
      │  └─ L3 分支工序维护
      └─ 拓扑模板维护（独立快照、单向复制新 L1）
```

脑图工具栏建议分为三组，避免按钮继续堆叠：

1. **产线选择**：搜索、切换当前产线；
2. **产线操作**：新增、编辑、启停、删除、模板；
3. **结构操作**：新建 L1/L2/L3 节点、编辑当前节点。

产线资料弹窗与节点编辑弹窗必须区分：

- 产线资料：名称、编码、描述、状态；
- 节点编辑：L1 产品模板关联、L2 MBOM 分支关联、L3 分支工序维护。

## 7. 委外/外协的长期领域边界

产线入口收敛后，再设计委外。委外不是采购订单的附属页面，也不是供应商资料的另一个别名；它是生产执行在某个工序节点上的外部执行方式。

### 7.1 领域归属

```text
生产管理
├─ 计划中心
├─ 生产协同
│  └─ 生产架构 / 产线脑图
└─ 委外管理
   ├─ 委外基础
   │  ├─ 委外单位
   │  └─ 委外协议/价格
   └─ 委外执行
      ├─ 委外任务
      ├─ 发出
      ├─ 在外
      ├─ 回收
      └─ 委外检验
```

委外属于生产管理域。采购域可以维护结算、付款和供应商合作信息，但不能拥有“某个产品当前处于哪个生产工序”的事实。

### 7.2 产品、一维码、账号权限与产线必须分开

| 对象                              | 原因                                                                             |
| --------------------------------- | -------------------------------------------------------------------------------- |
| `Product`                         | 产品主数据和产品规则来源，可用于打印生成一维码，但不保存某个一维码当前在哪道工序 |
| 产品一维码                        | 由产品/订单打印发号产生，可反查产品；生产执行把当前工序状态绑定到一维码          |
| `ProductionBOMBranchOperation`    | 当前脑图 L3 分支工序；现有路线中的 `ProcessStep` 引用待迁移，不承载人员授权     |
| 账号权限 / 命令权限               | 决定某个账号是否能打开页面、点击按钮或执行扫码命令，属于权限系统                 |
| `Position` / `EmployeeAssignment` | 组织人事资料，可用于人员档案展示，不参与生产扫码或工序执行授权                   |
| `ProductionLine` / `LineSegment`  | 产线和工段主数据，只描述生产结构，不保存操作人状态                               |
| `Supplier`                        | 供应商适合采购合作方，不能自动代表生产执行事实                                   |
| `EquipmentPartner`                | 设备/工装合作方与生产加工委外不是同一事实                                        |
| 裁纱卷材绑定                      | 裁纱与卷材追溯是独立模块，不能成为后续生产或委外的硬前置                         |

一维码的最短执行链路固定为：

```text
产品/订单行
  → 打印生成一维码
  → 扫码反查产品
  → 按活跃执行批次读取计划已绑定的路线修订
  → 读取一维码当前工序状态
  → 扫码账号
  → 页面/命令/动作权限校验
  → 工序执行或转移事件
```

这条链路只读取所需的计划产品与 MBOM 分支身份，不加载整张计划任务明细、库存或卷材追溯数据。其他领域通过明确 ID 或产品一维码关联。

绑定错误时，必须能从一维码直接查到：

- 对应的产品；
- 当前工序；
- 最近一次状态事件；
- 操作账号；
- 关联路线版本。

当前已落地基础状态链：

```text
product_barcode_states
  └─ product_barcode_state_events
```

该链路以一维码为锚点保存当前工序状态和事件历史。HTTP 初始化不接受路线或工序身份；首次生产扫码读取计划已绑定的路线修订并写入首个路线步骤，后续执行按条码状态定位当前工序。卷材绑定不是生产扫码前置。

`production_execution_lots` 将产品码关联到必填的生产计划，任务和批次号可选。活跃执行批次及其计划是生产扫码解析 MBOM 分支的前置条件；计划已有批次或已开始执行后禁止改分支。

当前已落地 `production_operation_executions`，用于记录某个产品码在某个工序上的开始、完成、暂停或返工动作。该服务只校验工序、路线、批次等生产事实；是否允许调用扫码、按钮或接口，由账号/人员权限体系在入口侧处理。写入成功后会同步写入一维码状态事件。

当前已落地统一扫码命令入口：

```text
POST /production/scan-commands/execute
```

该入口是 Web、PDA、USB 扫码的统一后端命令层，复用 `action_production_issuance_execute` 动作权限，不从工序或人员档案推导授权。客户端提交条码、动作及作业地点等执行信息；服务端按活跃批次读取计划固定的路线修订，再从条码状态与路线步骤确定当前工序，完成后按路线 `sequence` 推进下一步骤。独立的 `POST /production/operation-executions` 已移除，执行事实通过统一扫码命令写入。

当前已落地转移事件基础表：

```text
product_barcode_transfer_events
```

它用于记录路线推进和可选持有方变化，不等于委外发出/回收业务状态机。当前委外发出、回收、在外、回收待检和检验处置已由委外执行首期链路承接，并在同一事务中写入对应执行事实。

当前已经落地 `OutsourceOrder` / `OutsourceOrderLine` 任务骨架，以及 `OutsourceTransfer` / `OutsourceInspection` 收发检验首期链路。它支持从销售订单或生产计划创建委外任务，销售订单和生产计划只作为来源快照；委外任务自己保存委外单位、数量、来源产品快照、计划发出/返回日期和状态，创建时不手工绑定 L3。因此“销售订单 500 件，本厂做不过来，直接开始委外”目前已有基础登记入口。B5 中只有扫码产生的委外发出/回收、检验等执行事实记录当时的 `branchOperationId`；计划行不保存该字段，避免任务创建时预选或固化 L3。

委外任务行不手工选择 L3。L3 属于分支路线定义；一个产品当前处于哪个工序，由条码状态的 `routeStepId` 和对应路线步骤的 `branchOperationId` 表达。扫码发出/回收及回收检验从条码当前路线步骤取得该分支工序身份并写入执行事实，而不是在委外页反向修改产线脑图或工序库。

当前已经形成“下发 → 发出 → 回厂 → 检验 → 关闭”的基本流转：发出/回厂写入 `OutsourceTransfer` 和 `product_barcode_transfer_events`，委外专用库存适配器在同一事务中更新 `Inventory` 并写入成对的 `InventoryLedgerEntry`，回厂检验先创建/领取带委外行与产品码来源绑定的正式 `InspectionTask`，再在同一事务内写入 `OutsourceInspection`、完成品质任务并调用统一扫码命令推进条码；失败、返工、让步和报废会在品质域留下 `QualityAbnormality`，委外域不直接承担后续审批。下达、作废、发出、回厂、检验处置和关闭也会通过 `PRODUCTION_OUTSOURCE` 事件源进入消息中心规则编排；通知收件、执行记录和刷新队列与业务同事务写入，发布失败关联原任务，执行日志页只恢复该原任务；仓储/品质/采购/裁纱的跨域读写契约已经明确，通用库存出入库会拒绝 `PRODUCTION_OUTSOURCE` 专用来源。路线步骤可配置质量处置目标，未配置时保持顺序推进或当前步骤返工的默认行为。

### 7.4 状态必须拆开

委外设计不能只用一个 `status` 解决所有问题，至少要区分：

| 状态维度 | 示例                                                                        |
| -------- | --------------------------------------------------------------------------- |
| 工序状态 | `NOT_STARTED`、`IN_PROGRESS`、`COMPLETED`、`HOLD`                           |
| 委外状态 | `DRAFT`、`RELEASED`、`SENT`、`IN_PROCESS`、`RETURNED`、`CLOSED`、`CANCELED` |
| 质量状态 | `PENDING`、`PASSED`、`FAILED`、`CONCESSION`、`REWORK`                       |
| 持有位置 | 本厂产线、待发区、委外单位、回收待检区、合格区、不合格区                    |

“产品到了路线的哪个具体作业”由一维码的 `routeStepId` 和状态事件表达；B5 完成后，当前/前后工序身份统一使用 `branchOperationId`。“这次操作是否完成”由工序执行记录表达；“东西由谁持有或移交到哪里”由独立转移事实表达；实际作业地点使用 `ProductionWorkLocation`，不复用 L2、工序、持有方或品质检验站身份；“是否允许进入下一道工序”由工序完成和质量判定共同决定。

工序与账号权限的关系必须分开：

```text
ProductionBOMBranchOperation
  └─ 保存当前脑图 L3 的分支工序定义

ProcessStep（当前路线模型，待迁移）
  └─ 保存现有路线引用的作业定义

账号
  └─ 页面权限 / 命令权限 / 动作权限
```

不允许把员工、账号或人员授权写进产线层级，也不允许通过产线节点推断操作人。组织人事域负责人员资料和组织归属；生产执行链路只记录操作账号。

### 7.5 委外执行链路

```mermaid
flowchart LR
  A["产品/订单行"] --> B["打印生成一维码"]
  B --> C["当前工序状态"]
  C --> D["扫码账号"]
  D --> E["账号权限校验"]
  E --> F{"本厂执行 or 委外执行"}
  F -->|本厂| G["工序执行记录"]
  F -->|委外| H["委外任务"]
  H --> I["发出转移"]
  I --> J["委外单位在制"]
  J --> K["回收转移"]
  K --> L["委外检验"]
  L -->|合格| M["下一路线工序"]
  L -->|不合格| N["返工/让步/报废"]
```

委外任务创建只绑定来源订单/计划、委外单位和数量；委外执行动作必须扫描产品一维码并读取其当前 `routeStepId`，不允许在任务表里手填或预选 L3。当前发出、回厂和检验接口会校验条码状态存在、产品和当前工序匹配，并将事实写入独立流水。

委外库存只表达物理数量和在制持有位置，不拥有委外状态机或产品工序状态。发出时由专用适配器把来源库区数量转入系统库区 `PRODUCTION_OUTSOURCE`；回厂时从该库区转出到明确目标库区。每次动作必须在一个数据库事务内同时写入：

```text
OutsourceTransfer
ProductBarcodeTransferEvent
Inventory
InventoryLedgerEntry (OUT + IN)
```

产品快照先经过产品到物料解析器映射到库存物料，不能把 `ProductID` 直接当作 `MaterialID`。通用仓储出入库、库存调拨、批量同步、负库存对账和作废接口不能写入 `PRODUCTION_OUTSOURCE`。委外页面读取库区选项时走生产域只读投影，不要求委外操作员额外拥有仓储菜单权限。

### 7.6 一维码与裁纱边界

产品、一维码和裁纱/卷材追溯是三个独立事实：

- 产品主数据只描述产品本身；
- 一维码由产品/订单打印产生，可反查产品，并承载当前工序状态；
- 产品只要完成必要的一维码/产品绑定，就可以进入后续下单和生产流程；
- 是否绑定卷材、是否完成裁纱计算，不得成为普通生产或委外的强制阻断条件；
- 裁纱结果可作为追溯、自动切割和后续质量分析的补充事实；
- 委外系统只能引用裁纱追溯信息，不能反向要求所有产品必须先绑定卷材。

一维码绑定错误必须通过一维码、产品引用和状态事件快速发现，不能依赖卷材、库存或整张生产计划才能判断。

这是生产执行和裁纱引擎之间的硬边界，必须在后续接口契约和验收用例中明确。

## 10. 最终验收原则

### 产线架构

- 一个产线只有一个维护入口：产线脑图；
- 产线资料与产线拓扑在同一领域内，但弹窗职责分离；
- 所有写入共享同一版本、授权、审计和缓存链路；
- 删除旧路由后，搜索、权限、侧边栏和最近访问不再出现旧入口；
- 不保留兼容跳转和旧连接。

### 委外/外协

- 委外任务创建不预选 L3；发出、回收和检验必须以扫描的一维码当前状态为准；
- 工序状态、委外状态、质量状态、持有位置互不混淆；
- 产品、一维码、账号权限和产线工序互不混淆；
- 委外单位不是简单复制采购供应商；
- 委外回收必须经过质量判定才能进入下一工序；
- 委外发出/回厂同时留下委外转移、条码持有方、库存余额和库存流水事实；
- 委外专用在制库区只能由委外专用适配器写入，委外页面不绕过生产域调用通用仓储写接口；
- 裁纱/卷材追溯不会阻断未绑定产品进入正常生产链路；
- 生产、采购、品质、仓储和裁纱分别拥有自己的事实所有权。

> 当前状态：产线唯一入口迁移已完成。L1 关联产品侧模板，L2 直接绑定有效生产 MBOM 分支，L3 为分支独立工序；生产位置使用独立身份。阶段 G 已使路线按销售订单明细或分支默认范围匹配，并在排产时绑定当前已发布修订；扫码和委外继续校验并使用该固定修订及来源身份。同码复检轮次和返工后重复委外周期已实现并通过服务回归。阶段 G 的新代码尚未完成目标部署；目标数据库结构核对和部署后业务验收待部署完成后进行。
