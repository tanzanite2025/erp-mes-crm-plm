# 生产工序库独立配置与 L2 分支选配设计

更新日期：2026-11-20。

## 1. 需求与现状

工序先在独立工序库维护。L2 可以选配需要的工序，脑图 L3 展示该 MBOM 分支的工序；生产路线 TAB 也可以直接选择工序库条目，并由服务端为该分支建立或复用同一 L3 身份。路线配置不依赖先在 L2 选配。工序库同时提供生产架构下的独立 TAB 和可供其他页面调用的配置弹窗，两种入口操作同一份服务端数据。

现有全局 `ProcessStep` 已有编码、名称、说明、显示顺序和启用状态，以及 `/production/processes` 查询、保存和删除接口；原配置面板内嵌在人事“作业架构”中。脑图 L3 仍是分支内独立维护的 `ProductionBOMBranchOperation`，现在通过独立的 `ProductionBOMBranchOperationProcessLibrarySelection` 保存工序库来源，不把工序库 ID 冒充 L3 或路线执行身份。

## 2. 配置入口与组件边界

- 生产架构增加“工序库”TAB，路径 `/production-architecture/process-library`。工序库不依赖 L1、L2、拓扑模板或路线，用户可以先维护工序。
- `ProductionProcessLibraryConfigurationContent` 负责列表、查询、新建、编辑、启停和删除，编辑表单内嵌，既不包含页面布局也不绑定 Dialog、路由或父页面状态。
- `ProductionProcessLibraryConfigurationPage` 只增加页面标题并承载共享内容；`ProductionProcessLibraryConfigurationDialog` 只增加弹窗、滚动区及关闭保护，并承载同一个内容组件。
- 弹窗允许调用方传入 `onProcessSaved`，返回服务端保存的工序。调用方可刷新候选或定位新工序；配置组件不得擅自替调用方关联 BOM、修改选配草稿或保存路线。
- 查询使用既有工序 query key；成功后写入服务端确认的数据并通知查询缓存，TAB、弹窗和选择器读取同一数据。读取失败显示具体错误与重试，不能伪装为空清单；保存失败保留草稿并允许重试。
- 写权限沿用接口的 `perm_manage`，只读权限不显示写操作；嵌入到其他页面不能扩大访问权限。没有生产配置读取权限时不发起工序查询。
- 保存期间阻止重复提交、切换编辑对象和关闭弹窗；未保存草稿关闭时需明确放弃确认。窄屏可滚动，列表和表单无横向溢出。
- 原人事作业架构直接使用共享内容，撤销重复的旧配置面板及其独占 hook；不保留另一套配置逻辑。

## 3. L2 选配与路线边界

后续选配以稳定 MBOM 分支身份为归属，以工序库 ID 为被选对象，不按名称匹配。必须保存“分支—工序库”的明确关联；不能继续只复制名称、说明而缺少来源身份，也不能把全局工序 ID 冒充已有 `branchOperationId`。

同一工序可以被多个 MBOM 分支选用，同一分支的重复选配要拒绝。某个 L2 调整选配不能改动其他 MBOM 分支；同一稳定 MBOM 分支在不同 L1 下的 L2 显示同一选配结果。工序库新增或编辑不自动替任何分支建立选配，不发布或覆盖路线。

L2 选配与路线选工序都将工序库条目关联到稳定 MBOM 分支，并使用该分支独立 L3 身份；L2 配置和路线草稿分别维护。生产路线决定实际执行工序子集、顺序、质检和委外要求。分支局部显示顺序与路线步骤顺序分别维护，不放进全局工序定义。路线发布后才控制执行，不能在勾选工序或保存草稿后隐式发布。已发布路线及当前/历史执行事实的引用保护必须继续有效。

工序库名称、说明和顺序的修改不覆盖既有 L3 快照，也不改写已发布路线或历史事实；启用状态修改只允许在没有分支选配引用时停用。删除/停用已被选配的工序由服务端校验并返回引用冲突；配置 UI 不能替代该保护。本轮配置入口继续使用现有工序接口，不写分支、路线或执行事实。

### F2 关联契约（已冻结并实施）

F2 新增的分支选配关系必须保存稳定 MBOM 分支身份与工序库记录 ID：

```text
ProductionBOMBranchOperationProcessLibrarySelection
  branchIdentity = productId + bomOwnerType + bomOwnerCustomerId + bomVersionLevel
  branchOperationId -> ProductionBOMBranchOperation.id
  processLibraryId -> ProcessStep.id
```

`ProductionBOMBranchOperation.id` 继续是 L3 及路线步骤引用的独立执行身份；关联表中的 `processLibraryId` 表示该 L3 来自哪个工序库记录，不能把工序库 ID 直接作为 `branchOperationId`。同一工序库记录可以被多个稳定 MBOM 分支选用；同一分支对同一工序库记录只能存在一条有效关联，服务端以数据库唯一约束和事务内校验双重保证。L2 只提交要保留的工序库 ID 集合，服务端按稳定分支身份重新读取有效 MBOM，并原子新增、保留、取消选配；路线保存也按稳定身份建立或复用同一关联。两条入口都不能接受客户端传入的产品名称、工序名称或其他分支的 L3 ID 作为归属依据。

创建关联时可以把工序库的名称、说明作为 L3 初始显示内容写入分支工序快照；这只是创建时的初始值，必须同时保存 `processLibraryId`，不能以名称匹配或名称复制结果代替关联身份。L3 的名称、说明、显示顺序和启停仍可在该分支下独立维护；修改 L3 不回写工序库，修改工序库也不静默覆盖已有 L3 快照。路线读取 L3 的独立 ID，并校验其 MBOM 分支归属及工序库记录当前启用。

L2 调整选配只影响当前稳定 MBOM 分支及其全部 L1 显示，不修改其他分支的选配、L3、路线或执行事实。取消选配前由服务端检查草稿/已发布路线及执行引用：已有发布或执行引用时返回业务冲突，保留关系并要求先处理路线；无引用时原子移除该 L3。工序库停用/删除保护与分支选配保护分别由服务端维护，配置弹窗不越权修改选配。

工序启用状态以本次显式保存值为准，包括新建时选择停用；不能被数据库模型的默认启用值覆盖。该校验属于工序库配置接口本身，不修改分支选配或执行身份。

F2/F3 验收覆盖：L2 选配的跨分支隔离、同分支重复 ID 拒绝、选配替换、取消引用保护；L3 编辑保存时保留来源关系；路线可直接选择工序库条目并建立或复用当前分支 L3，保存和发布校验其归属及启用状态；关联中的工序库工序停用或删除返回引用冲突；前端选配保存失败保留草稿并允许重试，保存期间阻止重复提交。运行时将关联表作为必需结构，不再因缺表退回无来源身份路径。选配写入锁定产品主记录及工序库行，工序库停用/删除也先锁定相同工序行，防止并发事务留下已停用但仍被关联的工序；同分支并发替换按产品行串行化。
