# APS 排产引擎 - 动态事件修正

## 1. 目标

本文件用于描述排产计划如何根据现场事件动态调整。

## 2. 事件来源

### 2.1 条形码事件

用于判断：

- 人员是否到岗
- 是否在休息日实际开工
- 某班次是否真的发生

### 2.2 设备事件

用于判断：

- 设备开机
- 设备停机
- 设备故障恢复
- 设备维护结束

### 2.3 物料事件

用于判断：

- 是否缺料
- 物料是否补齐
- 某订单是否可继续排产

### 2.4 人工调整事件

用于处理：

- 紧急插单
- 手工改排
- 管理员锁定计划

## 3. 调整方式

### 3.1 局部修正

只调整某条线、某一天、某一个订单段。

### 3.2 触发重排

当事件影响范围较大时，重新计算一段时间内的排产。

### 3.3 版本更新

每次调整都保存一个新版本，便于追踪差异。

## 4. 条码驱动的特殊场景

如果本来是休息日，但条码记录显示有人上班，则系统应：

1. 标记当天为“可用工时变化”
2. 更新当天产能
3. 必要时触发局部重排
4. 保留事件记录和原因

## 5. 简化原则

第一版先不要做太复杂的智能推理，只做：

- 事件记录
- 产能变化
- 局部修正
- 重排触发
