# APS 排产引擎 - 数据模型

## 1. 目标

本文件用于描述排产引擎的基础对象，先把“排什么、排给谁、什么时候排”定义清楚。

## 2. 核心对象

### 2.1 Order

订单是排产的入口对象，至少包含：

- 订单号
- 客户
- 交期
- 优先级
- 数量
- 状态
- 是否允许拆分

### 2.2 Route / Process

订单需要映射到生产域的已发布工艺路线修订 `ProductionRoute`，路线步骤使用 `ProductionRouteStep`。当前路线模型包含：

- `processStepId`：工序库中的正式工序身份 `ProcessStep.id`
- `sequence`：路线工序顺序
- `estimatedMinutes`：每道路线工序的预计耗时
- `executionMode`：本厂或委外执行方式
- `qualityGate`、质检路由及交接要求

产品分类树第三级 `ProductType` 是产品归类和展示标签，不单独决定工序或排产。现有主数据通过 `Product.typeId` 与 MBOM `productId` 校验分类归属；订单界面可以把分类与有效 MBOM 稳定分支作为可读的销售生产组合上下文，但生产约束落在具体 MBOM 分支，分支中的 `productId` 不是订单上的独立产品选择。`ProductTemplate` 只定义产品规格字段，不参与工序身份。MBOM 分支预设默认工序及顺序；订单明细选择分支后默认继承该路线，只有对应 EMBOM 需要个性调整时，订单行才选择本单自定义路线。排产时 `ProductionPlan` 继承订单行的分支和路线方式，并固定实际采用的路线修订，已排产计划不因后续修改而改变。没有销售订单行来源的计划使用所选分支默认路线。`ProductionLine` 是独立产线主数据，由 EBOM 新建时单选关联，MBOM 沿 `SourceEBOMID` 展示来源产线；产线归属不决定 APS 资源或生产路线。订单行分支、自定义路线、计划路线修订绑定，以及 MRP/正式领料自动解析订单行唯一有效 MBOM 并阻断重复发布均已实现；连接实际浏览器 API 的端到端验收仍待完成，详见[生产线主数据与订单路线分阶段设计](../生产线主数据与订单路线分阶段实施设计.md)。

工程 BOM 的 `BOMSection` 只负责物料分类，不是 APS 的工段或工序来源。BOM 物料和路线步骤之间如果需要表达领料或消耗点，应通过独立的物料与工艺步骤关联，不应根据 `BOMItem.section` 猜测生产路线。

### 2.3 Production Resource

APS 资源模型属于后续设计，目前尚未定义产线主数据与产能资源之间的绑定。未来资源模型需表达排产依赖的生产能力，至少包含：

- 产线或工作中心
- 设备
- 人员
- 可用工时

实际扫码地点由生产域 `ProductionWorkLocation` 单独表达；地点身份不等于产线、MBOM 分支、MBOM 分支工序或路线步骤。资源与路线步骤之间的能力、时间及可选资源约束需要单独定义。

### 2.4 Calendar

日历用于表达可排产日期，至少包含：

- 工作日
- 休息日
- 法定节假日
- 临时加班日
- 停线日

### 2.5 Schedule Plan

排产结果对象，至少包含：

- 关联订单
- 关联产线
- 开始时间
- 结束时间
- 占用资源
- 排产版本
- 状态

### 2.6 Schedule Event

动态调整事件，至少包含：

- 条码记录
- 签到记录
- 到岗记录
- 设备状态变化
- 缺料
- 停机
- 人工调整

## 4. 简化原则

第一版先不要把模型做得太复杂，先保证：

1. 能描述订单
2. 能描述资源
3. 能描述日历
4. 能描述排产结果
5. 能记录动态事件
