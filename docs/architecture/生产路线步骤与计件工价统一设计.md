# 生产路线步骤与独立工资计算边界

更新日期：2026-11-26。财务只使用已有人员、部门和独立环节工价录入数量、计算工资。

> 文档状态：工资隔离规则继续有效。生产模型区分工序库身份、MBOM 分支允许工序和有序路线步骤。产品分类只用于识别和展示；产线是独立主数据，EBOM 记录所属产线，MBOM 沿来源 EBOM 展示；工序由 MBOM 分支配置维护。

工资唯一实施契约见 [`独立计件工资模块契约与实现边界.md`](独立计件工资模块契约与实现边界.md)。本文说明生产模型及生产、工资两域的职责边界。

默认工序顺序挂载在具体 MBOM 稳定分支上。产品分类只提供人员理解产品的归类标签，`Product.typeId` 用于校验和展示，不单独决定工序或路线。订单明细选择分类上下文和有效 MBOM 分支后默认继承分支路线；仅当该订单对应 EMBOM 需要个性调整时，订单行才选择本单自定义工序。路线配置直接选择订单行，路线名称和编号由系统生成。正式工序身份为工序库 `ProcessStep.id`，路线位置以 `routeStepId` 表示。产线归属是 BOM 的识别和展示上下文，不参与订单、计划、APS 资源或扫码执行。订单行路线方式、生产计划修订绑定，以及 MRP／正式领料自动解析订单行唯一有效 MBOM、对重复发布完整性异常阻断均已实现；浏览器连接实际 API 的端到端验收仍待完成，详见[产线与订单路线分阶段实施设计](生产线主数据与订单路线分阶段实施设计.md)。生产位置、工序和持有方分别建模；工资隔离契约保持不变。

## 1. 生产模型

```text
Product 产品
  -> 有效生产 MBOM 分支（产品、归属、性能版本）
    -> 允许使用的工序库身份（ProcessStep.id）
    -> ProductionRoute 路线
      -> ProductionRouteStep 路线步骤
        -> ProcessStep.id + 发布快照
```

工序库身份由分支关联、路线步骤和执行事实共同引用；`routeStepId` 表示特定路线中的有序位置。路线历史保存名称/说明快照。工资域不依赖这些生产身份。

生产计划继承订单行选定的分类展示上下文、MBOM 分支和路线方式，并保存排产时绑定的路线修订；产品码通过执行批次关联计划。扫码读取计划固定修订，客户端不选择批次、路线或当前工序；计划已有批次或执行事实后禁止更换分支或路线。没有订单行来源的计划使用明确选择的 MBOM 分支默认工序路线。

产线是独立 `ProductionLine` 主数据，一条产线可以关联多张 EBOM；MBOM 经 `SourceEBOMID` 展示来源产线。工序和路线步骤分别由 MBOM 分支配置及订单路线维护，与工资工价无关。

| 对象 | 文件 | 含义 |
|---|---|---|
| 产线 | `server/models/production_line.go` | 独立主数据；EBOM 单选归属，MBOM 沿来源 EBOM 展示 |
| 标准作业 | `server/models/production_process.go` | 可复用生产作业 |
| 路线与步骤 | `server/models/production_route.go` | 产品执行顺序及约束 |
| 生产执行 | `server/models/production_execution.go` | 生产动作、请求回执及轮次 |

## 2. 工资模型

```text
既有人员和部门 + 独立工资环节与工价 + 财务输入数量
  -> 工资计算明细
  -> 人员、部门汇总（分币种）
```

`PieceworkPayItem` 表示独立工资环节，`PieceworkRate` 表示该环节按单位和生效日期维护的工价。计算直接读取既有人事主数据，不能引用 `ProcessStep`、`ProductionRouteStep`、产品、条码、批次、BOM 或用料分配。

录错后修改输入、重新计算；无生效工价时直接报错。计算不会写入业务事实。

工价使用 `payItemId`、`unitPrice`、`currency`、`effectiveFrom/effectiveTo`、状态和行版本。工价区间与版本属于工资维护，生产路线版本属于生产，两者不关联。

## 3. 已有生产保护与后续生产事项

路线支持 `DRAFT/PUBLISHED` 业务修订：发布前重新校验分支和步骤，发布修订不能原地修改或删除；路线身份、独立业务修订号、历史快照和复制修订已实现。分支默认路线由 MBOM 分支工序及顺序物化；生产路线 TAB 仅维护订单行选择的本单自定义路线。订单明细选择和生产计划继承已实现。

生产 HTTP 执行和扫码要求自己的 `idempotencyKey`，回执与生产副作用同事务提交。同条码操作串行化，完工按条码、路线步骤、作业与轮次唯一；返工开启下一生产轮次。生产轮次不生成工资，生产请求不携带工资归属字段。

计划、批次产品与扫码路线之间的一致性校验已实现并通过隔离 PostgreSQL 测试。MBOM 分支工序配置执行路线引用保护；独立产线主数据、EBOM 单产线归属和 MBOM 来源展示已实现，服务及 SQLite 回归通过，PostgreSQL 专项回归尚未执行。工资计算不引用产线、工序或路线步骤。

## 4. 迁移与验证边界

生产回执和轮次迁移只处理生产表。工资迁移只维护独立环节和工价，不创建、迁移或推导工资报工及收付记录。业务库尚未执行本轮应用迁移。

2026-11-17，本地隔离 PostgreSQL 15 已通过生产身份迁移回滚、重复启动、MBOM 分支产品身份约束、计划/批次锁定及扫码并发重放验收；实际目标部署数据库的迁移与部署后验收尚未执行。命令及边界记录于分阶段实施设计。

工资计算与生产执行分别独立运行；生产扫码不依赖工资资料，工资计算也不依赖生产表。
