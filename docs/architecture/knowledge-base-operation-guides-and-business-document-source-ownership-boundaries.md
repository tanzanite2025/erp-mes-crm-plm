# 知识库、操作指南与业务文档的职责及内容来源契约

建立日期：2026-10-26。

本文是知识库、操作指南、字段帮助与业务文档之间的统一边界约定。适用于知识编辑、全局搜索中的知识结果、产品与 BOM 操作手册，以及后续业务域的说明入口。本文先确立长期规则；指南知识索引、结构化来源链接及章节定位仍需后续实现，不表示本次已上线。

## 1. 定义与内容归属

| 类型         | 用户要解决的问题                             | 承担的内容                                                   | 内容维护方                                                         |
| ------------ | -------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------ |
| 操作指南     | “这件事从头到尾怎么做？”                     | 前置条件、步骤顺序、填写解释、核对方法和业务入口             | 对应业务域，例如 `engineering`、`product-structure`                |
| 知识库       | “这是什么意思？为什么这样？遇到问题怎么办？” | 可搜索的问答、术语、规则解释、异常处理、说明图及相关来源链接 | 业务解释由所属业务域维护；企业自行编写的经验问答沿用知识库维护入口 |
| 字段帮助     | “这个字段怎么理解、怎么填？”                 | 当前上下文中的简短解释、示例和完整说明入口                   | 字段所属业务域                                                     |
| 业务文档主库 | “正式依据是哪份文件、哪个修订？”             | 文档身份、原始附件、修订、适用范围、关联、预览和下载         | 文档所属业务模块，例如工程技术规范归 `engineering-db`              |
| 仓库开发文档 | “系统如何设计、实现和维护？”                 | 架构、接口、部署、排查及验证依据                             | 对应开发维护方，保存在 `docs/**` 等仓库文档入口                    |

知识库中可以直接阅读知识条目自己的文字、截图和示意图片。说明图片用于解释概念或操作，不替代正式规范附件、图纸或文档修订。

涉及正式业务文件时，知识条目提供简短描述和原模块链接。原始文件的读取、预览、下载及修订管理继续由所属主库承接；知识库不上传或复制另一份 PDF、Excel、Word、图纸，不接入这些文件的独立查看器，也不把原文件地址当作长期来源链接。

仓库开发文档是维护依据。面向业务用户的知识须整理为适合其阅读的解释，不整份导入开发文档或暴露本地文件路径、环境配置及实现细节。

## 2. 知识条目的组织方式

一条知识围绕一个明确问题组织，先给出能够直接理解的答案，再提供必要的说明和去向。允许保留术语等陈述式标题，无需把全部已有标题改写为问句。

建议包含以下内容：

- 标题：使用用户会搜索的业务说法，例如“BOM 的成品重量在哪里填写”。
- 摘要：一两句话回答核心问题，搜索结果可直接显示。
- 正文：解释含义、适用范围、填写方法或排查步骤，按需附图。
- 关键词：常用名称、简称及合理同义词，例如“重量、成品重量、BOM、性能版本”。
- 来源与相关入口：完整指南、业务页面或原始文档主库中的记录，注明各自用途。

知识正文应足以回答该问题，不能只有一个无解释的跳转链接。指南则保留完整的步骤编排，不拆成互不关联的知识条目后替代原手册。

| 搜索问题                             | 知识库给出的答案                                                                                 | 进一步查看或操作                             |
| ------------------------------------ | ------------------------------------------------------------------------------------------------ | -------------------------------------------- |
| BOM 成品重量填在哪里                 | 重量和单位属于具体产品当前 BOM，与归属、性能版本及配方一起维护；物料用量不能直接相加当作成品重量 | BOM 指南的性能版本与重量章节、BOM 配方页面   |
| 研发 BOM 怎么转成生产 BOM            | 已发布且锁定的研发 BOM 可以派生独立的生产草稿，核对后发布；源研发记录保留                        | BOM 指南的生命周期章节、BOM 配方页面         |
| 归属中的内部生产和客户专供有什么区别 | 归属表示配方供谁使用，内部生产不指定客户，客户专供须选择实际客户                                 | 同一归属解释主题、完整 BOM 指南              |
| 某份工艺规范有什么用途               | 简述该规范的用途和适用范围，给出原主库记录入口；文件修订以主库实时记录为准                       | 工程技术规范主库，由主库展示原文件和当前修订 |

示例产品、重量和修订号须标明为示例。知识文章不保存某产品当前 BOM 重量、当前文档修订等业务记录副本；需要核对实际值时进入原模块读取。

## 3. 指南、字段帮助与知识搜索共用解释来源

同一业务含义只维护一份权威解释。业务域拥有解释主题，指南按步骤编排主题，字段帮助按上下文展示主题，知识搜索按用户的问题和关键词查找主题。

已有 BOM 主题定义、中英文词典、`BOMFieldBusinessMeaningExplanation` 与 `BOMFieldBusinessMeaningHelpPopover` 已为指南和字段帮助提供复用基础。后续接入知识搜索时，应消费主题的纯内容和来源元数据；搜索索引不依赖弹窗组件，不加载业务表单或保存 Hook。

主题身份使用稳定业务含义，例如“BOM 归属”，不依赖第几个 TAB、当前中文标题、展示位置或组件文件名。知识的问法和关键词可以有多个，均指向同一主题。共享适用范围、示例和限制时一并复用，避免搜索摘要与完整指南含义不同。

企业自行编写的经验、异常处理与补充问答继续使用现有知识条目，不要求每条内容都有指南来源。系统提供的指南解释与企业条目应能区分来源，避免把自动生成的主题副本与人工编辑内容混在一起覆盖。

指南或业务规则变更时，由所属业务域同时核对主题、摘要、示例、关键词和目标入口。索引是派生内容；需要保存索引副本时，须有明确的来源身份与更新方式，不能再形成一份独立维护的业务定义。第一阶段可以人工核对维护，不宣称已有自动同步。

## 4. 描述与链接的边界

| 链接用途     | 展示方式                                 | 目标负责的内容                   |
| ------------ | ---------------------------------------- | -------------------------------- |
| 完整指南     | “阅读完整 BOM 指南”等有业务含义的文字    | 原指南的章节和步骤               |
| 业务操作入口 | “前往 BOM 配方”等文字                    | 目标业务页面、校验与原有操作流程 |
| 原始业务文档 | “前往技术规范主库查看《规范名称》”等描述 | 原主库记录、修订、附件预览和下载 |

说明与链接分开：阅读答案不自动跳转，点击链接才进入原模块。知识库的业务入口只负责导航，不直接保存、发布、审批或打开另一套业务表单。指南中既有的主动操作入口仍复用原领域编辑器及权限，与知识阅读分别管理。

优先链接原模块的稳定页面或记录身份，不持久化本地路径、临时 blob、带时效的附件 URL，或用复制文件规避原主库入口。具体记录跳转只使用目标模块已支持的参数；目标未提供记录定位时，先进入主库页面，不自造 `documentId` 等未承接参数。

当前指南通过页内 Tabs 管理阅读章节，尚无统一的 URL 章节定位契约。现阶段链接进入完整指南页面；后续需要定位某章时，应由原指南公开稳定主题或章节参数，再由知识入口使用，不依赖不可见章节的滚动锚点或写死“第 3 个 TAB”。

内容可读、目标可访问和业务可操作分别判断。知识阅读不授予目标页面或文档权限；链接展示应按目标访问规则处理，原模块及后端继续执行权限校验。无权限、目标删除或读取失败时说明原因，不在知识详情内回退读取原始附件。一般知识正文避免混入只应在受限业务记录中展示的信息。

## 5. 搜索范围与文件职责

知识搜索的命中对象是知识条目或后续登记的解释主题，可以搜索标题、摘要、正文文本、关键词和相关入口信息。支持解释图文不等于识别图片内文字，也不表示对业务原始文件做全文检索；需要这些能力时须由文件所属模块另行定义。

搜索“如何建立 BOM”可以同时出现指南页面入口和对应知识答案：页面结果用于进入手册，知识结果先回答问题。两者保留明确的类型与用途。后续登记指南主题时复用现有搜索入口，不新增另一套搜索弹窗。

| 现有文件或目录                                                                                        | 当前职责与后续约束                                           |
| ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `src/features/basic-settings/knowledge-base/`                                                         | 企业知识条目的编辑、传输及图文展示；不接管指南步骤或文档预览 |
| `server/models/knowledge_base.go`、`server/handlers/knowledge_base_handlers.go`                       | 现有知识条目持久化、搜索和阅读统计；不拥有正式业务文档       |
| `src/hooks/use-command-menu-knowledge.ts`、`src/components/command-menu-knowledge-*.tsx`              | 搜索会话、结果和知识正文展示；来源链接交给目标模块处理       |
| `src/features/product-structure/data/bom-field-business-meaning-help-topic-definitions.ts` 及对应词典 | BOM 解释主题和内容来源，知识接入应读取纯内容元数据           |
| 产品、BOM、料号需求和生产领料指南页面、章节定义                                                       | 原业务域的阅读编排、上下文、能力启用说明与合法操作入口       |
| `src/features/engineering-db/` 的技术规范服务、查询及预览组件                                         | 唯一技术规范主库的读取、写入、附件和预览；知识库通过链接使用 |
| `docs/architecture/`、`docs/frontend/` 等                                                             | 开发维护契约，区分现状、规则与后续计划                       |

后续内容适配按明确职责独立文件承接。业务域不反向依赖基础设置的知识管理界面；知识适配不把解释内容、表单状态、业务请求和主库文件查看混入同一组件。本约定不要求立即新增通用内容平台、额外文档表、独立搜索服务或新的权限位。

## 6. 已有能力与待接入事项

截至 2026-10-26 的源码现状：

- 知识条目已有标题、摘要、正文、关键词、分类及单一 `routePath`，支持说明图片和正文链接；搜索结果可展开知识正文，并提供“打开页面”。
- 全局搜索已接入知识条目接口。知识与 Go/Rust 业务记录搜索是不同来源，当前没有自动把指南正文、仓库 Markdown 或技术规范原文件加入知识搜索。
- 现有编辑器的关联入口主要是页面选择，尚无结构化的指南主题、多个关联入口或文档记录引用协议。
- 产品和 BOM 指南独立承接，BOM 字段帮助与指南已经复用部分主题；知识搜索尚未消费这些主题。
- 生产领料指南与料号需求指南同级，明确区分已接入的原单下发／撤回和仓库领退，以及待接入的总体订单进度、正式打印和消息；其职责见[生产领料下发及库存过账契约](production-material-issuance-dispatch-warehouse-confirmation-and-inventory-posting-contract.md)。指南正文未自动加入知识搜索，后续索引须同步保留能力启用状态。
- 技术规范原文件由工程主库预览和下载。知识库目前没有接入 PDF、Excel 等业务文件查看器。
- 知识编辑器提示仍写“后续可直接接入全局搜索索引”，与已接入的现状不一致；后续界面调整时应修正，不据此判断搜索尚未实现。

本次只建立本文与文档引用，不改知识数据结构、搜索接口、权限、页面或业务文件。后续优先选取 BOM 的归属、性能版本与重量、生命周期等少量主题，验证来源复用、问题检索及链接承接，再按同一边界扩展其他指南；不把所有章节全量复制成可独立编辑的知识文章。

后续接入的验收应覆盖：问题及常用词能找到答案；摘要与指南使用同一解释；说明图正常展示；页面、章节或记录链接由目标模块正确承接；权限和目标失效有明确反馈；业务原文件仍在原主库查看；修改解释后无第二份长期失联的内容副本。
