# Chrome 109 业务页面与底部菜单栏颜色兼容

兼容基准为 Win7 官方最后支持的 Chrome 109。此次修复业务内容与底部菜单栏中由 OKLCH、`color-mix()` 无法解析导致的背景透明、文字失去对比度、边框变黑和按钮状态颜色丢失。新版浏览器继续使用原样式。

## 实现与边界

- `scripts/chrome109-business-content-and-floating-surface-color-fallbacks-postcss-plugin.js` 由 Vite 的 PostCSS 配置调用，读取现有应用主题和 Tailwind 调色板，构建时生成对应的 sRGB 颜色。没有新增依赖。2026-10-22 将原业务区与底栏插件扩展为业务区、侧栏和浮层共用的生成器。
- 所有生成的兼容 CSS 都位于 `@supports not (color: oklch(1 0 0))` 中，作用域为 `[data-slot="sidebar-inset"]`、`[data-slot="global-bottom-dock"]`、侧栏和已登记浮层及其后代，不覆盖 `:root` 或 `body`。
- Portal 浮层独立登记为作用域根节点，因此即使挂在 `body` 下，也能获得与业务区相同的主题、调色板和透明色回退。通用角色及自定义浮层的登记约定见[浮层兼容文档](./chrome109-floating-overlay-compatibility.md)。侧栏导航状态与底栏表面继续使用各自的专用规则。
- 半透明语义颜色、调色板颜色与透明阴影使用局部 RGB 通道和 alpha 变量，保留主题自身透明度、工具类百分比以及阴影的运行时 alpha。
- 每条透明度回退紧邻原规则，保留 layer、媒体查询、深色祖先、伪元素与选择器优先级，避免覆盖后续同优先级的实色工具类。默认文字颜色放在 base layer，保留反色按钮和状态文字。
- `src/styles/chrome109-bottom-dock-color-fallbacks.css` 单独处理底栏的背景。原底栏把完整主题颜色嵌入 `hsl(var(...))`，无法解析；旧浏览器改用局部 sRGB 通道，保留原透明度、背景模糊、桌面和窄屏表面结构。组件仅添加定位作用域的 `data-slot`。
- 不为未知局部颜色、`currentColor` 混色或 keyframe 混色推测颜色，也不改变页面几何、布局或业务逻辑。

## 2026-10-17 验证记录

浏览器使用本地模拟接口与隔离账号，没有对生产业务数据执行操作。

- 真实 Chromium 109.0.5414.46：产品管理、环节与工价、单位管理、全厂概览，浅深主题及主按钮/表格行悬停共 14 个状态通过。业务内容外的计算样式和业务内容几何保持不变；产品主按钮背景、反色文字及边框恢复。
- 产品管理与产品外观页签切换、单位搜索与分类过滤、新增单位表单填写和取消、工价搜索、计件工价/工资环节切换、工价编辑框输入及选择环节后取消均正常。未提交新增或编辑数据。
- 底栏在 1440×1000、1366×768、390×844 下，浅深主题、扫描按钮悬停和仪表盘当前页面状态共 12 个状态通过；背景、按钮与图标颜色恢复，按钮在可视范围内，底栏外的计算样式和底栏几何保持不变。
- 浅深主题分别验证扫描入口的键盘打开、展开态颜色和 Escape 关闭，全局搜索输入及关闭按钮、通知中心打开和关闭、仪表盘跳转及高亮。全局搜索沿用原有的关闭按钮约定，未改变交互行为。
- Chromium 155：业务区 14 组、底栏 12 组修改前后整页截图均逐像素一致，计算样式与几何也保持一致。
- 最终生产 CSS 移除旧浏览器条件块后，与业务区修改前的 CSS 逐字节一致。9 个 PostCSS 单元测试、完整生产构建和所改脚本/组件的 ESLint 均通过。
- 两组浏览器比较均未捕获运行时异常。无本地 WebSocket 后端时的连接失败与重试不纳入应用兼容结论。

此次完成的是公共颜色兼容与代表页面验收，并不表示全部路由、所有业务操作、打印或 3D 功能已逐项验收。旧内核运行于较新 Windows，Win7 实机的字体、缩放和实际交互仍需复核。左侧菜单、业务区和底栏的这些新增修改尚未部署服务器。
