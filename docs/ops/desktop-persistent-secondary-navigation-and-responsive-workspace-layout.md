# 桌面端常驻功能目录与响应式工作区布局

## 用户行为

- 1024px 及以上采用一级业务分类、常驻功能目录、业务工作区三列布局。
- 点击分类只切换目录；点击具体功能才导航。悬停、鼠标离开、再次点击分类均不会关闭目录，也不会出现遮罩。
- 目录仅展示下级分组及模块，不放分类标题、搜索框或入口统计。模块页签在首次进入及切换分类后默认全部展开；每个模块可独立点击收起或展开，操作一个模块不会影响其他模块。没有模块页签的业务保留直接入口。
- 路由变化、刷新、前进后退时恢复当前页面的所属分类和入口。当前页面所属分类、模块及入口使用橙色胶囊大圆角；正在浏览的其他分类、展开模块使用蓝色胶囊大圆角，暗色主题使用对应浅色文字。
- 一级列底部按钮独立收起/展开功能目录；顶栏按钮控制整个导航。点击一级分类会重新展开目录。
- 1024px 以下使用抽屉手风琴，选择入口后关闭抽屉。桌面端的“不可折叠”偏好不会禁用窄屏抽屉。
- 首次访问默认显示桌面导航，已有 `sidebar_state` 偏好继续有效。目录展开状态单独保存在 `sidebar_secondary_open` Cookie。

## 布局契约

- `SidebarProvider` 的导航断点为 1024px，与 `sidebar.tsx` 的 `lg:` 样式和 `sidebar-navigation-workspace-layout.css` 的媒体查询一致。其他业务组件使用的 `useIsMobile()` 默认仍为 768px。
- 一级列基础宽度为 8.5rem，目录宽度预算为 14rem；1280px 起分别为 10rem 和 15rem。浮动/内嵌外观的外侧留白计入导航总预算。
- 两列由同一个 `Sidebar` 管理，其桌面占位元素和固定导航共用 `--sidebar-width`。收起目录后该变量仅包含一级列，禁止业务页面额外硬编码导航宽度。
- `SidebarInset` 统一提供 `--header-fixed-left/right`，顶栏、模块页签、底部 Dock、通用底部操作条共同使用。内嵌外观展开时，正文没有左外边距，顶栏也不额外累加 0.5rem。
- 页面祖先不设置 `container-type`：Chrome 109 会使其中的固定顶栏/底栏改以该元素定位，造成重复偏移。命名宽度查询容器下移到 `Table` 包装层和 `DataTablePagination`，表格列与分页仍按自己的可用宽度响应。
- 登录后的应用容器使用视口高度；一级分类、功能目录和业务内容各自拥有滚动区域。固定布局页面继续使用自身滚动容器，普通页面可在 `SidebarInset` 内滚动。
- 桌面一级分类在可用导航区内上下居中；下级目录通过弹性布局与自动上下外边距居中，内容超高时外边距自动归零，保留从首项开始的完整滚动范围。菜单图标与文字垂直对齐，不用固定定位或手工计算顶部偏移。
- 视口布局的根页面不预留双侧滚动条槽位；滚动由内部区域承担，避免 Chrome 109 中固定定位宽度与根滚动条槽位不一致。
- 原有 `inset/sidebar/floating` 外观共用同一套宽度约定。PDA 页面继续不渲染导航，打印模板工作区继续不渲染全局 Dock。
- 整栏隐藏时导航容器使用 `inert`，避免键盘焦点进入屏幕外的菜单。

## 数据与状态职责

- `sidebar-navigation-model.ts` 是菜单数据唯一组装入口，统一处理国际化、菜单权限、徽标以及经过页签权限投影的 `categoryDirectories`。
- `sidebar-tab-preview-registry.ts` 继续复用业务模块现有页签配置，不在新组件中复制功能入口。
- `use-sidebar-category-selection.ts` 管理仅供浏览的分类选择；每次路由变化清除临时选择，权限移除分类时退回可访问分类。
- `desktop-sidebar-secondary-navigation.tsx` 仅渲染目录、可独立展开或收起的模块和当前入口，不负责请求权限或维护第二份菜单。
- 已删除旧 `sidebar-category-scrubber.tsx` 浮层实现及旧浮层测试；保留并复用其纯数据整理工具和对应测试。
- 新导航样式直接使用完整主题颜色变量，沿用项目已有 Chrome 109 主题回退，不将完整颜色再次嵌入 `hsl()`，也不新增对 `color-mix()` 的依赖。

## 验证记录

- 类型检查与 Vite 生产构建通过；构建仍提示部分既有入口包超过 1000kB。
- 导航测试覆盖分类选择与权限变化回退、模块默认全部展开、跨分组独立收起与展开、切换分类恢复全部展开、路由选中、移动端展开与关闭。
- 修改的应用组件、hook 通过 ESLint；中英文键结构及中文编码检查通过。
- 浏览器使用独立会话、模拟身份和模拟接口；不使用真实业务数据验证。
- 现代 Chromium 与真实 Chromium 109.0.5414.46 均完成响应式边界和导航交互检查。Chrome 109 的模拟 WebSocket 工具会报告不支持 `URL.parse`，该工具报错不作为真实后端或通知系统验证结果。
- 1920、1366、1280、1024、1023、900、390px 七种宽度检查通过：正文/顶栏/Dock 对齐，页签位于业务区，导航不覆盖内容，页面无横向溢出。
- `sidebar/floating/inset` 三种外观检查通过：目录独立滚动，不带动一级分类和正文，稳定页面高度不超过视口。
- 初版浏览器交互检查通过：悬停不切换、点击分类不跳页、重复点击不关闭、目录收起后刷新恢复、整栏隐藏不可键盘进入、路由返回恢复、手机手风琴及选中入口关闭。后续按反馈移除搜索和统计，并将模块改为默认全折叠的手风琴。
- 手风琴调整后补测：3 个相关测试文件共 10 项通过，类型检查、ESLint、国际化键结构检查通过。现代 Chromium 验证默认全折叠、互斥展开、再次折叠、切换分类重置、折叠/展开均居中、320px 低高度滚动完整，以及橙蓝胶囊和暗色主题配色；重新检查七种响应式宽度的工作区对齐。
- 花鼓主数据库页面在两种浏览器的 1366、1024、390px 下补测通过：表格和分页保留命名宽度查询，分页按实际业务区宽度由横排切换到纵排，固定顶栏保持对齐。
- 检查产物保存在忽略提交的 `output/playwright/`，文件名前缀为 `sidebar-` 或 `verify-sidebar-navigation-`。
