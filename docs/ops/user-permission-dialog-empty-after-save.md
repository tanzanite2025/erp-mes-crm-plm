# 权限保存后面板显示全空

## 复现条件与原因

账号未分配权限预设时，Go 读取接口使用 `append([]string(nil), ...)` 复制空集合，JSON 中的 `presetPermissions` 因而是 `null`。账号完全没有权限时，`effectivePermissions` 也可能是 `null`。前端 DTO 原先要求这些字段必须为数组，因此拒绝整份响应，包括其中已保存的显式权限。

权限弹层原先忽略了读取错误，继续把没有查询数据的状态显示为“无预设、最终有效 0、全部未勾选”。保存接口仍能成功，但因为读取查询没有成功建立缓存，保存后的缓存更新也无法回填，形成“提示成功，面板全空”。2026-10-17 针对截图账号进行了服务器数据库只读核对，存在 275 条有效显式权限，没有修改账号授权。

## 修复

- 后端权限详情和账号访问画像的空权限集合统一返回 `[]`，保留已有权限内容与数量。
- 前端兼容旧版接口的明确 `null` 空集合，将其规范成 `[]`；仍拒绝缺失字段、字符串集合和无效数组元素，不推导额外授权。
- 读取失败时显示错误与重试按钮，概览使用 `—` 表示未知；禁止全选、清空、切换权限和保存，避免把读取失败当成空权限覆盖。成功读取后的面板布局和权限逻辑保持原样。
- 保存权限继续以服务端返回的实际权限更新查询缓存。

## 验证

- 修复前，新增的前端 API 回归用例复现 `presetPermissions: null` 导致整份权限响应被拒绝；后端 JSON 回归用例复现空集合输出为 `null`。
- 前端 API、查询/修改 hooks、权限编辑 hook 共 16 项测试通过，覆盖读取旧接口空集合、拒绝无效响应、失败时阻止保存、重试恢复、保存后刷新以及关闭后重开。
- 后端权限响应 JSON 与账号访问画像测试通过，覆盖没有权限和已有显式权限但未分配预设的账号。
- 所改前端文件的 ESLint 与中英文翻译结构检查通过。
- `pnpm build` 通过，包含 TypeScript 检查与生产资源构建。
- 在 Chromium 109.0.5414.46 和 Chromium 155 中，使用本地生产构建及隔离的模拟账号验收：旧接口 `presetPermissions: null` 能回填已保存权限；保存后、刷新后及关闭后重开均保留勾选；无效响应显示错误和 `—` 计数，并禁用全选与保存；重试后恢复已保存权限。两种内核的应用运行时异常均为 0，读取、重开和重试均未增加权限写入次数。
- 已检查浅色错误状态与深色恢复状态截图，产物及浏览器验收日志位于 `output/playwright/user-permission-dialog-empty-after-save/`。浏览器验收运行在当前 Windows 电脑上的 Chromium 109 内核，没有直接在 Windows 7 系统上运行；没有在生产账号上执行权限写入测试。
- 所改前端文件和本文的 Prettier 检查、`git diff --check` 通过。

该修复不修改数据库中的授权，也不自动分配权限预设。代码尚未部署到服务器。
